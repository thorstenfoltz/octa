# GUI: table view, chrome, view modes, dialogs, settings

## Module layout

- `src/ui/table_view.rs`: virtual renderer (scroll, resize min 60px, drag-reorder, multi-cell/row/column selection, inline edit, context menu, line breaks, binary display). Returns an `Interaction` struct; caller mutates.
- `src/ui/toolbar/` (dir module): toolbar (logo, File/Edit/View/Search/Help menus, zoom, view-mode radio, custom title-bar buttons). `mod.rs` holds `draw_toolbar` (the menu bodies are inline closures sharing its locals); `types.rs` holds the returned `ToolbarAction` struct + `ParseScope` (re-exported); `menu_button.rs` holds `top_menu_button`, which sets `ui.style_mut().wrap_mode = Extend` inside every menu so long localized item labels (de/ru/...) don't wrap onto two lines, the popup grows instead.
- `src/ui/directory_tree.rs`: sidebar browser, left/right per setting; each row a full-width `Sense::click()` rect; `read_sorted_dir` is the sole disk walker. `render_directory_tree`/`draw_dir` take `allowed_exts: Option<&HashSet<String>>` (lowercased registry extensions + `text_mode_extensions`, built in `sidebar.rs` when `directory_tree_filter_enabled`, default on): files whose extension isn't in the set (and extensionless files) are hidden; directories always shown.
- `src/ui/table_picker.rs`: modal for multi-table sources (single-table DBs auto-load). Window id `octa_table_picker_dialog_v2`; height fit-to-content up to `table_picker_visible_rows` (default 10); body/footer via `Panel::bottom` + `CentralPanel`.
- `src/view_modes/`: per-mode renderers (Notebook, Markdown, Raw, JSON/YAML Tree, SQL, Compare, EPUB, Map, Record). The Compare view (`src/view_modes/compare/`) has four sub-modes (`data::CompareMode`): `TextDiff` (`text_diff.rs`), `RowHashDiff` (`row_diff.rs`, BLAKE3 set-difference), and `Ordered`/`Join` (`key_diff.rs`) which route through the shared `octa::data::compare` (`compare_ordered`/`compare_join` -> `build_compare_table`, same logic as CLI `--diff` + MCP `diff_tables`); Join reuses `compare_columns_left` as the key-column pick. TextDiff pairs `similar`'s delete/insert runs into aligned rows via `pair_changes` (modified line -> old-left/new-right on one row, no drift). All four sub-modes support copy: Ctrl+C + right-click (`compare.copy_left|copy_right|copy_unified` for TextDiff; `compare.copy_table` for the table-based modes). JSON/YAML trees share `render_value_tree` (private `TreeKind`); `markdown::render_pulldown` is `pub(crate)` for EPUB reuse. Markdown Edit/Split editor (`render_editor_pane`, takes `tab_size`) has a line-number gutter mirroring the Raw view; like the Raw editor it `lock_focus(true)`s and expands an inserted Tab into `tab_size` spaces (re-anchoring the cursor) instead of moving focus. Notebook **source cells are editable** (`render_notebook_view` takes `&mut TabState` + `readonly`); frameless `TextEdit::multiline`, code cells keep syntect via `.layouter`; writes through `tab.table.set`. `.ipynb` writer (`jupyter_reader::write_notebook`) re-reads original via `source_path` and overwrites only `source`/`cell_type`, preserving outputs/metadata.
- `src/view_modes/map.rs`: GeoJSON Map via `walkers` (own tokio runtime in a private thread). Polygon holes stroked, not cut (egui has no even-odd rule). Also plots **any** table with lat/lon columns: `octa::data::geo_detect::detect_lat_lon` (name + value-range check) gates `ViewMode::Map` in `available_view_modes`; on Map entry `seed_point_features` builds `geojson_features` via `octa::formats::geojson_reader::points_to_features` (Point geometry, `x=lon`/`y=lat`), remembering the columns in `TabState.map_coord_cols`. A toolbar Lat/Lon dropdown (`draw_coord_picker`) rebuilds on change. i18n `[mapcoord]`.
- `src/view_modes/record.rs`: `ViewMode::Record` - one row shown vertically as field/value pairs, for tables too wide to read in the grid. Offered for any tab with columns, reached via the View menu radio or F4. Pure `next_record_index(filtered, current, dir)` (unit-tested) walks `TabState.filtered_rows`, so stepping follows the active search/column filters. **Reuses `crate::app::state::NavDir`** rather than defining a second Prev/Next. The shown row is `table_state.selected_cell`'s row, written back on navigation, so Table and Record share one place. Field list is virtualised (`show_rows`), values carry the shared search highlight, and clicking one starts an edit through `TableViewState::begin_edit` + `CellValue::parse_like` (the grid's inline path additionally handles `=formulas` and binary; Record does not). `TableViewState.edit_needs_focus` is `pub` for this: focus once, then commit on `lost_focus`. Takes `theme_mode` as a parameter like the chart view. i18n `[record]` + `view_menu.record`(+`_hint`).
- `src/view_modes/text_ops.rs`: `apply_case_to_selection` (Upper/Lower) shared by SQL/raw editors (char-to-byte range mapping).
- `src/ui/syntax.rs`: syntect over `SyntaxSet::load_defaults_newlines()` + bundled `assets/Terraform.sublime-syntax`. `HIGHLIGHT_WHITELIST` **includes** JSON/YAML/XML/TOML (they open in the raw view, so colouring them there is wanted); only CSV/TSV/Markdown stay out. Size-gated by `syntax_highlight_max_bytes` (1 MB). **`highlight_layout_job` is memoized (`HIGHLIGHT_MEMO`, one entry) and must stay that way**: egui calls a `TextEdit` layouter on EVERY frame *before* consulting its galley cache - that cache is keyed on the `LayoutJob` the layouter returns, so it cannot save the work of building one. Unmemoized, a 700 KB JSON re-tokenised 60x/second and cost **4.3 s per frame** (measured, debug), freezing the whole app whenever the raw view was open; the memo took it to 54 ms. The entry is validated by comparing `job.text` against the buffer - a `memcmp` against something already stored, exact where a length-or-fingerprint check would leave stale colours after a same-length edit. This regressed once because JSON was added to the whitelist while the comment beside it still said JSON was excluded *for this reason*; both comments now point at the memo instead.
- `src/ui/settings.rs` (+ `settings/`): `AppSettings` + TOML persistence (`~/.config/octa/settings.toml`, `~/Library/Application Support/Octa/`, `%APPDATA%\Octa\`). The Settings dialog UI is `settings/dialog/` (dir module): `mod.rs` holds `open`/`show`/`draw_sections`; `shortcuts_grid.rs` the Shortcuts section + `capture_combo`; `chat_section.rs` the chat model pickers. All are `impl SettingsDialog` blocks (the struct stays in `settings/mod.rs`). `IconVariant::Random` resolves once into `OctaApp.resolved_icon`. Rainbow easter-egg theme: `ensure_logo_textures` renders `assets/octa-random.svg` while active; leaving Rainbow nulls the logo textures so the configured icon returns.
- `src/ui/status_bar.rs`: bottom bar; nav input jumps to `R5:C3`/`R5`/`C3`/row#/column name. Takes `busy` + `busy_hint` for a Spinner.
- `src/ui/theme/`: `ThemeMode`, `ThemeColors`; `apply_theme(ctx, mode, font)` is the single entry point. The theme applies on **Apply** (no live preview, no OS-follow, no custom palettes). `ThemeMode::label()` is plain English (themes are NOT enumerated by name in docs, so adding/renaming one is self-contained). Adding a theme: variant + `ALL`/`is_dark`/`label`/`for_mode` (mod.rs) + a palette fn (`palettes.rs`) + optional `apply_*_decoration`/`paint_*_background` (`visuals.rs`, else route through a no-op arm). **Warm** (warm light) and **Forest** (deep woodland dark) both use `apply_soft_decoration`. **North** is the former "Nord" (renamed variant + `#[serde(alias = "Nord")]` so old settings load; colours unchanged). (Apple-style Aura/Graphite were trialled and removed — don't re-propose.)

## Performance settings

- `initial_load_rows` (default **5M**) caps the first streaming batch. Process-wide `AtomicUsize` (`src/formats/mod.rs::INITIAL_LOAD_ROWS`); `set_initial_load_rows` runs from `OctaApp::new`, Settings apply, and `run_mcp`. `InitialLoadRowsGuard` is an RAII override for CLI `--rows` / MCP `unlimited` (safe: CLI single-threaded, MCP current-thread runtime). `initial_load_rows_unlimited` overrides to `usize::MAX`.
- Single-table reads of files >= `BACKGROUND_LOAD_MIN_BYTES` (8 MB, `src/app/file_io/`) run on a worker thread (`OctaApp.pending_load`, polled by `drive_pending_load` in the update loop, applied via `finish_single_load`); the status-bar spinner shows "Loading file..." and the open-queue waits for the in-flight load. Multi-table sources (Excel/DB) stay synchronous; files < 8 MB load inline.
- `syntax_highlight_max_bytes` (default 1024 KB) gates the raw editor's syntect pass; Settings exposes a Bytes/KB/MB unit picker.
- `text_mode_extensions: Vec<String>` forces unknown extensions through `TextReader` (checked in `load_file` before registry lookup; lowercased, dot-stripped; unioned into the picker's "All Supported").
- `thousands_separators_in_cells` (default **on**) + `number_separator_style: SeparatorStyle` (English/European) group numeric cells display-only via `src/ui/table_view/rows.rs` -> `octa::data::num_format::format_cell_number` (never touches saved/exported/CLI/MCP output).
- `excel_max_auto_sheets` (default **5**) caps auto-opened Excel sheets; above it `load_file` raises `pending_sheet_picker`.
- `trim_whitespace_on_load` (default **off**) + `warn_on_whitespace_trim` (default **on**) drive the load-time whitespace pass; `offer_repair_on_malformed` (default **off**) the repair prompt; `language` (default `"en"`) drives `octa::i18n`.

## Keyboard shortcuts

`src/ui/shortcuts.rs`: `ShortcutAction` (strum `EnumIter`) + `default_combo`/`label`/`group` (all exhaustive matches), `Shortcuts { bindings: HashMap }` persisted in `AppSettings`. All toolbar menus render from startup (the old `if has_data` wrapper around Edit/Columns/Data/View/Search/Analyse is gone; those five show a weak `menu.need_table` note and return when no table is open; Analyse keeps SQL + Assistant clickable without data). Dispatch in `src/app/shortcuts_dispatch.rs::handle_shortcuts` (most dialog-opening actions gated on `!text_edit_focused`, edits on `!is_readonly()`). The Settings rebind UI is `settings/dialog/shortcuts_grid.rs` (records a combo, refuses conflicts; one nested `CollapsingHeader` per `ShortcutGroup` so the section opens as a short group list). Adding a feature dialog: add a variant + the three match arms + a dispatch arm; a unit test (`default_combos_are_unique`) pins that no two defaults collide (the only ship-time conflict guard, since the settings UI only checks at rebind). Labels are English-only (`label()`), not i18n. Newer dialogs (Pivot/Transform/CondFormat/CondColumn/Validation/MultiSort/Summary/NumberFormat/CopyMarkdown) ship Ctrl+Shift+<letter> defaults.

## Undo / Redo

`src/app/shortcuts_dispatch.rs` -> `OctaApp::do_undo`/`do_redo` (`src/app/edit_ops.rs`), which reset `filter_dirty`/`widths_initialized`. Gated on no TextEdit focus (so Ctrl+Z edits text there). `UndoAction` covers cell edits, structural mutations, colour marks; structural ops push to `undo_stack`, clear `redo_stack`.

## Colour Marking

`DataTable.marks: HashMap<MarkKey, MarkColor>` (`MarkKey::{Cell,Row,Column}`, precedence cell>row>column). **Edit -> Mark** / `Mark` (Ctrl+M) apply `default_mark_color` with precedence rows>cols>cells>cell. Context-menu uses the same precedence when the clicked target is in the selection, else colours the single target. `interaction.set_mark`/`clear_mark` carry `Vec<MarkKey>` for batch apply. Rainbow theme pins marked-cell text to `WHITE` (or `BLACK` via `MarkColor::needs_dark_text`).

## Design patterns

- **Lazy filter**: `filter_dirty` triggers `recompute_filter()`; `filtered_rows: Vec<usize>` maps display->data index.
- **Search: filter vs highlight**: `data::SearchResultMode {Filter, Highlight}` (default Filter; persisted `AppSettings.search_result_mode`, session override `OctaApp.search_result_mode`, search-bar toggle). `state::effective_highlight(view_mode, mode)` = `Highlight || view_is_text_or_tree` (Notebook/Raw/Markdown/Json|YamlTree always highlight). Reusable engine `src/ui/search_highlight.rs`: `apply_highlight(job, ranges, current, normal, active)` splits `LayoutJob` sections to background-paint matches (composes with any layouter), `highlight_colors(&ThemeColors)`, `cell_matches(...)`; `RowMatcher::find_ranges(text)` yields byte ranges. Per-tab `TabState.search_nav: SearchNavState {match_count, current, pending_jump: Option<NavDir>}` + `search_cell_matches`; Enter/Shift+Enter (or the `<`/`>` toolbar buttons) set `pending_jump`, the active view advances `current` and scrolls (table: `selected_cell`+scroll; text editors: `set_char_range`+`scroll_to_rect`; tree/notebook: `scroll_to_me`/offset). Highlight mode keeps all rows in `recompute_filter` (column filters still hide). `render_pulldown(ui, src, Option<&(RowMatcher, Color32)>)` carries the docs-dialog + markdown-preview highlight (None elsewhere keeps EPUB/preview unchanged).
- **Selection model**: cell click selects one; **Ctrl+click** toggles into a disjoint `selected_cells` set (first toggle promotes the prior single cell). Row-number click selects a row (Ctrl/Shift extends); header click selects a column. Copy honours the selection.
- **Tab multi-selection for Compare**: Ctrl-click a non-active tab toggles `OctaApp.tab_multi_selection`; `CompareSelectedTabs` (F9) runs with exactly one selected; `begin_compare_with_tab` clones the right side from memory (in-memory edits carry through).
- **Right-click copy**: TextEdit views (raw, SQL) show **Copy** (by selection id) + **Copy All**; non-TextEdit views keep one whole-content entry (`Label::selectable(true)` handles partial Ctrl+C).
- **Arrow navigation**: extend-selection (Ctrl+Arrow) resolved before plain arrows in `draw_table`. Jump-first/last are Ctrl+Shift+Arrow. `ScrollPageUp`/`ScrollPageDown` (Ctrl+PageUp/Down) step by `floor(area_height/row_height)` and let `scroll_row_into_view` follow. All remappable via `ShortcutAction`.
- **Zoom**: Ctrl+Plus/Minus/0, 5% steps, 25-500%; `OctaApp.zoom_percent` is transient.
- **Clipboard**: dual-path `arboard` + `TableViewState.clipboard` fallback; TSV cells, newline rows. `copy_selection_as_markdown` (`src/app/clipboard.rs`) renders the same selection as a GitHub Markdown table (header row + `md_escape` for pipes/newlines); `do_copy_markdown` -> **Edit -> Copy as Markdown table** (`ToolbarAction.copy_as_markdown`) + cell/row context menu (`TableInteraction.ctx_copy_markdown`). i18n `edit_menu.copy_markdown`(+`_hint`), `context_menu.copy_markdown`.
- **Unsaved-changes guards**: window close and file open check `is_modified() || raw_content_modified` -> Save/Don't Save/Cancel.
- **JSON/YAML tree key editing**: `render_value_tree` overrides `selection.bg_fill` to a neutral; object keys renamable inline (Enter -> `json_util::rename_object_key_at_path`, rebuilds map to preserve order); array indices not. Edits flow to `tab.raw_content` via the kind's serializer.
- **Text-editor drag-select autoscroll**: `view_modes::text_ops::autoscroll_while_selecting(ui, &response)` — call it **inside** the `ScrollArea` closure (it reads `ui.clip_rect()` as the viewport). egui's `TextEdit` extends its selection to the pointer but never scrolls its `ScrollArea`, so a selection could not be dragged past the visible lines. Wired into the Raw, Markdown-edit and SQL editors. `ui.scroll_with_delta` is **inverted** (negative y scrolls down).
- **Load banners must not be wider than the screen** (`ui::message::elide_list` + `BANNER_LIST_MAX` 6): the dates-detected, near-miss, trim and numbers banners each joined EVERY affected column into one label placed BEFORE their Okay/Dismiss buttons, inside a non-wrapping `ui.horizontal`. A JSON with ~30 date columns therefore pushed those buttons off the right edge of a strip that does not scroll sideways, so the banner could not be answered. All four now elide to N names + "and X more" (full list on hover) AND use `horizontal_wrapped`; both halves are needed, since wrapping alone still walks the buttons off the bottom. i18n `banner.and_more`, `dialog.date_queue`/`date_apply_all`(+`_hint`).
- **Multi-file open**: `pick_files()` / CLI multi-path -> `pending_open_queue`; `drain_pending_open_queue` pops one per frame, pausing while a table/date-picker modal is up.
- **Scrollable tab bar**: `render_tab_bar` (`tabs.rs`) wraps the tab row in an `egui::ScrollArea::horizontal()` so overflowing tabs stay reachable. Two egui defaults have to be overridden locally: (1) a **plain (vertical) wheel** only reaches a horizontal-only scroll area when `style.always_scroll_the_only_direction` is set (default **false**), else the wheel needs Shift; (2) scrollbars **float** by default, i.e. are painted *over* the content, which laid the bar across the tab labels — `ScrollStyle::solid()` gives it its own strip, and the panel's `exact_size` adds `SCROLL_BAR_STRIP` to fit it beneath the tabs.
- **Union files from the directory tree**: Ctrl/Shift-click files in the sidebar (`DirectoryTreeState.selected: HashSet<PathBuf>` + `select_anchor`; plain click clears + opens, Shift range-selects within the current dir listing, gated by `file_row_visible` so hidden/filtered rows can't be swept in) then **Union...** in the tree's selection bar or the row context menu -> `TreeAction.union_files` -> `OctaApp::open_union_for_files` (`dialogs/union.rs`). Reads each file via `registry.reader_for_path(..).read_file(..)` and opens the **same** Union dialog in **file mode**: `UnionState.{file_sources, file_tables, file_selected}` non-empty switches every branch (`render_union_dialog`, `recompute_plan_for_files`, `apply_union`) off the open-tab path. Lets N parquet parts become one table without N tabs; any readable mix of formats works, since the plan reconciles columns anyway.
- **Raw JSON formatting**: a minified `.json` is one endless line in the raw editor. The toolbar's **Format JSON** tick box reuses the CSV alignment flags unchanged (`raw_view_formatted` = "the buffer is a reformatted view", `raw_content_original` = what un-ticking restores) but deliberately does **not** set `raw_content_modified` - re-indenting is a way of reading the file, not an edit of it, so it must not turn the next Save into a rewrite of the whole document; the confirm dialog therefore only appears once the user has edited the formatted buffer themselves. `octa::data::json_util::pretty_print` is a hand-written bracket walker, **not** a `serde_json::Value` round trip: only whitespace *between* tokens changes, so numbers keep their exact digits (`1.50` stays `1.50`, `1e5` stays `1e5`), integers wider than `u64` survive, and escapes and key order are untouched - all four of which a re-serialise would quietly rewrite in a buffer the user can save back over their file. The confirm dialog's strings are toggle-neutral for that reason (`dialog.unalign_*` no longer names 'Align Columns'), and the formatted buffer is ~2x larger for a truly minified file (measured 31 KB -> 59 KB), so a big one can cross `syntax_highlight_max_bytes` and drop to plain monospace.
- **Raw CSV quote/escape modes**: `format_delimited_text` (`view_modes/raw_text.rs`) is a quote-aware tokenizer (RFC 4180 defaults `Double`+`Doubled`); `colored_layouter` reuses `split_delimited_line_ranges`. Coloring/alignment off via the slow-file prompt for CSV/TSV >10 MB.
- **Best-fit column width**: double-click a header seam -> `compute_optimal_col_width` (header + cells via `layout_no_wrap`, ≤5000 sample rows, +16px). Rust 2024 edition required for `cargo fmt`.
- **Parse in new tab**: scope (Cell/Row/Column/Whole table) + format (JSON/JSONL/YAML/TOML/XML/CSV/TSV/Markdown/Plain Text) -> a `tempfile::NamedTempFile`, routed through `load_file`; `source_path` cleared. Cell/Row/Column build a **synthetic `DataTable`** (source names as headers) then serialize via the registry, so headers survive (Plain Text is verbatim). Helpers in `src/app/dialogs/parse_in_new_tab.rs`.
- **Sequential row-number column**: `show_sequential_row_numbers` (default **on**) adds a second gutter sub-column numbering the *visible* rows from 1, shown only while a filter is active (`central_panel.rs` computes `show_sequential = setting && (!search_text.is_empty() || !column_filters.is_empty())`). `draw_table` splits the row-number gutter into original (`row_number_width - seq_number_width`) + sequential (`seq_number_width`) sub-columns; `rows.rs` draws `actual_row+1+row_offset` left, `display_idx+1` right (muted, with a thin separator). Off when unfiltered (it would just duplicate the original numbers).
- **Chart control bar rows**: `view_modes::chart::control_row` + `control_text_edit` pin every interactive widget in a row to one `control_height`. Left alone, a ComboBox, a `TextEdit` and a checkbox each take a different natural height, so the labels between them drift out of line.
- **Custom title bar (default on)**: `use_custom_title_bar` (default **true**) strips system decorations; `draw_toolbar` renders close/max/min at the toolbar's right edge. Move/maximise: `draw_toolbar` interacts with the whole toolbar rect FIRST (lowest hit-test priority, so menus/buttons added after keep their clicks) -> left-drag the empty background sends `ViewportCommand::StartDrag`, double-click toggles `Maximized`. Resize: `OctaApp::render_window_resize_handles` lays 8 mutually-exclusive grab strips along `viewport_rect()`, each `ViewportCommand::BeginResize(dir)` on `is_pointer_button_down_on()` (press, no drag threshold -> instant like a native border). **The strips are `ui.interact(grab, ..)` calls on ONE hand-built `egui::Ui` in a shared foreground layer (`HANDLE_LAYER`), NEVER `egui::Area`s** - an Area derives its rect from laying out its contents and can settle somewhere else entirely (on Linux Mint/Cinnamon `resize_s` came out as the bottom 40% of the window), and `hit_test.rs` discards every layer beneath the first hit covering the pointer, so every button in that band died while drag and scroll still worked. `Ui::interact` registers exactly the rect passed (hence `max_rect(rect)`), pinned by a `debug_assert_eq!`. Strips sense **drag only** (a click-sense foreground widget steals clicks from what is under it; the click/drag split only saves widgets a strip *partially* covers) and the side strips start **below** the 40px toolbar. Bottom/side generous, bottom corners large (CORNER 20); top a thin sliver (TOP_EDGE 4 / TOP_CORNER 8). Skipped while maximised. Both commands are OS-driven so they work on X11/Wayland/Windows. Takes effect after restart.
- **Cycle view mode (F4)**: advances `tab.view_mode` through `available_view_modes`; gated on TextEdit focus.
- **Frozen columns**: header right-click **Freeze columns up to here** / **Unfreeze all columns** set `TableViewState.frozen_cols` (session-only). `draw_table` clamps to keep >=100 px scrollable (`frozen_band_width`, hidden cols count 0) and passes `frozen_cols`/`frozen_width` into header/rows, which keep two running x's (frozen ignores `scroll_x`) and per-region clips so scrolled columns slide under the band; drag-target mapping via pure `drag_target_at_x`; `scroll_col_into_view` measures from the first scrolled column. Geometry unit tests pin frozen=0 to the original arithmetic.
- **Debug mode is reachable without the GUI**: `OCTA_DEBUG=1` (read in `main.rs` after `AppSettings::load()`) forces `settings.debug_mode` on for one run without writing it, and `AppSettings::load` writes `settings.toml` on first run (it used to be written only on Settings-Apply, so a fresh install had no file to hand-edit). Both exist because of a Linux Mint report where every button inside an `egui::Window` was dead while the toolbar worked, making the Settings checkbox unreachable on the one machine that needed it; `show_widget_hits` then named the culprit outright (see Custom title bar). With it on, `src/diagnostics/input_trace.rs::trace` (last in `update_loop::ui`) logs one line per pointer press/release (pos, `press_origin`, `any_click`, `could_any_button_be_click`, `is_decidedly_dragging`, `memory::layer_id_at`) plus a startup line (`pixels_per_point` vs `native_pixels_per_point`, `viewport_rect`/`content_rect`, `XDG_SESSION_TYPE`/`XDG_CURRENT_DESKTOP`), and switches on egui's `debug_on_hover`/`show_interactive_widgets`/`show_widget_hits`. Between them those separate the four ways egui reaches "painted but unclickable": a foreground layer swallowing the pointer, a negative/NaN interact rect, a release rejected as a click (`max_click_dist` 6.0 / `max_click_duration` 0.8s), and a scale-factor mismatch. Overlay setup is once-per-session, so a theme change mid-session drops it; restart.
