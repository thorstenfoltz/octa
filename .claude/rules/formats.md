# Format readers, loading and writing

## Registry

Canonical format registration order: `FormatRegistry::new()` (`src/formats/mod.rs`); user-facing list `docs/getting-started/supported-formats.md` — both update together. Read-only formats (SAS, R, HDF5, NetCDF, EPUB, GeoJSON, Fixed-Width) inherit `supports_write=false`.

`TextReader` claims every highlightable source/config extension (`.py`/`.rs`/`.go`/web markup/...) so they're advertised as supported; `highlight_whitelist_is_supported` pins `HIGHLIGHT_WHITELIST` to the registry's set. `formats::filename_reader_name(file_name)` matches extension-less filename conventions (`Dockerfile`, `Dockerfile.*`, `Containerfile`, `Containerfile.*`) to the Text reader, checked in `reader_for_path` between the extension and sniff steps; a bundled `assets/Dockerfile.sublime-syntax` (loaded best-effort like Terraform/TOML) + `syntax::syntax_for_filename` highlight them; `directory_tree::file_is_listed` keeps known filenames visible in the sidebar filter. `src/formats/sniff.rs::sniff_format` does content-based detection (magic bytes + JSON/CSV probes) for missing/wrong extensions: `reader_for_path` consults it before the Text fallback, `load_file` retries via `try_content_sniff_reload`; `reader_by_name` maps a sniff result to a reader.

## Module layout

- `src/data/encoding.rs`: `decode_bytes(&[u8]) -> (String, &'static str)` and `read_to_string_detected(path)` — BOM sniff, then UTF-8 fast path, then `chardetng` + `encoding_rs`. Used by `TextReader`/`MarkdownReader` so non-UTF-8 (Windows-1252/Latin-1/UTF-16) text opens. CSV keeps its own streaming path (`csv_reader` `lossy_utf8`).
- `src/formats/mod.rs`: `FormatReader` trait + `FormatRegistry`. Multi-table sources implement `list_tables`/`read_table(name)`; single-table formats fall through to `read_file`.
- `src/formats/parquet_reader.rs`: `build_arrow_array` + `data_type_from_string` map our type-name strings <-> Arrow `DataType` (update together). Native reader (parquet-58) rejects >32,767 row groups; `read_file` retries via a DuckDB path (`read_parquet` + `query_arrow`). Both honour `initial_load_rows` and strip pandas index columns via `pandas_index_columns`. **arrow/parquet are held at 58 by `duckdb` and `orc-rust`**, both of which require arrow `^58` on their latest releases *and* their main branches. That is what keeps the open `thrift 0.17` advisory (GHSA-2f9f-gq7v-9h6m, OOM on a malicious Parquet footer) unfixable: arrow-rs 59 dropped the `thrift` crate outright, so bumping to 59 would close it. Aliasing parquet 59 beside arrow 58 was considered and rejected - a third arrow copy in the binary, plus `arrow_ipc_reader.rs` and `file_io/mod.rs` both call `parquet_reader::{arrow_value_to_cell, data_type_from_string, build_arrow_array}`, and `parquet_reader.rs` would have to juggle arrow 59 from the native reader against arrow 58 from its DuckDB fallback. Recheck when duckdb-rs or orc-rust ship arrow 59.
- `src/formats/spss_reader.rs`: SPSS read-only via `ambers` (needs arrow ^57; pinned `arrow57 = { package = "arrow", version = "57" }` alongside arrow 58).
- `src/formats/{sas,stata,rds,dbf,hdf5,netcdf,geojson,epub}_reader.rs`: pure-Rust, mostly read-only. RDS = tabular subset. `geojson_reader` claims only `.geojson`. `epub_reader` uses `rbook` + `htmd` (Apache-2.0; `epub`/`html2md` crates are GPL-3.0, blocked).
- `src/formats/fwf_reader.rs`: fixed-width (`.fwf`/`.prn`), read-only. `infer_field_ranges` finds boundaries from always-blank char positions; first line is header. All Utf8. Pure `read_fwf(&str, &Path)`.
- `src/formats/numpy_reader.rs`: NumPy `.npy` (single array) + `.npz` (zip of named arrays -> multi-table via `list_tables`/`read_table`), read-only. `.npy` parsed by `npyz` (dtype dispatched on `TypeChar`+byte width -> `CellValue`); 1-D -> one `value` col, 2-D+ -> `col_N` per trailing-axis index (row-major). `.npz` unzipped with the existing `zip` crate (no `npyz` `npz` feature, avoids a second zip). Structured/record arrays rejected.
- `src/formats/{msgpack,bson}_reader.rs`: MessagePack (`rmp-serde`) + BSON (`bson`, features `serde`+`serde_json-1`), both read-only. Each decodes to `serde_json::Value` then reuses `json_reader::json_to_table` (same flattening as JSON). BSON reads concatenated documents (mongodump shape) via `Document::from_reader` over a cursor, each -> `Bson::into_relaxed_extjson`.
- `src/formats/shapefile_reader.rs`: ESRI Shapefile (`.shp` + sibling `.dbf`/`.shx`), read-only, via `shapefile` crate (feature `geo-types`). `read_with_features` mirrors geojson: leading `__geometry` WKT col + `.dbf` attribute cols (field order read from the sibling `.dbf` via `dbase::Reader` since `dbase::Record` iterates unordered; reuses dbf_reader's `field_value_to_cell`/`dbf_type_string`), plus `Vec<MapFeature>` (`geo_types::Geometry::try_from(shape)`). Wired exactly like GeoJSON: `file_io.rs` populates `tab.geojson_features` on load -> `ViewMode::Map`; `available_view_modes` + `map.rs` treat `Some("GeoJSON")|Some("Shapefile")` as geometry-from-file (no lat/lon coord picker).
- `src/formats/lakehouse_reader.rs`: Delta Lake / Apache Iceberg, read-only. **NOT in the registry** (the unit of opening is a *directory*, not an extension). `detect(dir)` -> `LakehouseKind` by marker subdir (`_delta_log/` Delta, `metadata/` Iceberg); `read_dir` runs `INSTALL/LOAD {delta|iceberg}` + `delta_scan`/`iceberg_scan` on an in-memory DuckDB conn (DESCRIBE for typed cols, reuses duckdb_reader's `duckdb_type_to_arrow`/`duckdb_value_to_cell`; honours `initial_load_rows`). Directory-open plumbing: `file_io.rs::load_file` short-circuits `path.is_dir()` -> `load_lakehouse_dir`; GUI **File -> Open table folder...** (`ToolbarAction.open_table_folder` -> `pick_folder` -> `load_file_in_new_tab`). **Extensions install over the network on first use** (then cached). i18n `file_menu.open_table_folder`(+`_hint`). **Dataset mode**: `LakehouseKind::Parts(PartsFamily{Parquet,Delimited,JsonLines})` — non-lakehouse directories are scanned recursively (depth 8) for data parts, the majority family wins (`read_dir_report` lists skipped files -> `dataset.skipped_files` banner), and DuckDB scans the **explicit file list** (never globs — DuckDB errors on no-match globs). Directory-tree context menu "Open as dataset..." (`TreeAction.open_dataset`). i18n `[dataset]`.

## Write Support

Most formats write. CSV preserves its `csv_delimiter`. Excel writes via `rust_xlsxwriter` (calamine read-only); only `.xlsx` round-trips. ODS has a hand-rolled OpenDocument 1.2 writer. TOML/YAML serialize through a JSON intermediary.

**`.xlsx` formatting export** (`src/formats/xlsx_style.rs`, pure + unit-tested; the writer in `excel_reader.rs` consumes its decisions and decides nothing itself): marks, conditional colours, frozen columns and per-column number formats cross into a saved workbook. `map_rule(&CondRule) -> XlsxRule` decides per rule whether it becomes a **live** Excel rule (`Cell`/`Text`/`Blank`) or must be **`Bake`**d, i.e. painted onto the cells matching it today. Two Excel semantics force baking and are the whole reason the module exists: ordering operators over **text** (Excel collates by locale, `rule_matches` by Rust string ordering) and **case-sensitive** `Eq`/`Ne`/`Contains`/`NotContains` (Excel's `cellIs`/`containsText` are unconditionally case-insensitive, so a native rule would colour *more* cells than Octa). A live Excel rule also always overrides a cell's direct fill with no notion of list order, so the export **partitions at the first baked rule**: everything before it stays live, everything from it on is painted. Gate `WriteOptions.xlsx.include_formatting` (**default off**). Saving a tab that carries any of the four asks once anyway via `save_would_ask_about_style` -> `pending_xlsx_style_save` -> `src/app/dialogs/xlsx_style_save.rs` (forced choice, optional remember -> writes the setting); the same predicate gates `auto_save::tab_is_auto_saveable`, since auto-save must never raise a modal. **One-way**: Octa reads a styled `.xlsx` back as plain data.

## Loading and format design patterns

- **Lazy row loading**: Parquet loads `initial_load_rows` sync, then `bg_row_buffer`/`bg_loading_done`/`bg_can_load_more` background-stream (UI drains per frame).
- **Column types as strings**: `ColumnInfo.data_type` holds Arrow type names; all readers must round-trip through `data_type_from_string()`.
- **Parse-error fallback**: `load_file` calls `fallback_to_raw_text` when a text-format reader errs — reloads via `TextReader`, switches to `ViewMode::Raw`, shows a dismissible `tab.parse_error_banner`. Files >500 MB skip it; binary formats never fall back.
- **Default view per file type**: `apply_loaded_table` (`file_io.rs`) overrides the Table default after parsing: `format_name == "JSON"` && `json_value.is_some()` -> `ViewMode::JsonTree`; `"YAML"` -> `ViewMode::Raw` (both close the SQL panel). JSONL/others stay Table. Hardcoded, not a setting; `available_view_modes` already offers these.
- **Open as / Reopen as (parse through a chosen reader)**: one format list (`toolbar::OPEN_AS_FORMATS` = {JSON, JSON Lines, CSV, TSV, YAML, TOML, XML, Markdown, Text}) behind two menus, for files whose extension lies (a `.log` that is really JSON). **File -> Open as ->** `<fmt>` (`ToolbarAction.open_as_files`) -> `OctaApp::open_files_as`: pick-the-format-then-the-files, `rfd` picker **unfiltered** (`All Files`) on purpose, N files -> a tab each. **View -> Reopen as ->** `<fmt>` (`ToolbarAction.open_as`, gated on `has_source_path`) -> `OctaApp::reopen_active_as`: re-reads the file already in the tab. Both funnel into `read_into_active_tab_as(path, reader_name)`, which reads via `registry.reader_by_name` **before** touching the tab (a failed parse leaves it intact), then blanks the tab's table (`DataTable::empty()` + `raw_content_modified = false`) so `apply_loaded_table` **reuses the active tab** rather than spilling into a new one, re-running the whole post-load pass (view-mode pick, JSON/YAML seeding, date inference). `tests/open_as_tests.rs::every_open_as_reader_name_resolves` pins the menu's reader names to the registry.
- **`load_file_in_new_tab` reuses a blank tab**: it pushes a placeholder tab *only* when the active tab is not blank (`col_count()==0 && raw_content.is_none() && !is_modified()`). Octa starts with one empty tab and the tab bar is hidden until a second tab exists, so unconditionally pushing left that empty tab stranded as a visible "Untitled" beside the file the user opened (cloud opens, archive-entry opens). Plain `load_file` never had the bug: `apply_loaded_table` does the same blank-tab check.
- **Column-wide date promotion**: `run_date_inference_pass` promotes string columns all matching one date/datetime layout to `Date`/`DateTime`. Ambiguous columns queue `pending_date_pickers` (European/US/leave-as-text). Binary readers excluded. The modal states how many are queued and offers **"Use this answer for all remaining columns"** (checkbox in egui temp memory, reset after each use); `takes_same_answer` only settles columns whose candidates actually contain the picked layout - forcing it on a column that never offered it would silently reinterpret its values - while `Choice::Skip` matches every queued column.
- **Whitespace trim on load**: `octa::data::trim::trim_string_columns(&mut DataTable) -> Vec<String>` strips leading/trailing whitespace from string cells + column titles (interior kept). `run_trim_pass` runs in `apply_loaded_table` before date inference when enabled; for DB tables re-syncs `db_meta.original`/`original_columns`. With `warn_on_whitespace_trim`, sets `pending_trim_warning` -> dismissible banner in `central_panel.rs` (next to the date banner). Both load banners (date, trim) have **Okay** (accept + close; date keeps the promotion) and **Dismiss** (date reverts via `revert_promoted_date_columns`; trim just closes).
- **Excel multi-sheet**: `ExcelReader` implements `list_tables` + `read_table(sheet)` and overrides `opens_all_tables() -> true`. `load_file` branches: ≤ `excel_max_auto_sheets` opens each sheet in its own tab; above it raises `pending_sheet_picker` (`src/app/dialogs/sheet_picker.rs`, multi-select). Excel *write* is single-sheet. **`TabState.sheet_name`** carries which table of a multi-table file the tab holds, so N sheets are not N tabs all called `book.xlsx`: `apply_loaded_table` clears it (a reused tab must not keep the last file's sheet) and the two callers that opened a *named* table set it afterwards via `label_active_tab_sheet` - the auto-open loop and `load_table` (which is also the table picker's route, so a SQLite/DuckDB table gets the same treatment). Deliberately NOT `custom_tab_label`, which `title_display` returns verbatim and would swallow the ` *` modified marker.
- **Archive viewer**: `.zip`/`.tar`/`.tgz` -> `octa::formats::archive_reader::ArchiveReader` (read-only); `read_file` returns one row per entry; `format_name` starts `"Archive"`. Action bar `src/app/archives.rs::render_archive_action_bar` when `active_tab_is_archive()`; **Open selected entry** -> `extract_entry_bytes` + tempfile + `load_file_in_new_tab` (pushes an empty placeholder so the listing isn't clobbered). `.tar.gz` not routed (ambiguous); `.tar.bz2` skipped.
- **Transparent compression**: `src/formats/compression.rs` (gzip + zstd, bomb cap `max_decompressed_bytes` default 4 GB + `_unlimited`; MB input in Settings). Shared entry `formats::read_table_auto` (CLI `read_table`, MCP `read_with_registry`); GUI `load_file` -> `OctaApp.pending_compressed_origin` -> `TabState.compressed_origin: CompressedOrigin{original,codec,temp}` + save-back `maybe_recompress_saved` at 3 save sites (temp-path match gates Save As). Inner format from the middle extension. `tests/compression_read_tests.rs`.
- **Malformed-file repair** (opt-in, default off): `maybe_offer_repair` runs `csv_reader::analyze_delimited`; if flagged raises `pending_file_repair` -> `src/app/dialogs/repair_file.rs`. `resolve_file_repair` reloads via `read_delimited_opts` (`ReadOptions { lossy_utf8, delimiter, strip_bom_controls, preserve_ragged }`). CSV/TSV only. **Ragged rows preserve all data, not drop it**: when field counts disagree with the header, `analyze_delimited` sets `preserve_ragged=true` and the repair dialog shows a "Keep extra values (add columns)" checkbox (`dialog.repair_keep_extra`, toggling it calls `OctaApp::refresh_repair_preview`); `build_table_from_reader(preserve_ragged=true)` widens the table to the longest record (overflow cols `column_N` via `overflow_column_name`) instead of trimming each row to the header (short rows still pad Null). The normal streaming read keeps `preserve_ragged=false`.
- **Write options** (`src/formats/write_options.rs`): `WriteOptions { parquet, csv }` whose `Default` reproduces byte-for-byte what Octa wrote before the module existed **except for the Parquet codec**, which is deliberately **zstd**: uncompressed parquet measured only 1.6x smaller than the source CSV where zstd managed 5.4x, at ~1% write and ~3% read cost, and `file_internals` was flagging Octa's own output for it. `write_parquet` delegates to `write_parquet_with(ParquetOptions::default())`, so the plain `write_file` path compresses too - there is one writer, not two that can drift. The trait gained `write_file_with_options` (default body forwards to `write_file`, so only parquet/csv override) and `write_file_schema_aware` grew an options parameter. `AppSettings.write_options` holds the defaults; the shared expander widget is `ui::settings::render_write_options` (**library-side** so both the Settings dialog and the binary's batch-convert dialog can call it). Save As uses the settings - it is the OS file picker with nowhere to host controls. `Cli::write_options()` loads `AppSettings` too (precedence flag > `settings.toml` > built-in), so CLI and GUI write the same files; MCP `convert` still passes `&Default::default()` (no settings plumbed into `ToolContext`). i18n `[wo]`.
- **Large-file mode** (`src/formats/large.rs`): the one reader that returns a **handle** rather than a `DataTable`. `LargeTable::{columns, row_count, page(offset, len, order, filter), filtered_count}` over an in-memory DuckDB scanning the file in place (`ScanKind::{Parquet,Csv,Json}`); the sort column is addressed by name from `self.columns` and quoted, and `filter` is the only caller-supplied SQL, built by `large_file::search_filter` from typed inputs with quotes doubled. `convert_to_temp_parquet` is the fallback for formats DuckDB cannot scan (the one path that does hold a whole table in memory, which is why the notice warns about it). App side `src/app/large_file.rs`: `intercept_large_file` runs in `load_file` before the normal read; **it is the only way in** (there is no menu entry - a manual "Open in large-file mode" was removed) and it gates on `large_file_min_bytes` (10 GB) OR a stated row count (Parquet footer only) at or above **`formats::initial_load_rows()`** - the streaming cap itself, deliberately not a second setting, so an unlimited cap means size alone decides. `TabState.large` makes `is_readonly()` true. **Three things have to stay true together or the window is unusable**, and all three were once wrong: (1) `recompute_filter` fills `filtered_rows` with the rows of the **page** (not the file, and not nothing - clearing it painted column headers over an empty grid); (2) after a page step the viewport lands on the `PAGE_OVERLAP` seam, never on a scroll edge, because parking it at an edge re-arms the opposite edge trigger and the two steps then ping-pong a query per frame; (3) the filtered total is carried on `table.total_rows` and only re-counted when the filter changes, since the edge triggers are evaluated every frame. Navigation is the **virtual scrollbar**: `TableViewState::set_virtual_rows(Some((offset, file_rows)))` makes the hand-drawn bar stand for the file and emit `TableInteraction::jump_to_row` -> `large_jump_to_row`, which centres the window on that row (paging alone would be 50,000 pages over 100M rows). The wheel still steps a page via `interaction.needs_more_rows` / `scroll_y() <= 0`; the search box becomes a WHERE clause **after a 400 ms settle**. **Ceiling: pages are fetched on the UI thread** (DuckDB serves a 2,000-row page from a 16 GB Parquet in ~0.1 s at any offset, so this is fine there and wrong for a deep OFFSET into a huge CSV). CLI `--sql --stream` registers `data` as a view via `SqlWorkspace::add_view_from_scan`, so an aggregate covers every row regardless of `--rows`; every other action warns on stderr. **MCP/chat stream per tool, never in `resolve`**: `ToolContext.large_file_min_bytes` + `ToolContext::scan_for(source)` (same gates as `resolve`, sandbox included) return a `LargeTable` only for a local scannable file over the threshold, and exactly four tools opt in - `count_rows`, `schema`, `read_table`, `run_sql` - each flagging `streamed: true`. Wiring `resolve` itself would have made `union_tables`/`join_tables`/`diff_tables`/`correlation`/`detect_outliers`/`data_drift` answer from a slice silently. i18n `[largefile]` + `SizeUnit` (renamed from `SyntaxSizeUnit`, gained `GB`).
- **Clean headers on load** (`clean_headers_on_load`, default off): `octa::data::trim::clean_headers(&mut DataTable) -> Vec<String>` snake_cases column titles (trim, lowercase, non-alphanumeric runs -> `_`, de-collide `name`/`name_2`, empty -> `column`). `run_clean_headers_pass` runs in `apply_loaded_table` after the whitespace-trim block (re-syncs `db_meta` baseline for DB tables); Settings checkbox next to `trim_whitespace_on_load`. i18n `settings.clean_headers`(+`_status`/hint).
