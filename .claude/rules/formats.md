# Format readers, loading and writing

## Registry

Canonical format registration order: `FormatRegistry::new()` (`src/formats/mod.rs`); user-facing list `docs/getting-started/supported-formats.md` — both update together. Read-only formats (SAS, R, HDF5, NetCDF, EPUB, GeoJSON, Fixed-Width) inherit `supports_write=false`.

`TextReader` claims every highlightable source/config extension (`.py`/`.rs`/`.go`/web markup/...) so they're advertised as supported; `highlight_whitelist_is_supported` pins `HIGHLIGHT_WHITELIST` to the registry's set. `formats::filename_reader_name(file_name)` matches extension-less filename conventions (`Dockerfile`, `Dockerfile.*`, `Containerfile`, `Containerfile.*`) to the Text reader, checked in `reader_for_path` between the extension and sniff steps; a bundled `assets/Dockerfile.sublime-syntax` (loaded best-effort like Terraform/TOML) + `syntax::syntax_for_filename` highlight them; `directory_tree::file_is_listed` keeps known filenames visible in the sidebar filter. `src/formats/sniff.rs::sniff_format` does content-based detection (magic bytes + JSON/CSV probes) for missing/wrong extensions: `reader_for_path` consults it before the Text fallback, `load_file` retries via `try_content_sniff_reload`; `reader_by_name` maps a sniff result to a reader.

## Module layout

- `src/data/encoding.rs`: `decode_bytes(&[u8]) -> (String, &'static str)` and `read_to_string_detected(path)` — BOM sniff, then UTF-8 fast path, then `chardetng` + `encoding_rs`. Used by `TextReader`/`MarkdownReader` so non-UTF-8 (Windows-1252/Latin-1/UTF-16) text opens. CSV keeps its own streaming path (`csv_reader` `lossy_utf8`).
- `src/formats/mod.rs`: `FormatReader` trait + `FormatRegistry`. Multi-table sources implement `list_tables`/`read_table(name)`; single-table formats fall through to `read_file`.
- `src/formats/parquet_reader.rs`: `build_arrow_array` + `data_type_from_string` map our type-name strings <-> Arrow `DataType` (update together). Native reader (parquet-58) rejects >32,767 row groups; `read_file` retries via a DuckDB path (`read_parquet` + `query_arrow`). Both honour `initial_load_rows` and strip pandas index columns via `pandas_index_columns`. **arrow/parquet are held at 58 by `duckdb` and `orc-rust`** (rechecked 2026-10-27): duckdb 1.10506 (DuckDB 1.5.6) needs arrow `^58`; the arrow 60 duckdb is 1.20000 = DuckDB 2.0.0, held back on purpose (see the Cargo.toml comment); orc-rust 0.9 and its main branch need arrow 59 and zstd 0.13. The old `thrift 0.17` advisory (GHSA-2f9f-gq7v-9h6m, OOM on a malicious Parquet footer) is closed: parquet 58.4.1 moved to thrift 0.23.0, the patched release. zstd 0.13 stays in the tree through orc-rust and parquet 58, hence the three zstd ignores in `deny.toml`. Aliasing a newer parquet beside arrow 58 was considered and rejected - a third arrow copy in the binary, plus `arrow_ipc_reader.rs` and `file_io/mod.rs` both call `parquet_reader::{arrow_value_to_cell, data_type_from_string, build_arrow_array}`, and `parquet_reader.rs` would have to juggle two arrow versions between the native reader and its DuckDB fallback. Recheck when a DuckDB 2.0 bugfix release lands or orc-rust ships arrow 60.
- `src/formats/spss_reader.rs`: SPSS read-only via `ambers` (needs arrow ^57; pinned `arrow57 = { package = "arrow", version = "57" }` alongside arrow 58).
- `src/formats/{sas,stata,rds,dbf,hdf5,netcdf,geojson,epub}_reader.rs`: pure-Rust, mostly read-only. RDS = tabular subset. `geojson_reader` claims only `.geojson`. `epub_reader` uses `rbook` + `htmd` (Apache-2.0; `epub`/`html2md` crates are GPL-3.0, blocked).
- `src/formats/fwf_reader.rs`: fixed-width (`.fwf`/`.prn`), read-only. `infer_field_ranges` finds boundaries from always-blank char positions; first line is header. All Utf8. Pure `read_fwf(&str, &Path)`.
- `src/formats/numpy_reader.rs`: NumPy `.npy` (single array) + `.npz` (zip of named arrays -> multi-table via `list_tables`/`read_table`), read-only. `.npy` parsed by `npyz` (dtype dispatched on `TypeChar`+byte width -> `CellValue`); 1-D -> one `value` col, 2-D+ -> `col_N` per trailing-axis index (row-major). `.npz` unzipped with the existing `zip` crate (no `npyz` `npz` feature, avoids a second zip). Structured/record arrays rejected.
- `src/formats/{msgpack,bson}_reader.rs`: MessagePack (`rmp-serde`) + BSON (`bson`, features `serde`+`serde_json-1`), both read-only. Each decodes to `serde_json::Value` then reuses `json_reader::json_to_table` (same flattening as JSON). BSON reads concatenated documents (mongodump shape) via `Document::from_reader` over a cursor, each -> `Bson::into_relaxed_extjson`.
- `src/formats/gpx_reader.rs` / `kml_reader.rs` (2026-11-12): GPX and KML/KMZ, read-only, both walk `xml_reader::parse_tree` (no new crate; element names are compared without their namespace prefix via `gpx_reader::local`). GPX = one row per waypoint / route point / track point (`kind`, `track`, `segment`, `name`, `lat`, `lon`, `elevation`, `time` as UTC `DateTime`; a time that does not read stays text); it opens in the Table view and the Map finds `lat`/`lon` through `geo_detect`. KML = one row per Placemark (`name`, `description`, `folder`, `kind`, first point's `lat`/`lon`/`altitude`); `kml_reader::read_with_features` returns one `MapFeature` per row (Point / LineString / Polygon with holes / MultiGeometry as a `GeometryCollection`), taken in `file_io`'s second pass like Shapefile, and `table_offers_map` names "KML". A `.kmz` reads `doc.kml` (else the first `.kml`) capped by `compression::max_decompressed()`. Not read: GPX extensions, KML styles, `gx:Track`, network links. Samples `samples/geo/walk.gpx`, `trip.kml`.
- `src/formats/xpt_reader.rs` / `qvd_reader.rs` (2026-11-13): SAS transport (`.xpt`/`.xport`, versions 5 and 8) and QlikView QVD, hand-written (QVD read-only; XPT writing is the next bullet), no new crate. XPT: 80-byte records, IBM floats, SAS format names decide Date/DateTime/time (`format_kind`), one number type so a column of whole values becomes `Int64`, several members go through `list_tables`/`read_table`; version 5 stores no row count, so trailing all-blank rows are dropped as padding (`ponytail:` note). QVD: XML header through `xml_reader::parse_tree`, symbol tables, bit-packed row index; a dual whose text says more than its number (`007`) makes the column text. Both reuse `sas_reader::format_unix_secs`. `sniff_format` knows XPT by its first 16 bytes; QVD is not sniffed (its marker sits past the 16 bytes read). **The unit tests build files by hand, so the proof is `tests/xpt_qvd_tests.rs`**: fixtures written by `pyreadstat` and `pyqvd` from `samples/tables/products.csv`, compared cell by cell with it. Not read: variable labels, QVD files from a real Qlik install (only pyqvd's output was tried). Both are in `windows/AppxManifest.xml` and named in the MCP `read_table` description.
- `src/formats/xpt_writer.rs` (2026-11-13): writes one dataset named after the file stem. **Version 5 when the table fits it** (names <= 8 chars, text <= 200 bytes: the FDA layout), else version 8. A column name that is no SAS name is refused by name, never renamed. A column is a number / date / datetime / time when every filled cell is one, else text; `Boolean` becomes 1/0, a `Decimal128` text cell is parsed to a float (about 16 digits, `ponytail:` note). `XptReader::write_file` refuses to overwrite a file of several datasets (the writer would drop the others). Proof beyond the round trip: `pyreadstat` read Octa's v5 and v8 output correctly (run by hand, not in CI). Labels are not written.
- `src/formats/access_reader.rs` (2026-11-13): Microsoft Access `.mdb` / `.accdb`, read-only, through the `jetdb` crate (pure Rust, MIT/Apache). Always multi-table (`list_tables` is `Some`), system and hidden tables and hidden columns left out. Date/Time is `Date` when no value has a time of day, else `DateTime`; Currency is `Decimal128(19, 4)`, cells through `decimal::number_cell`. `sniff_format` knows the `Standard Jet` / `Standard ACE` header. **Passwords**: `access_reader::needs_password` / `unlock` (a session map by path, memory only) feed the GUI's passphrase prompt (`intercept_protected_file`, `open_protected`: no temp copy, the reader decrypts as it reads); CLI and MCP read `OCTA_ACCESS_PASSWORD`. A password never appears in an error. `.mdb` database passwords do not encrypt and open without one. Fixture `tests/fixtures/protected.accdb` is jetdb's `enc_vbaV2007.accdb` (Jackcess test data, Apache-2.0), password `1234567890`; by hand jetdb's RC4 CryptoAPI and Access 2007 AES samples opened too (password `Test123`); its 2013 and non-standard AES samples were not proven, their passwords are unknown. Attachments and multi-value columns read empty. Proof: `tests/access_tests.rs` on fixtures written by Jackcess (Java) in the 2003 and 2010 layouts.
- `src/formats/mat_reader.rs` (2026-11-13): MATLAB `.mat`, read-only, every variable a table (`list_tables` always `Some`; `read_file` = the first variable that reads). Version 5 (`-v6`/`-v7`) parsed by hand (data elements, small-element format, `miCOMPRESSED` through flate2 under `compression::max_decompressed()`, names read from a 4 KB inflated prefix so listing stays cheap; top-level elements are NOT padded, inner ones are). Version 7.3 = HDF5 behind a 512-byte header through `hdf5-reader`: `MATLAB_class` decides the kind, shapes are reversed (column-major either way, so one builder serves both), cells are object references resolved against the `#refs#` datasets by address, struct field order from `MATLAB_fields` through `Group::resolve_vlen_reference_bytes` (it does not read as strings). Both layouts fill one `Var` model and `to_table`: vector = one column named after the variable, matrix `c1..cn`, char rows, cell of single values, 1x1 struct of equally long fields = one column per field, struct array = one row per element; whole-valued doubles become `Int64`, NaN empty. Refused with the reason (listed in the picker anyway): MATLAB table/string/datetime objects, class instances, sparse, complex, function handles, more than two dimensions, version 4. Proof: `tests/mat_tests.rs` on files written by `scipy.io.savemat` (plain and compressed) and `hdf5storage` (7.3), not by MATLAB itself; edges (big endian, small elements, NaN, unequal fields) by hand in `mat_reader_tests.rs`. Not sniffed. Sample `samples/tables/products.mat`.
- `src/formats/shapefile_reader.rs`: ESRI Shapefile (`.shp` + sibling `.dbf`/`.shx`), read-only, via `shapefile` crate (feature `geo-types`). `read_with_features` mirrors geojson: leading `__geometry` WKT col + `.dbf` attribute cols (field order read from the sibling `.dbf` via `dbase::Reader` since `dbase::Record` iterates unordered; reuses dbf_reader's `field_value_to_cell`/`dbf_type_string`), plus `Vec<MapFeature>` (`geo_types::Geometry::try_from(shape)`). Wired exactly like GeoJSON: `file_io.rs` populates `tab.geojson_features` on load -> `ViewMode::Map`; `available_view_modes` + `map.rs` treat `Some("GeoJSON")|Some("Shapefile")` as geometry-from-file (no lat/lon coord picker).
- `src/formats/html_reader.rs`: HTML tables, read-only, via `html5ever` + `markup5ever_rcdom` (both already in the tree via `htmd`). **Every** `<table>` is a table (`opens_all_tables`), captions name them, `rowspan`/`colspan` expand into repeated cells, `<th>` row -> header, values stay text so the load passes promote them. Nested tables are listed too; only a **pure wrapper** (cells holding nothing but another table) is dropped - the plan's "outermost only" rule swallowed a real table inside a layout table. **Open URL** already downloads to a temp file, so a Wikipedia page opens as its tables with no extra plumbing.
- `src/formats/pdf_reader.rs`: tables inside a PDF, read-only, via `pdf-extract` 0.12 (MIT, pulls lopdf + 9 small crates; decodes fonts and hands every glyph over through an `OutputDev`). Multi-table through `list_tables`/`read_table` (`Page N, table M`), so the ordinary table picker does the choosing. Pure `detect_tables(&[Glyph])`: lines by baseline (0.4 em), cells at gaps > 0.9 em, a run of lines with >= 2 cells is a table, columns = merged x ranges; a one-cell line or a gap > 2.6 lines ends it. **Scanned pages** (image XObject + < 20 text chars) are detected with lopdf and reported, never silently empty: all-scanned -> `pdfread.scanned_all` as the read error, some scanned -> `scan_note(path)` becomes the tab's `parse_error_banner` in `apply_loaded_table`. i18n section is `[pdfread]` because **`[pdf]` already belongs to PDF export** (a script that skipped existing sections wrote nothing because of that). One-slot scan cache keyed by path+mtime (picker, read and note share one parse); extraction wrapped in `catch_unwind` (third-party font code). Empty-password encryption is decrypted silently. Tests build real PDFs with `pdf-writer` (Helvetica text + an image-only page); `write_pdf_samples` (ignored) regenerates `samples/documents/{invoice,scanned}.pdf`. Ceilings in the module's `ponytail:` note.
- `src/formats/sql_dump_reader.rs`: `mysqldump` / `pg_dump` / `sqlite3 .dump`, read-only. **`extensions()` is empty on purpose** - `.sql` belongs to `TextReader` (added there so the sidebar filter and syntect see it), and the dump reader is reached only via `reader_by_name`, i.e. `OPEN_AS_FORMATS`'s new `("open_as.sql_dump", "SQL dump")` entry. No SQL parser: `split_statements` (one `skip_atom` scanner shared by the statement splitter, `split_top_level`, `matching_paren`, `split_qualified` and `strip_comments`) cuts the file up, `scrub`/`scrub_create_table` file the dialect off, and the result is replayed into an **in-memory `rusqlite`** read back through `sqlite_reader::{list_user_tables_conn, read_table_conn}` (both split out of the path-based versions for this). `db_meta` is cleared - the rows come from a scratch DB, not the file. Failures of `CREATE TABLE`/`INSERT`/`COPY` are counted into `DumpReport` and surfaced once in `apply_loaded_table` as `parse_error_banner` (i18n `sqldump.skipped`); every other failure (`SET`, `LOCK TABLES`, `ALTER ... OWNER TO`) is ignored by design. **Found only by testing real dumps**: `pg_dump` puts a `--` banner in front of every statement (so the schema-strip and COPY regexes had to skip leading comments) plus a `\restrict` psql line since 17.6, and MariaDB writes `DEFAULT current_timestamp()`, which SQLite rejects unless parenthesised. `COPY ... FROM stdin` rows are bound as parameters (`\N` -> NULL, `t`/`f` -> 1/0 for boolean columns). Cap `MAX_DUMP_BYTES` 512 MB; one-slot replay cache (`ponytail:` comment) so picker-then-open does not parse twice. `read_into_active_tab_as` now routes any multi-table chosen reader through `pending_table_picker`, and `load_table` takes `reader_name: Option<&str>` because `reader_for_path` would resolve a `.sql` to Text.
- `src/formats/lakehouse_reader.rs`: Delta Lake / Apache Iceberg, read-only. **NOT in the registry** (the unit of opening is a *directory*, not an extension). `detect(dir)` -> `LakehouseKind` by marker subdir (`_delta_log/` Delta, `metadata/` Iceberg); `read_dir` runs `INSTALL/LOAD {delta|iceberg}` + `delta_scan`/`iceberg_scan` on an in-memory DuckDB conn (DESCRIBE for typed cols, reuses duckdb_reader's `duckdb_type_to_arrow`/`duckdb_value_to_cell`; honours `initial_load_rows`). Directory-open plumbing: `file_io.rs::load_file` short-circuits `path.is_dir()` -> `load_lakehouse_dir`; GUI **File -> Open table folder...** (`ToolbarAction.open_table_folder` -> `pick_folder` -> `load_file_in_new_tab`). **Extensions install over the network on first use** (then cached). i18n `file_menu.open_table_folder`(+`_hint`). **Dataset mode**: `LakehouseKind::Parts(PartsFamily{Parquet,Delimited,JsonLines})` — non-lakehouse directories are scanned recursively (depth 8) for data parts, the majority family wins (`read_dir_report` lists skipped files -> `dataset.skipped_files` banner), and DuckDB scans the **explicit file list** (never globs — DuckDB errors on no-match globs). Directory-tree context menu "Open as dataset..." (`TreeAction.open_dataset`). i18n `[dataset]`.
- `src/formats/duckdb_nested.rs` (2026-11-06): DuckDB's nested values as text, reached from `duckdb_value_to_cell_tz`, the ONE conversion now (the SQL engine's copy is gone), so `.duckdb` tabs, SQL results, connection tabs and large-file pages all share it. Before it, `duckdb_type_to_arrow`'s word search typed `INTEGER[]` as `Int64`, each cell held a `{:?}` dump of its whole batch, and every typed writer dropped those cells: `--convert x.duckdb y.parquet` wrote NULL over every vector and reported success. Nested types now keep DuckDB's spelling as `data_type` (`data_type_from_string` falls back to text for them). **The text must cast back, not just read well**: a connection tab saves whole rows, so it returns through `CAST`. Arrow's display fails that: it leaves strings unquoted (`['r,s']` comes back as two elements with no error), writes a map's `=` as `:`, and cuts a 39-digit HUGEINT to 38 digits, so decimals are formatted from the raw value. A formatting failure prints the debug text, never `NULL`. Known ceiling: no text says which member of a UNION a value is in, so a whole-row save moves it into the text member (pinned). The driver's `ValueRef` is `non_exhaustive`, so a catch-all must stay and a variant it adds in future reaches debug text. **`TIME_NS` panics the driver** (`unreachable!` in row.rs): the file reader, large-file pages and dataset folders fetch it as text; `query_table_cut` cannot rewrite the user's SQL, so it refuses with the CAST to use. **The check runs in CI through `cargo test`**, on all three platforms, with no env var and no network, so it cannot pass as a no-op, and `Cargo.lock` is in the `rust` paths filter, so a driver bump runs it: `duckdb_nested_tests.rs` (casts every shape and type back through real DuckDB), `tests/duckdb_nested_tests.rs` (file, conversion to nine formats, edits, schema change, SQL, large file, binary), `db/duckdb_file_tests.rs::saving_a_row_keeps_its_nested_columns_exactly`. Open: TIMETZ reads without its offset; BIT and BIGNUM show their internal bytes.
- `src/data/decimal.rs` (2026-11-06): exact decimals. `CellValue` has none, so a decimal column is a `Decimal128(p, s)` type over cells holding the digits as text, or a `Float` where that says the same number (`decimal_cell`, the Parquet reader). `duckdb_type_to_arrow` used to say `Float64`, so Parquet got a DOUBLE and `...456.78` became `1.23e+35`; the Parquet reader's `raw as f64 / divisor` then rounded on read, and `data_type_from_string` had no decimal, so a Parquet decimal re-saved as text. **The type is what keeps the column a number**: `is_numeric_data_type` takes `Decimal128(`/`Decimal256(`, `sort_rows_by_columns` compares through `cmp_decimal` (text order put `10.00` before `9.00`, already wrong for `.duckdb` files), and `sql/engine.rs`'s and `duckdb_reader.rs`'s `arrow_to_duckdb_type` give `DECIMAL(p,s)`, so the SQL panel's SUM is exact. `build_arrow_array` has no way to report a failure, so every writer calls `refuse_unwritable_decimals` first (Parquet in `ParquetStreamWriter::write`, Arrow IPC before creating the file), or typed text or an oversized number would become NULL with a success message. Digits past the scale round half away from zero, like DuckDB's cast. ORC, Avro, CSV, JSON and xlsx write the digits as text. `schema_export::decimal_ddl` gives each dialect its own type (SQLite's affinity is `NUMERIC`, Exasol stops at 36 digits). **Text reads exactly too** (2026-11-06, user: "we must be as precise as possible, but also must prevent rounding issues when aggregating"; chose DECIMAL output and floats summed by the digits shown): `csv_reader::infer_cell_value` and `CellValue::parse_like` go through `decimal::number_cell` (a `Float` only when its shortest text says the same value, else the digits as `String`), `column_type_from_cells` (returns `String` now) types a column with a fraction `Decimal128(p,s)` through `DecimalShape` (exponent/NaN/>38 digits stay `Float64`, or `Utf8` when it holds digits a float would round), `num_parse::apply_style` is exact via `plain_text`/`number_cell`, `decimal::type_text_columns` retypes the `Float64` columns of the other `times::is_text_format` readers (not MessagePack/BSON, binary floats) in `read_table_auto` and `run_load_passes`, `bg_rows::cast_chunk` widens decimal columns per chunk (`widen_type`; an Int64 meeting a fraction becomes `Decimal128(19,0)` first, the earlier rows are not in the chunk), and `ScanKind::exact_scan_expr` gives large-file mode and `--stream` CSV scans `types={..DECIMAL..}` from one measuring pass that also counts rows. SQLite REAL without a declared type stays `Float64`. **Sums**: `decimal::Sum` (exact by shown digits, Neumaier fallback past i128/38 digits) for the status bar, chart Sum/Avg, cohort sums, calculated running total/difference/percent of total; `sql::run_query` registers through `set_active_table_summing` (`decimal::summing_columns`: a Float64 column whose values all fit is DECIMAL there), so pivot, time series, Summary, profile and reshape tabs sum exactly; the SQL panel/`--sql`/`run_sql` keep the declared type on purpose (user SQL on a DOUBLE is float arithmetic, documented). `append_rows` appends a Float into a DECIMAL column as its text, DuckDB's double cast lands one off past ~15 digits. Summary sums a numeric column in its own type (no `TRY_CAST AS DOUBLE`) and keeps reporting `DOUBLE` for Float64 columns. `Sum::mean` divides to 38 digits so it equals a float division of exact values; `mean_cell` keeps 12 extra digits. **Writers**: Avro writes `Schema::Decimal` (bytes) and reads it back by the column's scale (`avro_to_cell_typed`; before, a decimal column made the Avro writer fail and leave an empty file); ORC writes a decimal column as Float64 when every cell is Int/Float, else text (orc-rust has no decimal); xlsx writes Float cells as numbers and exact text as text. **JSON**: `json_reader::protect_long_numbers` turns every plain number a float would round (past ~15 digits, past i64) into a NUL-marked string before serde_json sees it (no `arbitrary_precision`: it would change every serde_json user), `restore_long_numbers` writes the marks back bare; JSON, JSONL, the JSON tree and db JSONL export use it. **Values, not spellings** (user 2026-11-10: "It's totally fine if 1.50 is 1.5 in a float ... I just want that aggregations, calculations and so on work"): `1.50` reads as the float 1.5 everywhere (text, servers, Parquet decimals); only digits a float would round are held as `String`. A version that kept `1.50` as typed was built and removed the same day, do not re-propose it. Those long digits are still numbers to `num_format::format_cell_number` (grouped, rounded by a column format), value-frequency bins, save-time rounding, Copy as INSERT (bare) and the CSV writer's decimal comma (`cell_text`, decimal columns only). Excel/ODS write them as text (15-digit program limit), ORC turns the whole column into text, YAML/TOML quote them; YAML and TOML also round long numbers on read (floats by their specs), documented in Exact numbers, Supported formats' round-trip list, Saving and the Help's "What a save keeps". Tests: `tests/exact_numbers_tests.rs` + `tests/decimal_tests.rs`, both ungated, so `cargo test` runs them on all three platforms. User pages `docs/usage/exact-numbers.md` + Help `EXACT_NUMBERS`.
- `src/formats/lance_reader.rs` (2026-11-06): Lance, read AND written through DuckDB's `lance` extension (about 100 MB on first use, 300 MB on disk). **In the registry** (`.lance`, and `sniff_format` answers for any folder holding `_versions/`), so CLI, MCP and Save As reach it, AND `LakehouseKind::Lance` for the directory-open path; `load_file` sends a dataset to `start_background_read` and `do_save_tab_inner` to a `SaveJob` at any size, or the download would freeze the window. **`FormatReader::writes_a_folder`** is the switch for anything that treats the written path as one file: encrypted zip, cloud upload, stdout, Raw view text and `write_split`'s size limit refuse it, auto-save skips it (each save stores the whole table again). `backup_existing_file` returns `Ok(None)` for a folder and `file_versions::keep` already did, since a save keeps the replaced version. A write is `COPY (SELECT .. FROM stage) TO .. (FORMAT lance, MODE 'overwrite')`, a new version committed atomically, so no temp-and-rename. **Types are exact both ways** (`exact_type` read, `stage_type` write), not `duckdb_type_to_arrow`, whose word search reads `INTEGER[]` as `Int64` and `FLOAT[3]` as `Float64`: a type Octa has no cell for keeps DuckDB's spelling as its `data_type` and is fetched as text (`lakehouse_reader::select_list`), and text casts back through the appender, so a save keeps vectors and a bad edit fails the write. Schema drift and the relationship map treat a dataset as one table. `CREATE INDEX` is refused on the 1.5.6 build, so what a save does to an index is unverified. Tests: `lance_reader_tests.rs` offline, `OCTA_TEST_LAKEHOUSE=1 cargo test --test lance_live_tests` and `--bin octa file_io::lakehouse` against the real extension, run by CI's `lance-live` job on all three platforms when the Lance code changes (see `packaging.md`); locally run on Linux only.
- `src/formats/mail/` (2026-11-01): mail, calendar and contact files, all read-only, one table per kind of item. Every reader fills a `MailBook`; `mod.rs` turns it into tables named by `Kind` (Mail, Calendar, Contacts, Tasks, Notes, Attachments; English and stable, like sheet names), and a kind the file does not hold is not offered. `mail_id` links Attachments to Mail. `eml_reader` + `mbox_reader` share `mime.rs` (`mail-parser` 0.11: 1.0 needs a newer Rust than our `rust-version`); `msg_reader` (`.msg`/`.oft`, `cfb` + `codepage`) + `pst_reader` (Microsoft's `outlook-pst`) share the MAPI property map in `mapi.rs`, so both agree on columns; `ics_reader` (`.ics`/`.vcs`) + `vcf_reader` share `content_line.rs` (own parser: unfolding and 2.1 quoted-printable); `olm_reader` is a zip of XML, undocumented by Microsoft, so names match ignoring case and anything unknown is skipped, never an error. One item opens all its tables; a mailbox goes through the table picker. A `.pst`'s picker counts come from each folder's contents table, so listing opens no message; reading a table opens only that kind, up to the initial-rows setting. **`.ost`/`.nst` are not supported**: Outlook 2013+ writes a 4 KB layout `outlook-pst` cannot read. Dev dependency `pst_writer` is `outlook-pst-rw` renamed (its lib name clashes), used by the tests to build a `.pst`; `samples/mail/` holds one file per extension, regenerated by the ignored `write_*_sample` tests. Docs: `docs/usage/mail-and-calendar-files.md`. **When adding a format, open a real sample through `load_file`, not only the reader**: the mail tests called the readers directly, so nobody saw the GUI refuse `.msg` and `.oft` as password protected (see below).
- `src/formats/follow.rs`: `FollowState`, the appended-bytes reader behind **Follow file** (complete lines only, a shrunk or replaced file is reported, not guessed at). The rest is under Live tabs in `ui.md`.
- `src/formats/partial_reads.rs` (2026-11-06): every read `read_table_auto` stopped at the row cap, per thread. It is the one record of "this table is not the whole file"; the surfaces take it when an action is done (`cli::dispatch`, `mcp::tools::say_if_partial`). `DataTable::refuse_partial_overwrite(source, target)` is the other half: anything that can write over its own input asks it first, including the batch engine, so the GUI is covered too. The harmonise engine goes further and refuses any input that is its own output (`data::same_file`), read whole or not, because the GUI dialog has no such check and "Your files are never modified" is a promise. A capped read written back shortens the file and reports success; found 2026-11-06 in five MCP tools, three CLI writers and both engines. `BatchItem.partial` says which copy is short: `status: partial` in `report_table`, and a banner on the GUI's report tab (`batch.partial`), where nothing takes the record because the worker is its own thread. GUI Harmonise has no such mark yet.
- `src/formats/xml_reader.rs`: `parse_tree` handles `Event::GeneralRef` itself and unescapes attributes. quick-xml 0.41 reports `&amp;` and friends as separate events, and dropping them lost the characters without an error.

## Write Support

Most formats write. CSV preserves its `csv_delimiter`. Excel writes via `rust_xlsxwriter` (calamine read-only); only `.xlsx` round-trips. ODS has a hand-rolled OpenDocument 1.2 writer. TOML/YAML serialize through a JSON intermediary.

**Excel formulas** (T11): `calamine::Reader::worksheet_formula` gives a parallel `Range<String>`; `excel_reader::collect_formulas` maps it onto `DataTable.formulas: HashMap<(row, col), String>` (sparse, `=` prefixed - calamine stores it without). **Three offsets have to line up**: the value range's `start()`, the formula range's own `start()`, and the header row, which is row 0 of the value range and not a data row. Walks `used_cells()`, so cost is proportional to the number of formulas, not the sheet. **Read it through `DataTable::formula(row, col)`, never the map**: that accessor withholds a formula from an edited cell (the typed value wins) and from a table with `structural_changes` (a formula says `=B2*C2` and Octa cannot rewrite references after an insert) - one chokepoint shared by the grid's hover tooltip (`table_view/rows.rs`), the Record view's inline line and the writer. Write-back is `WriteOptions.xlsx.preserve_formulas` (**off by default**, `xlsx_formatting_is_off_by_default` pins it) -> `write_workbook_with(path, sheets, preserve)`, a sibling of `write_workbook` so the CLI/MCP/Workbook-dialog callers keep today's behaviour with no signature churn. The written `Formula` carries `.set_result(cell.to_string())`, else the file reads as zeros until something recalculates it. i18n `wo.xlsx_preserve_formulas`(+`_hint`). `tests/excel_formula_tests.rs` asserts the `<f>` elements are present or absent per setting. **Adding a field to `DataTable` costs ~70 struct-literal edits** - that is what it took here.

**Big saves stream to a worker** (2026-10-17, `src/app/file_io/save_job.rs`): a CSV/TSV/Parquet save of more than one slice (`slice_rows(cols)` = 500,000 cells) is a `TabState.saving: SaveJob` instead of a synchronous write. The window thread copies one slice per frame with `clone_with_rows` (edits read inline, rounding applied per slice) into a `sync_channel(1)`; the worker runs `formats::write_slices` (the ONE CSV/TSV/Parquet writer: `write_delimited_with` and `write_parquet_with` are one-slice uses of it) through `write_atomically`, then `SaveBack::run` (zip write-back or recompression, read on the window thread by `SaveBack::of`). Memory: three slices, never a copy of the table (a 1M-row complaints.csv is ~1 GB in Octa). The tab is read-only (`is_readonly`), sorting and row streaming wait, a second save of the tab or any save into the same path is refused (`saving.busy`: two writes would share a temp name). `RowsStamp` (rows address, count, offset, edit count, columns; NOT undo counts, because marks are allowed read-only and push undo entries) stops a save whose table changes before the last slice was handed over (`saving.stopped`, temp removed); after that the file is complete and only the tab is left alone. Landing goes through `finish_table_save`, shared with the synchronous path; a plain Save of a cloud tab uploads on landing (`SaveJob.upload`). `stop_save_jobs` at exit drops the jobs and waits up to 2 s so no hidden multi-GB temp stays. Measured per 1M rows: CSV ~1.1 s, Parquet ~2.4 s, xlsx ~8 s. **Every other format writes in the background too** (2026-10-17): `JobWriter::Whole { reader, opts, carry }` puts the slices back together on the worker (one full copy, worker-held; `ponytail:` note in the module) and calls the format's own `write_file_with_options` from a fresh `FormatRegistry`; `Carry::of` sends marks, formulas (minus edited cells'), `structural_changes`, source path and format name for a Rebase, nothing for a Copy (as `clone_with_rows` never did). Only formats whose `FormatReader::writes_in_place()` is true (SQLite, DuckDB, GeoPackage: the three that override `write_file_retagged`) and `db_meta` tabs write while the window waits. **Backups and earlier versions are `PreStep`s** run by the worker before the write (sync path runs the same `PreStep::run`); `keep_version` now returns `Option<PreStep>`; the assistant backup is taken at the write, not at the top of `do_save_tab_inner`, and `SaveJob.assistant_backup` clears the flag on landing. **Close/exit prompt**: `save_in_foreground` is gone; a save that started a job gets `SaveJob.then = Some(AfterSave::{CloseTab, Exit})`, and `drive_save_jobs` closes the tab / sends `ViewportCommand::Close` once it landed and the tab is unmodified. `SliceFeed`, `RowsStamp` and `slice_rows` live in `src/app/slice_feed.rs`, shared with the SQL copy job (`DataStamp` there wraps a `RowsStamp` plus undo/redo counts). Every worker poll that treats all endings alike uses `ServerTask::poll_result`. **Picker answers apply on a worker**: `src/app/column_cast_job.rs` (`ColumnCastJob`, `start_column_cast`) runs the date and number ambiguity pickers' conversion on a one-column copy and puts it back only if the rows and that column are unchanged; `TabState.column_casts` counts in `TabState::holds_rows` (read-only, no sort, no streaming). **Large-file Save As** (`file_io/large_save.rs`): `do_save_tab_inner` routes a `tab.large` tab to `start_large_export`, which runs `LargeTable::export_job` (DuckDB `COPY (SELECT ... [WHERE view filter] [ORDER BY view sort]) TO tmp` on a cloned connection, through `write_atomically`; `ExportFormat` = CSV/TSV (decimal comma spelled by `replace(CAST(.. AS VARCHAR))` per Float/Decimal column since `DECIMAL_SEPARATOR` is read-only in DuckDB; BOM prepended from a `.body` temp), Parquet (codec + row group size), JSON (array) / JSONL; anything else refused `largefile.save_formats`). `TabState.large_export`, dropped = `InterruptHandle::interrupt`. Refuses the source path itself; plain Save on a large tab says `largefile.save_in_place` (before this, the partial dialog's Save anyway wrote the 2,000-row page over the source).

**`.xlsx` formatting export** (`src/formats/xlsx_style.rs`, pure + unit-tested; the writer in `excel_reader.rs` consumes its decisions and decides nothing itself): marks, conditional colours, frozen columns and per-column number formats cross into a saved workbook. `map_rule(&CondRule) -> XlsxRule` decides per rule whether it becomes a **live** Excel rule (`Cell`/`Text`/`Blank`) or must be **`Bake`**d, i.e. painted onto the cells matching it today. Two Excel semantics force baking and are the whole reason the module exists: ordering operators over **text** (Excel collates by locale, `rule_matches` by Rust string ordering) and **case-sensitive** `Eq`/`Ne`/`Contains`/`NotContains` (Excel's `cellIs`/`containsText` are unconditionally case-insensitive, so a native rule would colour *more* cells than Octa). A live Excel rule also always overrides a cell's direct fill with no notion of list order, so the export **partitions at the first baked rule**: everything before it stays live, everything from it on is painted. Gate `WriteOptions.xlsx.include_formatting` (**default off**). Saving a tab that carries any of the four asks once anyway via `save_would_ask_about_style` -> `pending_xlsx_style_save` -> `src/app/dialogs/xlsx_style_save.rs` (forced choice, optional remember -> writes the setting); the same predicate gates `auto_save::tab_is_auto_saveable`, since auto-save must never raise a modal. **One-way**: Octa reads a styled `.xlsx` back as plain data.

## Loading and format design patterns

- **Lazy row loading**: Parquet loads `initial_load_rows` sync, then `bg_row_buffer`/`bg_loading_done`/`bg_can_load_more` background-stream (UI drains per frame). **Chunks never re-read from the start** (2026-10-17): CSV/TSV seeks to the `csv::Position` the last chunk stopped at (`TabState.csv_resume`, keyed by the record count so a mismatch falls back to counting; reset on every placement), Parquet uses `with_offset`/`with_limit`. **Chunks get the load's conversions** (`bg_rows::cast_chunk`, before append): `TabState.chunk_trim` and `chunk_casts` (date layout or number style per column) are recorded by `report_load_passes`, `report_date_findings` (load + Detect dates) and both ambiguity pickers; a cast applies only while the column still has the type it gave (so Dismiss/undo/Change type need no bookkeeping), and an unreadable value stays text. Eviction follows the Settings row limit (`rows_to_evict`: past cap + cap/2, back to cap; Unlimited never). The drain reads `bg_loading_done` BEFORE draining, else rows handed over between the drain and the read were dropped with the buffer.
- **Column types as strings**: `ColumnInfo.data_type` holds Arrow type names; all readers must round-trip through `data_type_from_string()`.
- **Parse-error fallback**: `load_file` calls `fallback_to_raw_text` when a text-format reader errs — reloads via `TextReader`, switches to `ViewMode::Raw`, shows a dismissible `tab.parse_error_banner`. Files over `raw_view_max_bytes` (50 MB) skip it; binary formats never fall back.
- **Default view per file type**: `apply_loaded_table` (`file_io.rs`) overrides the Table default after parsing: `format_name == "JSON"` && `json_value.is_some()` -> `ViewMode::JsonTree`; `"YAML"` -> `ViewMode::Raw` (both close the SQL panel). JSONL/others stay Table. Hardcoded, not a setting; `available_view_modes` already offers these.
- **Open as / Reopen as (parse through a chosen reader)**: one format list (`toolbar::OPEN_AS_FORMATS` = {JSON, JSON Lines, CSV, TSV, YAML, TOML, XML, Markdown, Text}) behind two menus, for files whose extension lies (a `.log` that is really JSON). **File -> Open as ->** `<fmt>` (`ToolbarAction.open_as_files`) -> `OctaApp::open_files_as`: pick-the-format-then-the-files, `rfd` picker **unfiltered** (`All Files`) on purpose, N files -> a tab each. **View -> Reopen as ->** `<fmt>` (`ToolbarAction.open_as`, gated on `has_source_path`) -> `OctaApp::reopen_active_as`: re-reads the file already in the tab. Both funnel into `read_into_active_tab_as(path, reader_name)`, which reads via `registry.reader_by_name` **before** touching the tab (a failed parse leaves it intact), then blanks the tab's table (`DataTable::empty()` + `raw_content_modified = false`) so `apply_loaded_table` **reuses the active tab** rather than spilling into a new one, re-running the whole post-load pass (view-mode pick, JSON/YAML seeding, date inference). `tests/open_as_tests.rs::every_open_as_reader_name_resolves` pins the menu's reader names to the registry.
- **`load_file_in_new_tab` reuses a blank tab**: it pushes a placeholder tab *only* when the active tab is not blank (`col_count()==0 && raw_content.is_none() && !is_modified()`). Octa starts with one empty tab and the tab bar is hidden until a second tab exists, so unconditionally pushing left that empty tab stranded as a visible "Untitled" beside the file the user opened (cloud opens, archive-entry opens). Plain `load_file` never had the bug: `apply_loaded_table` does the same blank-tab check.
- **Load passes run on the reader thread**: `file_io/passes.rs::run_load_passes(table, PassSwitches)` (trim, clean headers, dates, numbers; pure, no `OctaApp`) runs inside the `load_file` worker for files >= `BACKGROUND_LOAD_MIN_BYTES`, and `PendingLoad.rx` carries `(DataTable, Option<LoadPasses>)`; `apply_loaded_table_with` runs them itself only when `None` (small or multi-table reads). `report_load_passes` turns the result into banners/pickers on the UI thread. Never put a pass back on the UI thread: at 5M rows the date check froze the window ~70 s (2026-10-16).
- **Column-wide date promotion**: gated by `detect_dates_on_load`, **off by default**; `header_rows::use_header_rows`/`header_is_data` take the same flag (recipe steps record it as `dates`, default true for old files). `date_infer::infer_column` first keeps only layouts that parse > half of the first 1000 values (`plausible_layouts`), so a text column costs ~0.1 s at 5M rows and a date column ~1.3 s check + ~1.3 s apply. Ticking the setting raises the Settings `ToggleWarning` modal (`cell_line_breaks` had one too until 2026-10-17, when `table_view::layout::ensure_row_y_offsets` started measuring only the rows in view; still off by default, the user's call). **Columns > Detect dates** (`src/app/date_detect.rs`): copies only `column_looks_like_dates` columns, runs `infer_column` on a `spawn_local_task` worker, `TabState.date_detect` makes the tab read-only (`is_readonly`), blocks `sort_tab_rows` and row streaming; the answer goes in as `ConvertColumn`s folded by `coalesce_undo_since`, after checking row count and column names are unchanged. Load-time `find_dates` promotes string columns all matching one date/datetime layout to `Date`/`DateTime`. Ambiguous columns queue `pending_date_pickers` (European/US/leave-as-text). Binary readers excluded. The modal states how many are queued and offers **"Use this answer for all remaining columns"** (checkbox in egui temp memory, reset after each use); `takes_same_answer` only settles columns whose candidates actually contain the picked layout - forcing it on a column that never offered it would silently reinterpret its values - while `Choice::Skip` matches every queued column.
- **Whitespace trim on load**: `octa::data::trim::trim_string_columns(&mut DataTable) -> Vec<String>` strips leading/trailing whitespace from string cells + column titles (interior kept). `run_load_passes` trims first (before dates) when enabled; for DB tables re-syncs `db_meta.original`/`original_columns`. With `warn_on_whitespace_trim`, sets `pending_trim_warning` -> dismissible banner in `central_panel/banners.rs` (next to the date banner). Both load banners (date, trim) have **Okay** (accept + close; date keeps the promotion) and **Dismiss** (date reverts via `revert_promoted_date_columns`; trim just closes).
- **Excel multi-sheet**: `ExcelReader` implements `list_tables` + `read_table(sheet)` and overrides `opens_all_tables() -> true`. `load_file` branches: ≤ `excel_max_auto_sheets` opens each sheet in its own tab; above it raises `pending_sheet_picker` (`src/app/dialogs/sheet_picker.rs`, multi-select). Excel *write* is single-sheet. **`TabState.sheet_name`** carries which table of a multi-table file the tab holds, so N sheets are not N tabs all called `book.xlsx`: `apply_loaded_table` clears it (a reused tab must not keep the last file's sheet) and the two callers that opened a *named* table set it afterwards via `label_active_tab_sheet` - the auto-open loop and `load_table` (which is also the table picker's route, so a SQLite/DuckDB table gets the same treatment). Deliberately NOT `custom_tab_label`, which `title_display` returns verbatim and would swallow the ` *` modified marker.
- **Archive viewer**: `.zip`/`.tar`/`.tgz` -> `octa::formats::archive_reader::ArchiveReader` (read-only); `read_file` returns one row per entry; `format_name` starts `"Archive"`. Action bar `src/app/archives.rs::render_archive_action_bar` when `active_tab_is_archive()`; **Open selected entry** -> `extract_entry_bytes` + tempfile + `load_file_in_new_tab` (pushes an empty placeholder so the listing isn't clobbered). `.tar.gz` not routed (ambiguous); `.tar.bz2` skipped.
- **Transparent compression**: `src/formats/compression.rs` (gzip + zstd, bomb cap `max_decompressed_bytes` default 4 GB + `_unlimited`; MB input in Settings, 1 MB = 1,000,000 bytes). **One process-wide cap**, `compression::max_decompressed()` / `set_max_decompressed`, built like `initial_load_rows`: the GUI sets it from `AppSettings::max_decompressed()` (Unlimited folded in) at start and on Apply, the CLI and `run_mcp` from the global `--max-decompressed MB|unlimited` flag, else settings.toml, else 4 GB (headless machines have no Settings dialog; no MCP tool parameter can raise it). Every read passes `max_decompressed()`; never `DEFAULT_MAX_DECOMPRESSED_BYTES` directly (that is only the starting value and the Settings default). Shared entry `formats::read_table_auto` (CLI `read_table`, MCP `read_with_registry`); GUI `load_file` -> `OctaApp.pending_compressed_origin` -> `TabState.compressed_origin: CompressedOrigin{original,codec,temp}` + save-back `maybe_recompress_saved` at 3 save sites (temp-path match gates Save As). Inner format from the middle extension. `tests/compression_read_tests.rs`.
- **Protected workbooks are told apart by their `EncryptedPackage` stream** (`decrypt::xlsx_needs_passphrase`, opened with `cfb`), never by the OLE signature alone: `.msg`, `.oft` and legacy `.xls` carry it too, and `intercept_protected_file` runs on every file, so until 2026-11-05 all of them were refused as password protected in the GUI while the CLI read them fine.
- **Encrypted zips, write side** (`src/formats/encrypt.rs`, the write half of `decrypt.rs`): AES-256 zip entries only. `write_encrypted_zip`, `replace_entry_encrypted` (copies every other entry raw, never decrypts it; appends a missing entry), `write_table_encrypted` / `write_bytes_encrypted` (plain copy only in a `ProtectedTempDir`, entry name must be a bare file name); all go through `formats::write_atomically`. `ProtectedTempDir`: private 0700 `octa-protected-*` folder holding a locked `.lock` for its life, removed on drop; `sweep_stale_protected_dirs(temp_dir)` runs in `OctaApp::new` and removes only unlocked folders older than 60 s. **Opened zip -> save back**: `open_protected` (`dialogs/passphrase.rs`) decrypts the first readable entry (never a compressed file or a nested archive, `opens_outside_private_folder` with the archive list taken from `ArchiveReader.extensions()` plus `.tar.gz`: decompression and the listing's Open selected entry both write plain data into the shared temp folder; `a_compressed_entry_inside_an_encrypted_zip_is_never_opened`) to `<ProtectedTempDir>/<entry file name>` and pushes it onto `OctaApp.pending_protected_origins` (a list: a second open must not drop the first while its background read runs). **Every tab placement** (`apply_loaded_table`, `finish_large_open`, `open_empty_file_placeholder`) calls `OctaApp::claim_protected_origin(tab_idx, path)` over the pure `take_protected_origin(pending, tabs, path)`: the pending origin for exactly that path, else a clone of the one a tab already on it holds (Refresh, Reopen as, other workbook sheets), so the folder lives as long as any holder; the claim also clears a zip-name label off a tab reused for an unrelated file. `release_unclaimed_protected_origins` (after each protected open and once per frame) drops pending origins with nothing in flight for their path (`pending_load`, table/sheet picker, large-file notice, repair prompt), so a failed or cancelled open does not keep its plaintext until exit. `intercept_large_file` opens a protected copy normally when DuckDB cannot scan its format (`is_protected_copy`): conversion would leave a plain Parquet in the shared temp folder. `take_reload_slot` moves `protected_origin` into the fresh tab like `cloud_origin`, so a Refresh never drops the folder under the read. `TabState.protected_origin: ProtectedOrigin { zip, entry, passphrase, temp_file, _temp: Arc<ProtectedTempDir> }`, NOT `Debug` (passphrase). `after_tab_saved(tab, written, wrote_text)` (Rebase only) puts the written copy back via `replace_entry_encrypted`; a write-back failure keeps the tab unsaved the way it was saved (`raw_content_modified` for a text save, `structural_changes` for a table save, so a retry never re-parses a table from text), since the edits live only in the plain copy; a Save As elsewhere drops the origin and the zip-name label. The close prompt's Save goes to Save As (`save_tab_as(tab_idx)`) for a tab with no file or a cloud object that may not be written, and closes the tab, or exits, only when the tab is no longer modified afterwards. `file_io::save::save_target(tab, path)` maps a temp copy to the file it stands for (`.gz` original, zip) for `keep_version` and both `backup_existing_file` calls, so no backup or version is ever of a temp copy. Session and Ctrl+Shift+T record the zip (passphrase asked again); `on_exit` drops every origin so the folders go even if eframe never drops the app. The passphrase is never persisted, logged or put in a message.
- **Malformed-file repair** (opt-in, default off): `maybe_offer_repair` runs `csv_reader::analyze_delimited`; if flagged raises `pending_file_repair` -> `src/app/dialogs/repair_file.rs`. `resolve_file_repair` reloads via `read_delimited_opts` (`ReadOptions { lossy_utf8, delimiter, strip_bom_controls, preserve_ragged }`). CSV/TSV only. **Ragged rows preserve all data, not drop it**: when field counts disagree with the header, `analyze_delimited` sets `preserve_ragged=true` and the repair dialog shows a "Keep extra values (add columns)" checkbox (`dialog.repair_keep_extra`, toggling it calls `OctaApp::refresh_repair_preview`); `build_table_from_reader(preserve_ragged=true)` widens the table to the longest record (overflow cols `column_N` via `overflow_column_name`) instead of trimming each row to the header (short rows still pad Null). The normal streaming read keeps `preserve_ragged=false`.
- **Write options** (`src/formats/write_options.rs`): `WriteOptions { parquet, csv }` whose `Default` reproduces byte-for-byte what Octa wrote before the module existed **except for the Parquet codec**, which is deliberately **zstd**: uncompressed parquet measured only 1.6x smaller than the source CSV where zstd managed 5.4x, at ~1% write and ~3% read cost, and `file_internals` was flagging Octa's own output for it. `write_parquet` delegates to `write_parquet_with(ParquetOptions::default())`, so the plain `write_file` path compresses too - there is one writer, not two that can drift. The trait gained `write_file_with_options` (default body forwards to `write_file`, so only parquet/csv override) and `write_file_schema_aware` grew an options parameter. `AppSettings.write_options` holds the defaults; the shared expander widget is `ui::settings::render_write_options` (**library-side** so both the Settings dialog and the binary's batch-convert dialog can call it), and inside it one nested `CollapsingHeader` per format (Parquet / CSV-TSV / Excel, i18n `wo.parquet`/`wo.csv`/`wo.xlsx`) - every control belongs to exactly one format, so a flat list made a CSV save scroll past row-group sizes; the Excel pair had no heading at all before, only a separator. Save As to a `.csv` asks its own CSV questions (separator, decimal mark, BOM) in `dialogs/save_as_dialog.rs`, see `ui.md`; every other Save As uses the settings. `Cli::write_options()` loads `AppSettings` too (precedence flag > `settings.toml` > built-in), so CLI and GUI write the same files; MCP `convert` still passes `&Default::default()` (no settings plumbed into `ToolContext`). i18n `[wo]`.
- **Times and durations in files** (see `data-engines.md`): Parquet/Arrow IPC read `Time32/64` and `Duration` (and `Interval` without months) typed and write `Time64`/`Duration` in the column's unit; `ParquetOptions.duration_as_integer` (Settings > Saving files > Write options > Parquet) writes INT64 microseconds instead, and Save As to Parquet shows `wo.duration_note` when `parquet_reader::duration_note_applies`. DuckDB files: `TIME`/`INTERVAL` (a month interval keeps DuckDB's text and settles its column to text; `same_column_type` treats that text column as unchanged on save, and the diff save sets only changed cells so an untouched interval keeps its day split). Excel: time-formatted cells -> Time, `[h]:mm:ss` and `DurationIso` -> Duration, written back as Excel time values, negative durations as text. ODS native both ways. Avro `time-micros` and the `duration` logical type in, Duration out as text. TOML local times. NumPy `timedelta64` -> Duration (NaT null). SPSS DTIME and SAS time formats read as Duration and narrow to Time when every value lies within a day (`times::narrow_to_time`). SQLite: a column declared TIME. ORC, CSV and other text formats write the display text in the chosen duration style.
- **Large-file mode** (`src/formats/large.rs`): the one reader that returns a **handle** rather than a `DataTable`. `LargeTable::{columns, row_count, page(offset, len, order, filter), filtered_count}` over an in-memory DuckDB scanning the file in place (`ScanKind::{Parquet,Csv,Json}`); the sort column is addressed by name from `self.columns` and quoted, and `filter` is the only caller-supplied SQL, built by `large_file::search_filter` from typed inputs with quotes doubled. `convert_to_temp_parquet` is the fallback for formats DuckDB cannot scan (the one path that does hold a whole table in memory, which is why the notice warns about it). App side `src/app/large_file.rs`: `intercept_large_file` runs in `load_file` before the normal read; **it is the only way in** (there is no menu entry - a manual "Open in large-file mode" was removed) and it gates on `large_file_min_bytes` (2 GB) alone, compared with `large_size`: the file length, or for Parquet the larger of that and the footer's summed column-chunk `uncompressed_size` (`stated_data_bytes`). **Never a row count**: it used to also fire at a footer row count >= `initial_load_rows()`, on the false premise that a normal open stops there (it streams the rest on scroll), and so asked about a 35 MB Parquet saved from a 5 GB CSV under a 10 GB threshold (fixed 2026-10-16). `TabState.large` makes `is_readonly()` true. **Three things have to stay true together or the window is unusable**, and all three were once wrong: (1) `recompute_filter` fills `filtered_rows` with the rows of the **page** (not the file, and not nothing - clearing it painted column headers over an empty grid); (2) after a page step the viewport lands on the `PAGE_OVERLAP` seam, never on a scroll edge, because parking it at an edge re-arms the opposite edge trigger and the two steps then ping-pong a query per frame; (3) the filtered total is carried on `table.total_rows` and only re-counted when the filter changes, since the edge triggers are evaluated every frame. Navigation is the **virtual scrollbar**: `TableViewState::set_virtual_rows(Some((offset, file_rows)))` makes the hand-drawn bar stand for the file and emit `TableInteraction::jump_to_row` -> `large_jump_to_row`, which centres the window on that row (paging alone would be 50,000 pages over 100M rows). The wheel still steps a page via `interaction.needs_more_rows` / `scroll_y() <= 0`; the search box becomes a WHERE clause **after a 400 ms settle**. Pages are fetched on a worker (see "Large-file reads are all on workers" below). CLI `--sql --stream` registers `data` as a view via `SqlWorkspace::add_view_from_scan`, so an aggregate covers every row regardless of `--rows`; every other action warns on stderr. **MCP/chat stream per tool, never in `resolve`**: `ToolContext.large_file_min_bytes` + `ToolContext::scan_for(source)` (same gates as `resolve`, sandbox included) return a `LargeTable` only for a local scannable file over the threshold, and exactly four tools opt in - `count_rows`, `schema`, `read_table`, `run_sql` - each flagging `streamed: true`. Wiring `resolve` itself would have made `union_tables`/`join_tables`/`diff_tables`/`correlation`/`detect_outliers`/`data_drift` answer from a slice silently. i18n `[largefile]` + `SizeUnit` (renamed from `SyntaxSizeUnit`, gained `GB`).
- **Clean headers on load** (`clean_headers_on_load`, default off): `octa::data::trim::clean_headers(&mut DataTable) -> Vec<String>` snake_cases column titles (trim, lowercase, non-alphanumeric runs -> `_`, de-collide `name`/`name_2`, empty -> `column`). `run_load_passes` runs in `apply_loaded_table` after the whitespace-trim block (re-syncs `db_meta` baseline for DB tables); Settings checkbox next to `trim_whitespace_on_load`. i18n `settings.clean_headers`(+`_status`/hint).
- **Log files** (`src/formats/log/`, one file per format + `reader.rs`): Apache/nginx combined and common, syslog RFC 5424 and 3164 (year from the file's mtime), JSON lines, logfmt (whole line must be pairs, at least two), timestamped text (Java/Python). `detect` takes the format matching most of the first 500 entry lines, needing 60%; below that the `Log` reader falls back to `text_reader::read_text_file`, so a `.log` of notes opens as before. `Log (any format)` (Reopen as only) uses the best format anyway. Continuation lines (indent, `at `, `Caused by:`, `Traceback`, `...`) join the entry above; any other stray line keeps its own row in `raw`, counted by `unmatched_note` into the tab banner. `utc_offset` is its own column (no DateTime cell carries an offset). `filename_reader_name` routes `syslog`/`messages`/`access_log`/`error_log` and `*.log.*`. Text reader no longer claims `log`.
- **CSV decimal comma + BOM** (`CsvOptions.decimal_comma`, `.bom`, both default off): the delimited writer is three shared pieces, `delimited_writer` (BOM + csv builder over any `Write`), `write_delimited_header`, `write_delimited_rows` (Float cells get `,` via `cell_text`; text is never rewritten), reused by the streaming DB export and by `preview_delimited` (the Save As preview). **Round trip**: `TabState.csv_decimal_comma` is set by the number pass (`run_load_passes`) or the ambiguity picker when a column reads European, `csv_bom` by `file_io::starts_with_bom` at load; `TabState::delimited_options(settings_csv, choice, format_delimiter)` (in `file_io/save.rs`) is the ONE merge of Settings + tab + Save As choice, shared by the save and `view_sync::table_as_text` so the Raw view shows the bytes a save writes. The save decides delimited-vs-registry by the **target extension** (`delimited_target`), never the tab's `format_name`: keying on the format wrote `;` text into a Save As `.parquet`/`.tsv` (fixed 2026-10-07). Verified 2026-10-07 that before this `--convert de.csv out.csv` turned `A;1.234,56` into `A,1234.56`.
- **Streaming Parquet** (`parquet_reader::ParquetStreamWriter`): `create(path, columns, opts)` fixes the Arrow types from the columns, `write(batch)` appends (column-count checked, types forced to the file's), `finish()` writes the footer. `write_parquet_with` is a one-batch use of it, so there is still one writer.
- **CSV title lines**: `csv_reader::detect_delimiter_in` is the only delimiter sniffer (the app-side copy in `file_io/mod.rs` is gone). A candidate's most common count `C` must hold from its first line on, earlier lines may hold fewer (title block), two lines must agree; earliest run start wins (decimal commas start below the header). `build_table_from_reader` widens to the common record width when most of the first 50 records are wider than the header, then drops overflow columns empty in every row (trailing delimiters). `column_type_from_cells` (in `data/cell_value.rs`) is the CSV type rule. Background chunks start at `TabState.file_rows_read`, not `row_offset + row_count()`.
- **Lakehouse history / time travel**: `formats/lakehouse_history.rs` (pure, offline) lists versions from the table's own files: Delta = `_delta_log/<20 digits>.json`, `commitInfo` line only (`inCommitTimestamp` > `timestamp` > mtime; metric keys for delta-rs and Spark; `numOutputRows` counts as added only for WRITE/CREATE/REPLACE/STREAMING UPDATE), newest `LIST_LIMIT` (500) with `total`; Iceberg = the metadata file `version-hint.text` names (`v<hint>.metadata.json`, `<hint>.metadata.json`, `<hint>`, DuckDB's order), `previous` = `parent-snapshot-id`. `lakehouse_reader::{open_connection, read_version, diff_versions}`: scans with `version = n` / `snapshot_from_id = id`; Iceberg always passes `allow_moved_paths = true` (pyiceberg writes absolute paths); `diff_versions` = exact `EXCEPT ALL` counts both ways + capped rows under a `change` column, shared columns by name. "Cannot open file" errors get the VACUUM explanation. Gated tests: `OCTA_TEST_LAKEHOUSE=1 cargo test --test lakehouse_live_tests` (needs network once and `git lfs pull`).
- **Large-file column filters** (2026-10-17): `large_file::view_filter(tab, search)` ANDs `search_filter` with one `LargeTable::values_filter(col, values)` per `column_filters` entry (columns in index order, values sorted, so the text is stable for the per-frame `want == applied` check). `values_filter` compares in the column's DuckDB type (`cell_kind` from the DESCRIBE type kept in `LargeTable.duck_types`; floats via `CAST AS DOUBLE` with a re-render guard, so `2` never matches a `2.0` cell; zoned timestamps via `timezone(zone, col)`; decimals as text), mirroring `duckdb_value_to_cell_tz` + `CellValue::to_string`; lists/structs/blobs return `None` and the status bar names them. Pinned per type by `tests/large_file_tests.rs::a_value_filter_keeps_the_rows_an_ordinary_tab_keeps`. Value lists: `facet_external`/`facet_from_file` and the Column Filter window's `on_server` are true for large tabs; `want_values` runs `LargeTable::value_frequency_job` (own connection, empty text counts as missing like `compute_value_frequency`) on `spawn_local_fallible`. Wording keys `largefile.facet_*`/`window_more`.
- **Large-file reads are all on workers** (2026-10-17): `finish_large_open` spawns `large::open` + the first page (`OctaApp.large_open_job`, polled by `poll_large_open`, status `largefile.converting`); every page goes through `request_large_page` -> `LargeTable::page_job` (a `try_clone`d connection, counts only when the filter changed) on `spawn_local_fallible`, held in `TabState.large_fetch`. One fetch per tab: a request made meanwhile waits in `LargeFetch.next` (newest wins), `large_page_step` does nothing while one runs (otherwise a step from the old page replaces the fetch that is moving it, every frame), and `Landing::{Forward,Backward,Row}` says where the viewport parks. Ask chips: `LargeTable::predicate_filter` spells each column as Octa displays it (`display_sql`: chrono `%.f` fractions, Float `{:.1}` rule, zoned wall clock), then `rule_matches`' number-or-text branches; pinned by `a_comparison_filter_keeps_the_rows_an_ordinary_tab_keeps` (every op, both cases, every type).
