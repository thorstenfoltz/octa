# SQL workspace and SQL view

## Module layout

- `src/sql/mod.rs`: re-exports `SqlWorkspace`, `AttachKind`, `WriteTarget`, `WriteMode`, `WriteReport`, `QueryKind`, `QueryOutcome`, `sanitize_sql_name`. `run_query(table, query)` is a one-shot wrapper (fresh workspace, registers `data`, tears down).
- `src/sql/workspace/` (`mod.rs` the workspace itself, `session.rs` the statements both connections run (`Session<'_>(&Connection)`, paged results, `run_job` + `DataFeed`/`JobQuery`/`RunDone`), `attach.rs` attaching files and live connections, `write.rs` Write result to DB, `workspace_tests.rs`): `SqlWorkspace` owns one persistent DuckDB conn + a `runner` second connection + `tables` + `attachments`. API: `new`, `set_active_table` (the `data` table, main catalog), `add_table_from_{file,datatable}`, `attach`, `detach`, `remove_table`, `rename_table` (ALTER TABLE + registry key; double-click a workspace row's name), `list_attached_tables`, `execute`, `write_result_to_db`. DuckDB ATTACH native for `.duckdb`/`.ddb`; SQLite tries `INSTALL/LOAD sqlite` then falls back to per-table `SqliteReader` (`alias__table`); SQLite writes always via `rusqlite`. `execute` columns all `Utf8`. Sync; MCP wraps with `spawn_blocking`.

## SQL view

Active table exposed as DuckDB table `data` (main catalog, so the runner connection sees it). **Except on a large-file tab** (2026-10-16): `sql_panel::register_active_data` calls `SqlWorkspace::set_active_scan`, which registers `data` as a VIEW over the file (registry entry with the file's row count, so `inspect_registered_table` never COUNTs it). A large tab registers its view synchronously through `sql_panel::register_active_data` (from `start_sql_job` and Explain); an ordinary tab's copy is a `SqlJob` (see Running state); Explain on stale `data` starts that copy job with `SqlJob.then_explain` and plans when it lands (`land_sql_job`), so nothing copies synchronously any more; `register_or_replace` drops via `drop_relation`, which handles table or view (DuckDB refuses DROP TABLE on a view). Before this the panel copied the 2,000-row page. Each tab owns a long-lived `SqlWorkspace` (`TabState.sql_workspace: Option<SqlWorkspace>`), dropped on close. Workspace section lists tables + ATTACHed DBs with per-row [x]/[detach], [+ Add table...], [Attach database...]; [refresh] copies `data` again on request. **`data` is copied only when the table changed** (2026-10-17): `register_active_data` reads cells through `DataTable::get` (edits included, no clone) and skips the copy while `TabState.sql_data_stamp` (`DataStamp`: rows address, shape, `row_offset`, columns with types, undo/redo/edit counts; the trim banner's Dismiss, which changes only cells, drops it itself) still matches; `forget_stale_data` runs for every tab every frame (an undo followed by a new edit ends on the same counts), and Run drops the stamp after any `is_mutation` statement (a refused fold-back leaves `data` different from the tab). A Run used to clone the table and copy it into DuckDB every time: ~1.3 s per 1M rows of complaints.csv for the copy alone. The other-tabs auto-registration (`sync_open_tabs_into_workspace`) is a job too: `TabState.sql_other_tabs: OtherTabsCopy` holds one `SliceFeed` + `RowsStamp` per other tab, `drive_other_tab_copies` feeds them per frame (a tab that changed or moved stops its feed and is left out), and `SqlWorkspace::copy_tables_job` writes each through `Session::copy_into` (the generalised `copy_data`: build `__octa_next_<name>`, swap in) on the runner; landing calls `note_table`. Status `sql.copying_tabs`. **+ Add table...** and the cloud picker's Add to workspace go through `start_workspace_files` (`sql_panel/workspace.rs`): a `spawn_local_fallible` worker reads each file and registers it through `ImportSink` (`SqlAttached::Files`, landed by `drive_sql_imports`), status `sql.adding_files`, Cancel = a stop flag between files that rolls back. **Attach database...** (a file) is `SqlWorkspace::file_attach_job` on the runner (`SqlAttached::File`, `note_file_attach`): DuckDB ATTACH, or SQLite via the extension (its load state rides back in `FileAttached.sqlite_extension`), else the per-table `alias__table` copy through `ImportSink` with a stop flag; sync `attach` (CLI/MCP/tests) runs the same job. Header also carries the plain-language **Ask** box (see Key Design Patterns; `SqlAction.ask`, greyed with a reason when no chat profile or no columns). Result actions [Run]/[Clear]/[Export...]/[Write result to DB...] (last -> `SqlWriteBackDialog` -> `SqlWorkspace::write_result_to_db`; writing into the open file's own `db_meta.table_name` with Append/Replace is rejected).

Docks Bottom/Top/Left/Right via Settings; editor has a monospace line-number gutter sharing one `ScrollArea`. Template `SELECT * FROM data LIMIT {sql_default_row_limit}` via hint_text. Autocomplete chips at word-token end; while the popup is open (`popup_active`) Up/Down move the selection, Enter or Tab accepts, Esc dismisses - keys are only consumed while it is open, so plain typing keeps Enter/arrows. The editor grabs focus on open via `SqlPane.focus_pending`. Workspace state is session-only. **The workspace opens on an EMPTY tab too** (no col_count gate; `set_active_table` skipped for zero-column snapshots so `data` just is not registered - attach + query servers with no file open). The inspector row splits in two when attachments exist: `render_attachment_info` is an attachments cheat-sheet (alias + kind + source + one-click example insert; i18n `sql.att_info*`).

Results render a row-counter label directly above the grid (display-only, never in the data/export). Result collection (local `sql/engine.rs::execute_query` AND server connectors) stops at `initial_load_rows()`; `result_rows_label` switches the counter to `sql.result_rows_capped` when row_count sits on the cap (translated x32; hermetic test `tests/sql_result_cap_tests.rs`, own binary since the guard is process-wide). `render_sql_view` zeroes `widgets.{hovered,active}.expansion` for the whole panel - themes paint hovered widgets up to 3px larger, which reads as twitching in the dense grid.

**Attached-table listings are cached** (`SqlWorkspace.attached_tables_cache`, RefCell): the panel rebuilds its workspace snapshot per frame, and for Postgres/MySQL attachments an uncached `list_attached_tables` is a remote information_schema query - two attached servers made the editor unusable. Cache dropped on `detach` + `invalidate_attached_cache()`; remote attachments also skip the per-table `COUNT(*)` entirely (`row_count: None` - on InnoDB that is a table scan).

**History** dropdown: per-tab session `TabState.sql_history` (recorded by `record_sql_history` in `land_sql_query`, cap 30); `SqlAction.recall_query` loads one back: `view_modes::sql::append_to_editor` (below the text after a blank line, the added query MARKED so Run, which runs the marked text first, runs just it; also used by the inspector's Insert SELECT) unless `AppSettings.sql_pick_replaces_editor` (Settings > SQL > Query history, default off) says replace. History and the Snippets window both go through `OctaApp::put_picked_query`, the one place that reads the setting. **Snippets** button opens `src/app/dialogs/sql_snippets_window.rs` (standard DialogSize chrome, app-level `OctaApp.sql_snippets_window_open`/`_size`) with save-current/Insert/delete; persistent `OctaApp.sql_snippets: Vec<SqlSnippet>` (`src/app/sql_snippets.rs`, `<config_dir>/sql_snippets.json`, name+description+query); naming dialog `src/app/dialogs/sql_snippet.rs`; `SqlAction.{insert_snippet,save_snippet,delete_snippet}`. i18n `sql.{history,snippets,snippet_*}`, `dialog.snip_*`.

**CREATE hands the table over** (`SqlWorkspace::execute`): a statement whose first keyword is `CREATE` gets the workspace's own catalog (`information_schema.tables`, catalog `current_database()` + `temp`) diffed before/after; exactly one new relation -> read via `read_typed` (SELECT * + DESCRIBE so declared types survive, `execute_query` alone labels every column Utf8), `DROP TABLE|VIEW` it, return `QueryOutcome { kind: Mutation, created: Some(name), table }`. GUI (`land_sql_query`) opens `table` as a new tab labelled `name`, no fold-back, no read-only refusal. `run_query` skips the schema re-stamp when `created` is set. CLI prints `created <name>`, MCP adds `"created"`. Attachments are read-only so a CREATE into one errors before the diff. Tests: `workspace_tests::create_*`.

**Row-diff highlight after mutation** (`sql_row_diff_highlight_enabled` default on + `sql_row_diff_highlight_secs` default 4): `apply_sql_diff_highlight` diffs pre/post via `compare::compare_ordered`, marks changed cells (Cell) + new rows (Row) green on the mutated table, stores keys in `TabState.sql_diff_marks` + expiry `sql_diff_highlight_until`; `OctaApp::expire_sql_diff_highlights` (per frame in `update_loop`) clears them when the timer elapses. i18n `settings.sql_diff_{highlight,secs}`.

**Format SQL** (0.20.1): `src/sql/format.rs::format_sql(sql, &SqlFormatOptions, FormatDialect)` wraps the `sqlformat` crate (keyword case, indent, JOIN level, list width `inline_width` -> `max_inline_arguments`, clause width `clause_width: Option` -> `max_inline_top_level` (None follows the list width; **applied only while `inline_width > 0`**, because top-level alone makes sqlformat print a clause's items unindented at column 0), bracket width -> `max_inline_block` (default 50 = sqlformat's own), `one_line` -> `inline` (leading commas skipped then), blank lines) and adds `final_semicolon` (`add_final_semicolon`: own line after a trailing `--` comment) and adds leading commas itself (`move_commas_to_line_start`: moves only a line-final comma, skips lines holding `--`). `AppSettings.sql_format` (Settings > SQL, with a live preview of `SQL_FORMAT_SAMPLE`). Toolbar **Format** (`SqlAction.format`) and `ShortcutAction::FormatSql` (unbound) both call `OctaApp::format_sql_editor`, which picks the dialect from the Run-on target (local DuckDB and Postgres/Redshift -> Postgres, MSSQL -> SqlServer, rest Generic) and `view_modes::sql::format_in_editor` formats the marked part or the whole buffer.

## Editor panes, keep-open, maximise, running state (0.20.1)

- **Escape in the autocomplete list** (2026-10-13): closes the list and KEEPS focus, so the next Enter is a line break. Consuming the key is not enough: egui's `Focus::begin_pass` drops focus on Escape at the start of the frame unless the focused widget's `EventFilter.escape` (set by the TextEdit the frame before) claims it, so `draw_sql_editor` takes `popup_open` and builds its own filter (`tab: true` replaces `lock_focus(true)`). Pinned by `escape_closes_suggestions_and_keeps_the_editor`.
- **Suggestions belong to typing** (2026-10-15): `SqlPane.ac_visible` is set by a text change and cleared by ANY other caret move (`draw_sql_editor` compares the TextEdit's `CCursorRange` with `SqlPane.ac_caret`, the last frame's), and no suggestions are computed while text is marked. Before, the flag stayed on from the first keystroke until Escape, so marking a column name left to right (caret after it) opened the list and the next Enter/Tab became a pick. A delay setting was considered and rejected: it postpones the popup until the selection stops, then shows it anyway. Pinned by `suggestions_show_while_typing_and_never_for_marked_text`.
- **N editors per tab** (`src/app/state/sql_pane.rs`): `SqlPane` holds one editor's query, result, selection, error, paging total, timings, autocomplete state and `running_since`. The **active pane lives in `TabState.sql`**; `TabState.sql_panes` holds every pane in order with a hollow placeholder at `sql_active_pane`. Everything that means "the editor" (Run, Format, shortcuts, write-back, Ask, Export) reads `tab.sql` unchanged, and the borrow checker sees it as disjoint from the rest of the tab. `render_sql_view` draws pane `i` via `each_pane` (`ui.columns`), swapping it in with `activate_sql_pane(i)` and back; the focused editor becomes active at frame start, a click in a column at frame end. Pane ids are process-global (0 = placeholder): they key the editor egui id (`editor_id(pane)`), and `SqlServerJob.pane_id` routes a server result to its pane even after tabs were reordered or panes closed.
- **Paged results are per pane**: `execute_paged/result_page/result_all(.., slot)` materialise into `__octa_result_{slot}` (slot = pane id); `drop_result` on pane close. One shared table let pane 2's run replace pane 1's Load more / Export rows (`paged_results_in_different_slots_stay_apart`).
- **Running state**: `SqlPane::start_run` clears result/error and sets `running_since`; the result area shows a spinner + elapsed time + Cancel (server or local). **Local queries and the copy of `data` run on a worker** (2026-10-17, `sql_panel/job.rs`): `SqlWorkspace.runner` is a second connection (`try_clone`, kept so SETs persist) held by the worker through `SqlWorkspace::run_job(Option<DataFeed>, Option<JobQuery>) -> RunDone`; the queries live in `Session<'_>(&Connection)` so both connections share them. **`data`, registered tables and `__octa_result_*` are main-catalog tables now, not TEMP** (TEMP is per connection). The copy is fed a slice per frame by `SliceFeed`, built as `__octa_data_next` and swapped in by DROP + RENAME in one transaction (a dropped feed leaves the old `data`). `TabState.sql_job` (`SqlJob`: pane id, query, readonly-at-start, feed + `RowsStamp` + `DataStamp`, task, interrupt); `start_sql_job(tab, query)` (copy when `data_is_stale`, large tabs register their view synchronously), `drive_sql_jobs` per frame feeds (stops on a changed `RowsStamp`) and lands via `land_sql_query` into the pane by id (`activate_sql_pane` swap and back). `SqlJob::holds_rows` (copy, or `is_mutation`) feeds `TabState::holds_rows`, so a SELECT leaves the tab editable. The panel open starts a copy job only when the workspace is new; `ensure_workspace` no longer copies; `register_active_data` stays synchronous only for Explain (refused with `sql.busy` while a job runs) and large tabs. Drop interrupts only an unfinished job (an interrupt on an idle connection could hit its next query). `pending_run`/`run_pending_sql` are gone.
- **Keep-open** (`AppSettings.sql_keep_open`, default on): `close_tab` of the active tab with the panel open opens it on the next active tab and `adopt_sql_editors` moves the editors that hold text or a file over (each with its file) when that tab's editors are all blank; the file-load path keeps an open panel open and its query text. Off = old per-tab behaviour.
- **Maximise**: `TabState.sql_maximised`; `open_sql_panel` (menu, Ctrl+J via `toggle_sql_panel`, Ctrl+T, keep-open) sets it on a blank tab. A maximised panel is NOT a docked panel: `render_sql_panel` returns early and `render_central_panel` calls `draw_sql_panel(ui, true)` in its place, so chat/side panels rendered later keep their space. File load and closing the panel clear it.
- **`ShortcutAction::AddSqlEditor`** = Ctrl+T (not Ctrl+Alt+letter: AltGr on de/pl layouts types a character), dispatched outside the TextEdit guard so it works while typing.
- **Settings > SQL** is six `sub_section_open(.., false)` groups (Panel, Editor, Results, Other open tabs, Query history, Format SQL); closed on purpose, unlike other sections' groups. Format widths are text fields (`SettingsDialog.sql_fmt_bufs`) parsed on `.changed()` because the preview is live; never `DragValue`. `the_settings_explanations_tell_the_truth` pins the examples the `*_explain` texts quote.
- **Explain** (`src/sql/explain/`, `src/app/sql_panel/explain.rs`): `mod.rs` holds the shared plan tree and dispatch; one parser per engine (`duckdb`, `postgres`, `mysql`, `databricks`, `bigquery`) with fixtures under `fixtures/`. Databricks = Spark's `EXPLAIN` text tree (3 chars per level, `#id` expression ids stripped, `*(n) ` codegen marks and the `Photon` prefix ignored for the kind, no row estimates); Spark returns a planning error AS the plan text, so `parse` turns an `...Exception:` first line into an error. Fixtures `spark_*.txt` are real Apache Spark 3.5.3 output (`apache/spark:3.5.3` spark-sql); Photon was checked live on 2026-10-15 against the user's DBSQL warehouse (`Databricks Imec`, `samples.nyctaxi`/`samples.tpch`): plans look like Spark's with `Photon*` operators, the WHERE folded into `PhotonScan`'s `DataFilters`, an `== Initial Plan ==` in-tree header, and `== Photon Explanation ==` / `== Optimizer Statistics ==` sections after the plan. Nothing runs: never `EXPLAIN ANALYZE`. MySQL 8.0.16+ uses `EXPLAIN FORMAT=TREE`; MariaDB, older servers or an empty TREE fall back to the JSON form. BigQuery has no plan, so it reports the bytes a dry run would read (`DbConnector::dry_run_bytes`), never a price. Other engines get the button disabled with a tooltip. Result lives in `SqlPane.plan`, the chosen view (In plain words default = `plain_text`: numbered in execution order (post-order), `Other` steps left out unless the plan has nothing else, multi-input steps name their input step numbers via `explain.uses_steps`, and each step prints its `PlanStep.fact` (2026-10-15: on Databricks two queries over one table read identically, because Photon folds the WHERE into the scan and plain words had no details, so a new Explain looked stale): the condition a read/filter keeps rows by (`explain.keeps_where`), a limit's count (`explain.first_rows`), a group/sort's keys (`explain.by`), set by each parser from its own fields; `condition()` flattens top-level ANDs, drops wrapping parens, drops a not-null test whose column another part names (whole-word match) and DuckDB's `optional:` runtime filters; a Spark read under Spark's own Filter step gets no fact (the Filter has it); Postgres and DuckDB limits print no count, DuckDB group keys are `#0` slots, so none. Photon fixtures `photon_*.txt` are real DBSQL warehouse output, storage path redacted; Table; Server's own) in `SqlPane.plan_view` (enum variant still `PlanView::Tree`), remembered per editor. The CLI `--explain` default and the MCP `plain` field print the same `plain_text` (user's call 2026-10-14; the indented `tree_text` and MCP `tree` field are gone). Headless: CLI `--explain` with `--sql` / `--db-query`, MCP `explain: true` on `run_sql` / `query_db`. **`single_statement` refuses ANY semicolon before the end, strings and comments included, and must stay that blunt** (2026-10-13 review): Explain skips every write gate, mysql_async turns on `CLIENT_MULTI_STATEMENTS` and `MySqlConnector::query` drains every result set, and MySQL lexes `--1` (minus minus one), `#` (comment) and `\'` (escaped quote) unlike a standard scanner. The earlier `skip_atom`-based splitter let `SELECT 1 --1; DROP TABLE t` through. Known, pre-existing and NOT fixed: `is_mutation` reads only the first keyword, so on MySQL `SELECT 1; DELETE ...` passes the write gate of Run / `--db-query` / `query_db`.
- **Find box** (2026-10-22, `src/view_modes/sql/find.rs` over the shared `view_modes::find_box`, see `ui.md` Find & Replace): `SqlPane.find: Option<SqlFind { input: FindInput, current, jump }>`, drawn by `draw_find_box` AFTER `draw_sql_editor` inside `each_pane`, floating over that editor's top right, so every pane has its own. `handle_shortcuts` routes `FocusSearch` (Ctrl+F) / `ToggleFindReplace` (Ctrl+H) to `find::open` when `find::owns_keyboard(ctx, tab.sql.id)` (editor, find field or replace field focused); the pane activation at the top of `render_sql_view` uses the same check. The editor's layouter re-finds the matches in the text it lays out (`find::highlight`, never stale byte ranges). `show_current` scrolls to the match and puts the editor's **caret** after it, not a selection: egui 0.36 collapses an unfocused TextEdit's selection to its primary cursor every frame. Escape or `x` closes and sets `focus_pending`. Before the box, a one-row strip above the editor squeezed its find field under its own buttons. Pinned by `sql_tests::the_find_strip_steps_through_matches_and_hands_back_the_editor`, `the_find_box_floats_over_the_top_right_of_the_editor`, `enter_in_the_replace_field_replaces_match_after_match` + `find_tests.rs`.
- **Editor files** (2026-10-15): `SqlPane.file: Option<SqlFile { path, saved, crlf }>`; unsaved = `saved != query` (a comparison, so Format/Ask/History/Insert need no flag). `read_sql_file`/`write_sql_file` (`state/sql_pane.rs`) drop a BOM, fold CRLF to LF and write CRLF back when the file had it; `write_sql_file` goes through `formats::write_atomically`. `file_display_name` (same file) is the shared name helper. `sql_panel/file.rs`: `open_sql_file` (refuses files over `settings.raw_view_allows`, message `sql.file_too_large`; blank active editor takes it via `TabState::put_sql_file`, else a new pane), `save_sql_file` (no file -> Save as), `save_sql_file_as` (both call `file_io::save::keep_earlier_version`, the helper `keep_version` shares, so Keep earlier versions applies). Toolbar **File** menu (`SqlAction.{open_file,save_file,save_file_as}`; labels reuse `common.open`/`common.save`/`common.save_as`; keys `sql.{file_menu,file_menu_hint,open_file_hint,save_file_hint,save_file_as_hint,file_saved,file_unsaved_hint,file_too_large}`), header label `pane_label` (`Editor N: name.sql *`). `SA::SaveFile` saves the SQL file when `sql_editor_id(tab.sql.id)` has focus; `OpenSqlFile`/`SaveSqlFileAs` unbound. Keep-open carries files (`sql_editors`/`adopt_sql_editors`). No unsaved prompt on close (user's call), no session restore.
