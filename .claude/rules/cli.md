# CLI

`octa` is **flag-driven**, not subcommand-driven: pick one of `--schema`, `--head`, `--tail`, `--sample`, `--convert`, `--sql`, `--export-schema` (`-e`), `--compare-schemas`, `--diff`, `--describe`, `--validate-schema`, `--unique-columns`, `--anonymize`, `--dedupe`, `--impute`, `--outliers`, `--detect-pii`, `--union`, `--join`, `--partition-by`, `--resample`, `--rolling`, `--batch-convert`, `--drift-report`, `--merge`, `--recipe`, `--check`, `--relationships`, `--mcp` (mutually exclusive via clap `group = "action"`); with none, launches the GUI with the positional file list. Implemented in `src/cli/`, one file per action. Global `-f / --format {tsv|json|csv}` (default tsv) routes through `src/cli/output.rs`; `--convert` (whose OUT may be `-` for stdout, requiring `--to EXT` since a pipe has no name; the data goes to stdout and the counts to stderr), `--export-schema` and `--partition-by` ignore it (the last prints a bare `path\trows` listing of the files it wrote, headerless, straight from `println!` - deliberately not a data table). `--export-schema` picks a target via `-t / --target` (`SchemaTargetArg` → `octa::data::schema_export::SchemaTarget`). `disable_help_flag = true` + a custom `--help` (`ArgAction::HelpLong`) makes `-h`/`--help` identical.

`--validate-schema` returns exit `1` on a successful read where schemas drift (CI gating); `cli::dispatch` pulls it out of the normal `Result → ExitCode` mapping so `validate_schema::run` returns `Result<ExitCode, _>`. `--mcp` does **not** route through `cli::dispatch`: `main.rs::run_mcp` peels it off first so GUI/CLI paths never build a tokio runtime.

`--diff` takes a `--diff-mode {set|ordered|join}` (default `set`) + `--diff-on COLS` (comma list, required for `join`). `set` is the original whole-row membership diff (`octa::data::diff::diff_rows`); `ordered`/`join` route through `octa::data::compare` (`compare_ordered` positional row-by-row cell diff; `compare_join` key-matched added/removed/changed). `compare::build_compare_table` renders the shared output table (leading `status` + `changed_columns`). `compare::subset` is reused by the MCP tool.

`--describe` grew `--deep` (physical layout, see File internals below); `--diff` grew `--diff-db CONN --diff-db-table SCHEMA.TABLE`, which replaces the second positional file with a live table (`--diff` is `num_args = 1..=2` for that reason, `detect_action` enforces which count each form needs); `--convert` and `--batch-convert` grew `--password-env VAR` (writes only `<out>.zip`, AES-256; the passphrase comes from the environment variable via `convert::passphrase_from_env`, never argv, and errors name the variable, never the value; `-` and a `.zip` output are rejected) and `--compression CODEC` (validated at parse time against `write_options::PARQUET_CODECS`) and `--row-group-size N`.

Man page source `docs/cli/octa.1.adoc`; mkdocs mirrors it by hand at `docs/cli/man-page.md` (same sections, same text, plus links to each action's page). The page is **grouped by task** (Look at a file, Analyse, Compare and check, Clean and transform, Combine and split, Convert and SQL, Databases, Cloud and web, Connections, MCP server): each action's entry is its usage line, what it does, then the options that belong to it alone as a nested list (`;;` in the adoc, an indented `:` list in the md). An option several actions share goes under COMMON OPTIONS; an action that exits 1 on a finding gets a row under EXIT STATUS. The rendered `pkg/linux/octa.1` is committed (install.sh installs it from a checkout; release CI, the AUR and `pkg/build-local.sh` render their own) and must be re-rendered after every adoc edit: `asciidoctor -b manpage docs/cli/octa.1.adoc -o pkg/linux/octa.1`. `src/cli/args_tests.rs::the_man_page_documents_every_flag` fails when any non-hidden `--flag` of `Cli` is missing from the adoc, the md or the rendered page (whole-flag match, roff's `\-` escaped hyphens): 55 flags had gone missing from the rendered page before it existed. It catches missing flags, not stale prose. `[[...]]` in the adoc is an anchor and vanishes; write `` `+[[rule]]+` ``.

A positional FILE may be **`-` for stdin** (buffered to a temp file since every reader needs `Seek`, then `sniff_format`; empty stdin is an error), a cloud object URL (see Cloud URL as a path below) or a plain `http(s)://` URL (`cloud::fetch::{is_http_url,fetch_http_to_temp}`, no credentials, extension taken from the URL path ignoring the query string, non-2xx is an error naming the status so a 404 HTML page is never parsed as a table); both read-only from the CLI, and both are branched in `cli::read_table` and `ToolContext::resolve`. **`fetch_http_to_temp` takes a `UrlTrust`**: `UserSupplied` (CLI/GUI, unrestricted - reading `localhost:8000` is normal) vs `AgentSupplied` (MCP/chat), which resolves the host and refuses non-global addresses (loopback/private/link-local incl. 169.254.169.254/unique-local v6) and disables redirects, because the HTTP branch sits *before* the chat sandbox's `ensure_readable` and would otherwise be a way out of a `restrict_filesystem` profile. Ceiling: resolve-then-connect, so DNS rebinding is not covered.

Global `--rows N|all` overrides the streaming initial-load cap for one run (`cli::parse_rows_flag`; `all` → `usize::MAX`); `cli::dispatch` installs an `octa::formats::InitialLoadRowsGuard`. Global `--max-decompressed MB|unlimited` (`cli::parse_max_decompressed_flag`, 1 MB = 1,000,000 bytes like Settings) sets `formats::compression::set_max_decompressed` in `main.rs` before dispatch: the flag, else `AppSettings::load().max_decompressed()`, else 4 GB; with `--mcp` it is handed to `run_mcp` and fixed for the server's life. Not an action modifier, so not in `stray_modifier`. Every CLI read goes through `cli::read_table` (stdin, URLs, cloud) or `cli::read_one(path, table)` (a named table of a multi-table file), both on `max_decompressed()`; an action file never calls `read_table_auto` itself.

`--sql` workspace flags: `--sql-table NAME=PATH` (repeatable) adds workspace tables; `--sql-attach ALIAS=PATH` ATTACHes a DuckDB/SQLite file (`alias.schema.tbl`); `--sql-write-to PATH` + `--sql-write-table TABLE` (+ optional `--sql-write-schema`, `--sql-write-mode {create|append|replace}`) persists the SELECT instead of printing. `src/cli/sql.rs` builds + tears down a fresh `SqlWorkspace` per invocation.

Data-ops actions (engines in `src/data/<name>.rs`, all also GUI dialogs + MCP tools): `--dedupe` (+`--dedupe-on/-keep`), `--impute COL=STRATEGY` (mean/median/mode/ffill/bfill/`const:VALUE`), `--outliers` (+`--outlier-method/-cols/-k`, prints flagged cell coords), `--detect-pii` (+`--pii-sample`), `--union` (+`--union-file/-drop/-cast`), `--join` (+`--join-file/-on/-type`), `--partition-by COL` (+`--out-dir` required, `--partition-format`, `--partition-layout {flat|folder|hive|hive-parts}` where hive writes `<col>=<value>/data.<ext>` that dataset mode reads back with the partition column restored, writes N files). `--split-rows`/`--split-size` select the partition action alone (or combine with `--partition-by`); `dispatch` lifts the load cap for it unless `--rows` is given. `tests/dedupe_cli_tests.rs` covers `--dedupe`.

Adding an action: append a flag to `cli::Cli`, add an `Action` variant, drop `src/cli/<verb>.rs`, extend `Cli::detect_action`, add a `cli::dispatch` arm.

Batch 2026-09-25 actions: `--shapes FILE --shapes-column COL`, `--lookups FILE [--lookups-min 0.95]`, `--cell-history FILE --history-column COL (--history-key K --history-value V | --history-row N) [--history-depth 50]`, `--spatial-join FILE --spatial-layer FILE... [--spatial-op inside|nearest] [--within-km N]` (`detect` refuses `--within-km` without `nearest`), `--forecast FILE --forecast-x COL --forecast-y COL [--forecast-periods 12] [--forecast-season N]`. Each has a page under `docs/cli/`, a man-page entry in both `octa.1.adoc` and `man-page.md`, and a smoke test. The cell-history smoke test's Git repo lives in `tests/common/git_repo.rs`, included by `#[path]` so the suite does not pull in all of `tests/common` (dead-code warnings).

`--compare-folders A B [C ...]` (`src/cli/compare_folders.rs`, engine `octa::data::folder_compare`): the positional FOLDERs (local path or cloud URL, each through `scan::source_for`) are the input, so `Action::CompareFolders` is in `main.rs`'s positional allowlist. `--no-recursive` is checked in `detect_action` like every other one-action modifier (see below). Exits 1 on any difference, missing copy or truncated listing (dispatch early-return block); listing names and the hashing count go to stderr.

**A modifier that belongs to one action is checked in `detect_action`, never with clap `requires = "<action>"`** (2026-10-14): clap waives a `requires` whose target conflicts with a flag that is present, and every action flag conflicts with every other through the `action` group, so `--head F --rules R` ran `--head` and dropped `--rules` without a word (12 flags had that hole). `Cli::stray_modifier` is the one table (`--rules`, `--mcp-read-only/-tools/-without`, `--deep`, `--fail-on`, `--report-sample/-sections`, `--sync-table/-on`, `--api-path`, `--db-export-tables`, `--partition-layout`, `--no-recursive`), checked before `pick_action`; `--split-rows`/`--split-size` select Split themselves, so `detect_action` refuses them when the picked action is not `Partition`. A new modifier of an action flag goes into that table. `requires` stays only where the target is NOT an action flag (`--db`, `--diff-db`). Pinned by `src/cli/detect_tests.rs`.
