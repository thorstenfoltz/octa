# i18n

Hand-rolled `src/i18n.rs` (spans the lib/bin split): `t(key)` + `set_language(code)`, TOML catalogs embedded from `locales/*.toml` (**32 files total**: English master + 31 langs: de/es/fr/it/nl/pt/pl/sv/da/no/fi/tr/id/vi/ro/hu/cs + el/ru/ja/ko/zh + uk/bg/sr/hr/sl/sk + lt/lv/et). Roboto-Medium/Bold cover Latin+Greek+Cyrillic; the bundled NotoSansCJK-subset covers CJK/kana/hangul (so el/ru/ja/ko/zh all render). `apply_fonts` also appends Roboto to the Monospace fallback so Greek/Cyrillic render in the SQL editor. `set_language` runs at `OctaApp::new` and on Settings apply (live). `every_language_covers_every_english_key` enforces key parity; `t()` falls back to English for any missing key. String migration is **incremental** — add a key to *every* locale then call `t()`. Arabic/Hebrew deferred (need RTL layout work).

`every_language_covers_every_english_key` checks only that a key *exists*, which left two traps that both hit in practice: a whole section could ship untranslated and stay green (the entire `[union_tree]` block did, in all 31 locales), and nothing enforced a locale's script (`sr.toml` is **Cyrillic** but once held 168 Latin strings, many ASCII-stripped past mechanical repair - a bare `c` is c, ch or ch depending on the word). Both now have their own test:

- **`non_latin_locales_are_written_in_their_own_script`** - a value in ru/uk/bg/sr/el/ja/ko/zh containing a Latin *word* (3+ letters) and no character of its own script fails, unless its letters match the English value, which is how product names (`JSON`, `Parquet`, `AWS IAM (RDS)`) stay Latin without an allowlist. It found and fixed **426 transliterated values** across seven locales on 2026-08-18.
- **`locales_do_not_carry_untranslated_english_sentences`** - a value identical to English with 3+ words fails. Single words are ignored (format and engine names are identical everywhere by design); `UNTRANSLATABLE_PHRASES` exempts the four real multi-word product terms.

Writing a locale in ASCII is a corruption, not a safety measure: the "ASCII only" rule for UI strings covers typographic punctuation (em-dashes, ellipsis characters, arrows) that egui's bundled font cannot draw, never alphabets. Roboto covers Latin/Greek/Cyrillic and the bundled NotoSansCJK subset covers CJK.
