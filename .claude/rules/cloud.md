# Cloud object storage

- **Union cloud objects**: same feature over the cloud sidebar. Ctrl-click toggles `CloudBrowserState.selected: HashSet<CloudSelection{conn_id,key,name}>` (`CloudTreeAction.toggle_select`; plain click still opens), the cloud header grows the same "N selected / Union..." bar -> `OctaApp::union_cloud_selection` downloads every selection on **one worker thread** (network + possible AWS-CLI shell-out must stay off the UI thread) via the shared `cloud_browser::fetch_object_to_temp`, then pushes `CloudOpenResult::UnionReady { paths, skipped }`, which `drain_cloud_pending_open` hands to the *same* `open_union_for_files`. Connections are resolved on the main thread first (`find_cloud_conn` borrows `self`).
- **Add a cloud connection from the sidebar**: `CloudTreeAction.add_connection` (a "+ Add" button in the cloud tree **header**, so it survives the `connections.is_empty()` early return, which is exactly when it is needed) -> `sidebar.rs` opens the Settings dialog and sets `SettingsDialog.focus_cloud_section` (mirrors `focus_chat_section`; the Cloud `CollapsingHeader` does `.default_open(std::mem::take(&mut self.focus_cloud_section))`). `SettingsDialog::open` already calls `clear_cloud_form`, so the form comes up blank.
- **Cloud inventory**: cloud-tree context "List contents as table..." (`CloudTreeAction.inventory`) -> worker `OctaApp::cloud_inventory` -> `CloudProvider::list_recursive(prefix, cap)` (INVENTORY_CAP=100_000; `ObjectEntry` grew `etag`/`version`) -> `octa::data::inventory::build_inventory_table` (path,name,extension,size,modified,etag,version) -> detached tab + truncation banner. Account-level root refused (`inventory.account_root`). MCP `list_objects` mirrors via `recursive: true`. i18n `[inventory]`.
- **Cloud URL as a path** (`src/cloud/fetch.rs`): one place decides how a bare `s3://`/`az://`/`gs://` URL finds credentials - `conn_for_url` (pure: the saved connection that `covers` it, account-level bound to the URL's bucket; the only unit-tested part), `provider_for_url` (that connection's creds, else an ephemeral connection on ambient creds), `fetch_url_to_temp` (download, temp keeps the object's extension, `tmp.keep()`). `cli::read_table` branches on `parse_cloud_url` before reading, so **every** CLI action taking a FILE takes a cloud object with no flag of its own; `cli/cloud.rs::provider_for` is now a wrapper over it. The MCP server deliberately keeps its own `resolve_cloud` (it carries the chat sandbox rule, which must not apply to CLI or GUI).
- **SFTP / WebDAV** (`src/cloud/{sftp,webdav}.rs`): `CloudKind::is_file_server()`. SFTP `bucket` = `host[:port]` (port 22 dropped), keys are server paths without the leading `/`, one cached session per user/host/port/auth over `crate::ssh::connect` (reconnects once, but only when the error is not the server's own status reply), saves go to `.<name>.octa-part` then remove + rename (no posix-rename in russh-sftp 3), single-object moves use `CloudProvider::rename`. WebDAV: `endpoint` = typed address, `bucket` = authority, `prefix` = path, store rooted at `scheme://authority/`; recursive listing walks Depth 1 (`walk_recursive`), `put_streaming` spools to a temp file and PUTs it with `ureq` (MKCOL on 409). WebDAV URLs need a saved connection; SFTP URLs fall back to `ephemeral_sftp` (agent, strict `known_hosts`).
- **Upload an open table** (`src/app/dialogs/cloud_upload.rs`, 2026-10-21): File > Save to cloud/SFTP... (`ShortcutAction::SaveToCloud`, unbound) and the tree's folder/root menu **Save the active tab here...** (`CloudTreeAction.save_here`, offered when `TreeCtx.can_upload`). The dialog only picks connection + key (pre-fill `root_prefix` or the clicked folder + `upload_file_name`: the cloud origin's object name, the source file name, `result_tab_file_name`, else `untitled.csv/.txt`). **The writing is a Save As** into a `ProtectedTempDir` (`begin_upload` -> `begin_save_as_for(.., Some(url))`: no open question, the prompt shows the URL, title `upload.title`), so rows/CSV questions, background jobs and the large-file export come for free. `OctaApp.pending_uploads` (keyed by the temp path) is handed over by `upload_saved_copy` at every landing of a Copy (`finish_table_save`, the text save, `drive_save_jobs`' table-changed branch, `poll_large_exports`) and dropped by `forget_upload` on every failure, refusal and Save As Cancel. `start_cloud_upload` (also the save-back path, `upload_cloud_tab`) streams with `octa::cloud::upload_file` (8 MiB blocks via `put_streaming`; `--cloud-put` uses it too), drops the temp folder, and queues the folder for a re-list (`cloud_browser.uploaded`). A partial tab shows the partial note + Load all rows in the dialog instead of `pending_partial_save_confirm` (whose Save anyway re-opens the file picker). Tests: `cloud_upload_tests.rs` (offline chain to a closed SFTP port, headless click, live `OCTA_TEST_SFTP_URL`).
- **Copy between kinds** (bucket <-> SFTP/WebDAV) always worked through `ops::copy` / `copy_across`; `tests/storage_live_tests.rs::across` pins it against CI's SFTP and WebDAV services with an in-memory bucket. The transfer dialog re-fills the destination when the target connection changes (`suggest_target_key`: the target's start folder + the source name; account-level targets keep the source path), until the user types into it (`tgt_key_edited`).
