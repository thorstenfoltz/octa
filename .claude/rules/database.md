# Live database connections

**Fourteen engines** (`DbEngine`, `ALL` in picker order): Postgres, MySql, Mssql, Oracle (oracle-rs, see its driver defects below), Redshift (Postgres wire protocol, `PgDialect` flag), ClickHouse (HTTP), Exasol (sqlx-exasol), Snowflake (SQL API v2), Databricks (Statement Execution API), BigQuery (REST `jobs.query`), Trino (HTTP), Athena (SigV4-signed HTTP, `src/db/sigv4.rs`), DuckDb and Sqlite (local files, see below). Redshift/ClickHouse/Exasol are wire connectors; the three warehouses talk REST/HTTP via `src/db/rest.rs` (`RestClient`). `DbEngine::duckdb_attachable()` = Postgres/MySql/Redshift only (native DuckDB ATTACH); the rest import table-by-table (row-capped). `DbEngine::supported_auth() -> &[DbAuthKind]` gates the Settings auth picker per engine; `DbAuth` grew Token (Databricks PAT)/KeyPairJwt{private_key_path}(Snowflake)/OAuthClientCredentials{client_id,token_url}(Snowflake+Databricks M2M)/OAuthBrowser(Snowflake SSO + Databricks U2M browser)/GcpAdc+GcpServiceAccount{key_path}(BigQuery); `AwsIam` also carries optional IAM Identity Center fields (`sso_start_url,sso_region,sso_account_id,sso_role`) for the in-app browser device flow; `DbAuthKind` is the fieldless mirror (`i18n_key()`). `DbConnector::fetch_batches` = default paged read (`paged_sql` LIMIT/OFFSET) every connector inherits; `copy.rs` `choose_lane(src,tgt)` picks **Fast** (both attachable -> DuckDB server-to-server, binary COPY) or **Universal** (`fetch_batches` -> `write_table`, any pair). ClickHouse/BigQuery tabs open read-only (no discoverable PK). Warehouse conn-field reuse: Databricks Database=warehouse_id, BigQuery Database=project, Snowflake account=Host label. **Catalog browsing**: `DbEngine::has_catalogs()` (Snowflake/Databricks/BigQuery only) drives a third sidebar level catalog>schema>table; `DbConnector::list_catalogs()` (default empty) + `list_schemas(catalog: Option<&str>)`/`list_tables(catalog, schema)` carry it (Snowflake `SHOW DATABASES`, Databricks `SHOW CATALOGS`, BigQuery Cloud Resource Manager `v1/projects` via a throwaway RestClient + cloud-platform token scope). `select_sample_sql`/`primary_key_sql`/`table_metadata_sql` take `catalog: Option<&str>` (3-part name; PK skipped for catalog engines). `table_metadata_sql` backs the db-tree "Show metadata..." context action (per-engine dispatch: Databricks `DESCRIBE TABLE EXTENDED`, Snowflake/ClickHouse/Exasol `DESCRIBE`, BigQuery/rest `information_schema.columns`) -> `open_db_metadata` worker -> `DbOpenResult::MetadataReady` -> read-only detached tab. Sidebar node key (`db_browser::ConnSchema`) second element is a `\x1f`-joined path (`split_path`/`join_path`); `db_tree::draw_level` recurses one extra level; `DbOrigin.catalog`/`DbCopyEnd.catalog` qualify the open/copy/server-SQL-hint. BigQuery `quote_ident` = backticks (was wrongly double-quotes). CLI/MCP/attach keep two-level (pass None).

**SSL mode, CA file, Connect via** (issue #87, 2026-10-20; `src/db/tls.rs`): `DbConnection.tls: DbTls { mode: TlsMode, ca_file, connect_via }` for Postgres/Redshift/MySQL (`tls::applies_to`). `TlsMode` = libpq's disable/prefer/require/verify-ca/verify-full (`label(engine)` prints MySQL's disabled/preferred/required/verify_identity, lower case like libpq's since 2026-10-21; `parse` takes either, any case). **Default `prefer` = encrypt if offered, certificate NOT checked** (user's decision, like psql/pgJDBC/DBeaver/mysql client); before, prefer verified chain+name, which refused every private/self-signed cert yet accepted plaintext. `effective_mode`: token auth raises disable/prefer to require. Postgres: `postgres_tls` -> tokio-postgres `SslMode` (verify-* -> Require) + rustls config with `NoCheck` (signatures still verified) or `ChainOnly` (maps `NotValidForName[Context]` to Ok) or webpki; native roots in a `OnceLock`, CA file (`DbTls::ca_path`, `~/` via `ssh::expand_home`) added per connect, read only by the verify modes; the config is kept in the connector for `cancel_handle`. MySQL: `mysql_ssl_opts` (accept_invalid_certs for unchecked modes, root certs only for verify, hostname override when dialling elsewhere); **no verify_ca** (mysql_async 0.37.1 string-matches `NotValidForName`, rustls 0.23.46 prints the Context variant); preferred emulated by reconnecting without TLS on `NoClientSslFlagFromServer` or a rustls handshake error (not on plain network errors); `tls::install_default_provider()` first, since mysql_async/sqlx-exasol call `ClientConfig::builder()`, which panics with ring + aws-lc-rs compiled in. **Connect via** = libpq `hostaddr`, IP only, folded into `DbConnection::dial_target()` (tunnel first); `postgres.rs` sets `port` ONCE (a second `.port()` gave "invalid number of ports": Postgres through an SSH tunnel never worked before). `duckdb_attach_sql` (now `Result`) passes `sslmode`/`sslrootcert` (`system` for verify-full without a file; libpq refuses `system` under verify-ca, so that bails) and `host=` + `hostaddr=`; MySQL `ssl_mode`/`ssl_ca`, verify modes refused without a CA file (DuckDB's MySQL extension checks nothing without one and never checks the name). `certificate_hint` adds a pointer to SSL mode / CA file / Connect via when the chain says `invalid peer certificate`. Known, documented: rustls refuses a CA-flagged self-signed server cert (`CaUsedAsEndEntity`, what `openssl req -x509` makes) even as the CA file, psql accepts it; `kubectl port-forward` dies whenever a TLS connection through it closes (psql too; kubectl#1169). Tests: `tls_tests.rs` (rcgen dev-dep mints certs, fake TLS Postgres server, mode matrix), `every_ssl_mode_says_what_it_does` (headless Settings render). CLI keys `sslmode=`/`sslrootcert=`/`hostaddr=`.

**tiberius 0.13 from crates.io, no fork any more** (2026-09-30). Until 0.13 we patched a fork (tokio-rustls 0.26 migration, since 0.12.3 dragged in an EOL rustls-webpki line); 0.13 did that migration upstream, so `[patch.crates-io]` and the `deny.toml` `allow-git` entry are gone. Two 0.13 behaviours matter: (1) a default **30 s `command_timeout`** that fails any round trip where the server stays silent that long, so `mssql.rs::connect` sets `command_timeout(None)` (pinned by `mssql_long_query_no_timeout_live`, which fails at 30 s without it); (2) it builds its rustls config with an explicit provider (process default, else aws-lc-rs, already in the tree via object_store), so the old "several providers, rustls refuses to pick" problem cannot occur, and it advertises TLS 1.2 and 1.3. The fork pinned 1.2 because the driver cannot process post-handshake TLS 1.3 records; SQL Server only offers 1.3 over TDS 8.0 strict encryption, which tiberius does not speak, and the live suite passed against SQL Server 2019 and 2022. If a KeyUpdate `UnexpectedEof` ever shows up mid-session, that pin is the thing to bring back. `mssql_session_encryption_live` asserts `sys.dm_exec_connections.encrypt_option = TRUE` - a silently-degraded TLS stack would still connect and pass every other MSSQL test.

**Every database error says who stopped it** (2026-10-23, `src/db/error.rs`; the user could not tell an Octa refusal from a server error after a typo). `db::connect` wraps every connector in `LabelledConnector` (ALL trait methods delegated, defaults included, or a connector's own `fetch_batches` would be bypassed) and labels connect failures, so every surface gets it at once. The lead is one sentence and a line break, never anyhow's `: ` (no colon in UI text): `<Engine label> returned an error.` when the server sent it (`from_server`: driver server variants, Postgres `as_db_error`, MySQL `Server`, tiberius `Server`, oracle-rs `OracleError`, sqlx-exasol `Database`, DuckDB `DuckDBFailure`, rusqlite `SqliteFailure`/`SqlInputError`, plus `db::ServerError`, which the HTTP engines raise in `rest.rs` (non-2xx, failed poll), Athena's state-change reason, Trino's error object and ClickHouse's non-2xx), else `Octa could not connect to 'name'.` / `Octa could not finish talking to 'name'.`. The labelled error is text (not downcastable); nothing downcasts a connector's error, and `ident_fix` reads text. `fetch_batches` passes a sink's own error (an export's full disk) through unlabelled (`FromSink`). Octa's refusals lead with `Octa did not send this to 'name', because ...` (`ensure_write_allowed`, MCP's read-only session) and `write_risk` reasons are whole sentences that quote the first word as typed (`statement_start`), so a typo shows. A new HTTP engine must raise `ServerError` for what its server says. Pinned by `db::error::tests` and `mod_tests::a_refusal_says_octa_refused_it_and_quotes_the_word_it_read`.

**Read-only connections are read-only on the server too** (2026-10-13). `ensure_write_allowed` / `may_write` = `is_mutation` || `write_risk(engine, sql)`: an ALLOW-list of first words (`READ_WORDS`: SELECT/WITH/SHOW/DESCRIBE/DESC/EXPLAIN/VALUES/TABLE/USE/LIST/HELP/EXISTS; SQL Server adds DECLARE/IF/BEGIN/WHILE/PRINT), then text rules: MySQL/BigQuery inner `;` (blunt, strings and comments count; the user chose to keep it blunt on 2026-10-22, MySQL's executable `/*! */` comments, `--1` and sql_mode-dependent quoting make an exact reading risky), SQL Server COMMIT/ROLLBACK/EXEC/EXECUTE and Redshift `INTO` **in code only** (2026-10-22, `src/db/sql_lex.rs`: `code_only(sql, Dialect)` empties strings, quoted names (`[..]` with `]]` on T-SQL, backticks on Spark) and comments (T-SQL nests block comments, so they are counted; elsewhere a nested `/*` has no answer), and returns `None`, i.e. every word counts, for a backslash on Spark/Redshift, a `$` on Redshift (dollar quoting) or anything unclosed; `has_code_word` also reads `@`/`#`/`$` as identifier chars on T-SQL and drops leading digits so `1EXEC` still counts), Databricks WITH (see below), EXPLAIN ANALYZE where the server does not enforce. **Databricks WITH reads the verb** (2026-10-22, `databricks::with_write_risk`, tokenising `sql_lex::code_only(.., Spark)`): the user hit the old blunt rule (any of INSERT/UPDATE/DELETE/MERGE anywhere, strings included) on everyday queries, e.g. a filter on `DESCRIBE HISTORY` output `operation = 'MERGE'`. Spark puts DML only AFTER the CTE list, never inside a CTE, so `spark_tokens` reads the depth-0 tokens of the emptied code (an outermost bracket records whether it starts like a query, which tells `name (cols) AS (q)` from `name (q)` + a bracketed main query) and `with_main_verb` reads the verb after the CTE list: SELECT/VALUES/TABLE/`(query)` run, `FROM` runs unless a write word follows at depth 0 (Hive multi-insert), anything else is refused. **Falls back to the blunt word rule** for a backslash anywhere (escape semantics differ: raw strings, backtick names, `escapedStringLiterals`), a nested block comment, an unclosed quote or unbalanced brackets (a bracketed `(WITH ...)` lands there too). Pinned by `databricks_tests::a_with_query_runs_unless_it_leads_into_a_write`. `sql::first_keyword` skips leading comments now (`-- x\nDELETE` used to read as `--`, a read, and ran); a leading block comment holding `/*` is left in place (PG/MSSQL/Spark nest them) and so refused. `DbEngine::enforces_read_only()` = PG/MySQL/MSSQL/ClickHouse, each connector reading `!conn.allow_writes` at connect: PG `SET default_transaction_read_only TO on` at connect AND again before every `query` (pipelined with `prepare` via `try_join!`, no extra round trip), because `SELECT set_config('default_transaction_read_only','off',false)` passes any word check (verified live); Redshift untested, so skipped. MySQL/MariaDB `SET SESSION TRANSACTION READ ONLY` (blocks DML, DDL, even temp tables; turning it off needs SET, which `is_mutation` refuses). SQL Server has no read-only session: `query` wraps the batch in `BEGIN TRANSACTION` ... `IF @@TRANCOUNT > 0 ROLLBACK` (after an error too); `execute` is NOT wrapped because `KILL` (the cancel) cannot run in a transaction. ClickHouse sends `readonly=1` on every request; a user whose profile is `readonly=2` gets "Cannot modify 'readonly' setting", which means the server already enforces, so `post` retries without it and remembers (`Cell<bool>`). MCP `ToolContext::db_connect` connects with `allow_writes = false` whenever `ctx.read_only`. Pinned by `read_only_connections_are_held_read_only_by_the_server_live` (bypasses the gate on purpose; each engine fails with its enforcement switched off, verified) and `cancel_running_query_live` (now also on read-only connections).

**Editable db tabs + confirmed write-back.** `src/db/write_back.rs` (pure library): `build_write_back_plan(table /*edits applied*/, &RowIdentity) -> DbWriteBackPlan{deletes,updates,inserts,added_columns}` - sqlite_reader diff shape addressed by the identity's values from `original[tag]`; errors on missing db_meta ("row identity lost") or a removed/renamed baseline column; added columns force full-row updates. **`RowIdentity` is how a row is addressed**: `Key(cols)` = a primary key OR a NOT NULL unique constraint (`db::row_key_sql` asks information_schema for both plus nullability, `db::choose_row_key` prefers the PK then the narrowest all-NOT-NULL unique, deterministically - the baseline is snapshotted at load and addressed by this key at save); `FullRow(cols)` = every baseline column, used when there is no key at all and `DbEngine::supports_row_update()` (PG/MySQL/MSSQL/Redshift/Exasol; ClickHouse + the catalog warehouses stay read-only, their DML is not a single-row UPDATE). **`FullRow` is safe only because `verify_one` rolls the transaction back unless each statement touched exactly 1 row** (2 = duplicate rows the values cannot tell apart, 0 = changed on the server since load); the check is deliberately NOT applied to `Key`, since MySQL reports *changed* not *matched* rows. `pk_where_sql` emits `IS NULL` for a NULL baseline value (`= NULL` is never true). `apply_write_back`: ONE transaction (ALTER ADD via `schema_export::sql::column_type_sql`, DELETE/full-row UPDATE, INSERT; rollback on error; MSSQL spells ADD without COLUMN). App side `src/app/dialogs/db_write_back.rs`: `save_file`/`save_tab` branch to `begin_db_write_back` BEFORE the source_path check (db tabs have no source_path; auto-save can't reach) -> guards -> plan -> `pending_db_write_back` -> CENTER forced-choice modal (counts + target + cannot-undo warn) -> Confirm spawns `DbWriteBackJob` (one app-wide, worker thread, `db_conn_cache.with_conn` - safe to retry, one transaction) -> `drain_db_write_back_job`: Ok -> `DbWriteBackReport::apply_to` (merged cells by tag and column name, since the tab may hold server hash columns the save leaves out; `gone` rows deleted with their undo entry popped) + `retag_db_meta` + `clear_modified`; `WriteBackFailure::Conflicts` -> `WriteConflicts::adopt_added_columns` + the conflict dialog; `Error` -> keep edits. The worker catches `WriteConflicts` INSIDE the `with_conn` closure (`downcast`, before any stringifying), so the cache neither drops the connector nor re-runs the save for an answer that is not a dead connection. **Conflict dialog** `src/app/dialogs/db_conflicts.rs` (`OctaApp.db_conflicts: Option<DbConflictsState{tab_idx,conflicts,choices,columns_added}>`, no shortcut: only a save raises it, re-pointed by `shift_refresh_indices` like the write-back job): per row a Keep mine / Take theirs radio pair whose labels follow `ConflictKind`, All mine / All theirs, selectable values; Save -> `apply_resolutions` (clears undo AND redo: no Undo is promised anywhere) + `TabState::recipe_after_history_cleared` (shared with `apply_view_page`) -> `db_write_back_prompt` (`Result<Option<_>, String>`: `Ok(None)` = the tab now equals the server, re-baselined; `Err` = cannot proceed, edits kept) -> `spawn_db_write_back` without the confirmation; disabled while another write runs. i18n `db.wb_done_merged`/`wb_conflicts`/`wb_conflicts_cols` + `[db_conflicts]`. `DbOrigin.identity: Option<RowIdentity>` (None = read-only) is what `is_readonly()` gates on; the editability note is four-way (key -> none / FullRow -> `db.tab_full_row_note` / conn read-only -> `db.tab_readonly_note` / no identity -> `db.tab_no_pk_note`). It is a **`status_message`**: it reports what happened when a tab opened, which is what every other such report in the app is, so it gets that style, that dismiss button, that hover pause and the one lifetime in Settings -> Appearance. It used to be a `parse_error_banner`, a second style that sat there until clicked. Nothing permanent is lost, because a non-writable db tab already shows the standing `[Read-only]` pill for as long as it is open. Status bar busy shows `db.writing_back`; a full Save As strips `db_origin`+`db_meta`. **Conflict check (no more last-writer-wins, 2026-10-14)**: for a `Key` plan carrying `merge: Some(MergeInfo)`, `apply_write_back` first re-reads every touched key INSIDE the transaction, before any ALTER/DELETE/UPDATE (`check_against_server` -> `reread_sql`: the baseline columns by name, `WHERE (key) OR (key) ...`, `CONFLICT_READ_BATCH` = 100 keys per SELECT because oracle-rs stops every result at 100 rows, and never more than `initial_load_rows()`, since `query` cuts there and a cut-off row would look deleted; a batch that comes back short AND at the cap, i.e. the cap was lowered mid-save, bails instead of reading the missing rows as gone). Decoded by the same `connector.query` that loaded the tab, so `key_text`/`same_cell` agree with the baseline (the live write-back and edit-one-cell tests assert an untouched server merges nothing). One known difference is absorbed there: Oracle types an unconstrained NUMBER per result, so the load can read `Float(5.0)` and a re-read `Int(5)`; `same_cell` treats an `Int` and a `Float` holding exactly that whole number as equal (`whole_i64`, never `i as f64 == f`, which is lossy above 2^53) and `key_text` prints such a Float as its Int. Then `merge_plan` merges three ways per cell: their change to another cell is written along with mine (`DbWriteBackReport.merged`), a row already gone is skipped (`.gone`), and any colliding change rolls back with the typed `WriteConflicts { conflicts, columns_added }` error (`downcast_ref`), no row written. Locks: `FOR UPDATE` on Postgres/MySQL/Oracle (on MySQL it is also what makes the read see the latest commit, not the REPEATABLE READ snapshot), `WITH (UPDLOCK, ROWLOCK)` on SQL Server, held until COMMIT/ROLLBACK, with one exception: **DDL commits on MySQL/MariaDB and Oracle** (`rechecks_after_alter`, which also covers Exasol). A save that adds a column there checks before the `ALTER TABLE ADD` (a conflict writes nothing, `columns_added: false`), the ALTER then commits and releases those locks (and drops MySQL back to autocommit), so `apply_write_back` issues `BEGIN` again and re-runs the check under fresh locks before any DML; the DML is built from that second read and stays atomic. A conflict found only in the second check leaves the added columns on the server and comes back with `columns_added: true`, so the caller appends them to the baseline (`WriteConflicts::adopt_added_columns`: `original_columns` + NULL in every baseline row AND in each conflict's `base`/`theirs`, or `apply_resolutions` would no longer recognise the baselines) before the next save would ALTER them again. Ceilings: Redshift reads without a lock and relies on its isolation, a gap of milliseconds between check and write. Exasol also reads without a lock and its connector swallows `BEGIN`, so its writes are not atomic and that millisecond gap remains; a save that adds a column re-reads after the ALTERs too, so the gap is not stretched to the ALTERs' duration. Not checked: `FullRow` plans (`verify_one` refuses a changed row instead) and sync plans (`merge: None`, `--sync-sql`/`sync_sql` already compared against the server). Live: `{postgres,mysql,mssql,oracle}_write_conflicts_live` (two sessions: other-cell merge, same-cell conflict writes nothing, deleted-on-server, added column: a conflict adds no column, a clean save adds it and keeps B's change; MariaDB runs through `OCTA_TEST_MYSQL_URL`, `docker run --rm -d -e MARIADB_ROOT_PASSWORD=octa_test_pw -p 53307:3306 mariadb:11`). The `postgres_*` tests that GRANT on schema `public` go through `pg_schema_grant` (a static Mutex): two concurrent GRANTs fail one with "tuple concurrently updated". Other ceiling: only loaded rows compared. i18n `db.wb_*`/`tab_*` + `dialog.dwb_*`.

**Text literals have ONE source: `pushdown::dialect::str_lit(engine, s)`.** The server analyses compare with it and `sql_literal` (every write-back UPDATE/WHERE and every `write_table_generic` INSERT, i.e. Save to database, copy, MCP `write_db_table`) writes `String`/`Nested` with it. Rules, from each engine's docs and pinned live: backslash doubled on Snowflake/ClickHouse/Redshift/Databricks/BigQuery (an escape there); `\'` instead of `''` on Databricks (Spark joins `'it''s'` into `its`, checked in a local Spark) and BigQuery (also `\n`/`\r`, no raw line break in a quoted literal); MySQL text containing `\` as `_utf8mb4 X'<hex>'` (exact with and without `NO_BACKSLASH_ESCAPES`; the introducer keeps it text for JSON columns); SQL Server `N'..'` only for non-ASCII (a plain literal goes through the code page: `中文` became `??`; ASCII stays plain so a VARCHAR key can still seek) and a backslash before a line break spliced in as `NCHAR(92)` (T-SQL drops `\`+newline as a line continuation); everyone else `''`. `*_text_survives_a_write_live` (PG with `standard_conforming_strings` off on role `octa_scs`, MySQL, MSSQL, ClickHouse `ENGINE = Memory`, Trino `memory` catalog, Oracle) writes `TRICKY_TEXT` and reads it back. Docker: `clickhouse/clickhouse-server` (`CLICKHOUSE_PASSWORD`, port 8123), `trinodb/trino` (catalog `memory`), `gvenzl/oracle-free:23-slim` (`ORACLE_PASSWORD`, db `FREEPDB1`).

**Append resolves the server's spelling** (2026-10-10): every identifier `write_table_generic` sends is quoted, so on Append it first runs `relationships::scan_columns(.., Some(table))` (the catalog listing filtered by `UPPER(table) = UPPER(str_lit)`, before BEGIN, best effort: a refused lookup keeps the data's names) and maps the table and each column through `relationships::server_name` (exact first, else the ONE case-insensitive match, else unchanged so the server's error names it); `table_columns` is the same rule for export's empty-table header. Oracle/Snowflake/Exasol fold unquoted names to upper, Postgres to lower, so `"id"` missed `ID` (ORA-00904). Pinned by `append_uses_the_servers_spelling_of_table_and_columns` and `oracle_text_survives_a_write_live` (unquoted DDL, lower-case table name). The lookup is per call, i.e. once per 50k batch in the copy lane.

**oracle-rs 0.1.7 driver defects** (diagnosed 2026-10-10 against 23 Free, user chose NOT to patch or fork the driver for now; documented as known in both docs): (1) **every result stops at 100 rows**: `parse_query_response_with_columns` hard-codes `has_more_rows: false`, so `oracle.rs::query`'s `fetch_more` loop never runs (table tabs, SQL panel, export, copy, relationship scan all see <= 100 rows; why `oracle_dialect_paths_live` fails at the `scan` assert: SYSTEM has ~456 columns); (2) `send_marker` writes a 2-byte length on a large-SDU connection, so any in-call error makes the server hang up: "ORA-00000: Server rejected the operation and closed the connection", then "connection not ready"; (3) `FetchMessage` has the same 2-byte framing, sequence number 0 and no 23ai token number, so fixing (1) alone kills the connection on the first `fetch_more` (`early eof`), and a 1000-row fetch spans several packets the driver reads one of. Upstream has the fixes as open PRs (stiang/oracle-rs #16 markers, #8 pagination+fetch framing, #14 multi-packet, #10 19c), no commit since 2026-03. A one-line marker patch was verified live (real ORA-00904, connection survives); the fetch path still hung with Octa's `FETCH_ROWS` 1000. Revisit when upstream releases.

## Database write semantics (SQLite / DuckDB)

DB writes are **diff-based, never overwrite**. The reader snapshots row identity (`rowid` / `__octa_row_id`) + original cells into `db_meta`. On save, in one transaction: DELETE missing tags, INSERT `None`-tag rows, UPDATE rows whose cells differ. Schema changes rejected before touching the file.

## Module layout

- `src/ssh.rs`: connect / host-key check (`~/.ssh/known_hosts`, accept-new opt-in, a changed key always refused) / sign-in (agent, key file with `~/` expanded, password) as `ssh::connect(rt, &SshTarget, secret) -> ssh::Session`, shared with the SFTP storage type. `src/db/ssh_tunnel.rs` re-exports `SshAuth` and `SshTarget as SshTunnel` (same serde shape, so saved DB connections load unchanged) and keeps only the loopback forwarding.
- `src/formats/sqlite_reader.rs`: `rusqlite` (bundled); `rowid` in `db_meta.row_tags`; diff writes; schema changes rejected.
- `src/formats/duckdb_reader.rs`: `duckdb` (bundled); synthetic `__octa_row_id BIGINT` (stripped from user schema) materialised **on save only** - reading NEVER mutates the file (tags come from DuckDB's implicit `rowid`; the save-time backfill sets `__octa_row_id = rowid` so read-tags still address the same rows). Users export results to .duckdb and open them elsewhere; a counter column sprouting on open was a reported bug. Diff-on-save.

## Related design patterns

- **Save an open table to a database**: **File -> Save to database...** (`ToolbarAction.open_table_to_db` -> `open_table_to_db_dialog`, `ShortcutAction::SaveTableToDb` UNBOUND) reuses the SQL panel's write-back dialog rather than adding a second one: `SqlWriteBackState.source: WriteBackSource::{SqlResult,ActiveTable}` is the only difference, so targets (saved live connection OR DuckDB/SQLite file) and modes are shared. The live-DB branch hands `tab.table` (edits applied) to `DbConnector::write_table`; the file branch builds a throwaway `SqlWorkspace` with the table as `data` and writes `SELECT * FROM data` through `write_result_to_db` (a long-lived workspace could hold a stale snapshot). Refuses an empty tab and a **large-file tab** (that holds one page, so it would write a slice and report success). **The live CREATE and its INSERT must quote identifiers identically**: `create_table_qualified` used `quote_ident` (bare when safe) while `write_table_generic`'s column list always quotes, so Postgres created `id` and the INSERT asked for `"ID"` - every table with a capital letter in a header failed with only "inserting rows". Fixed by `Dialect::quote_always`, pinned by `live_ddl_quotes_identifiers_so_the_insert_can_find_them`.
- **File vs database or cloud compare** (`src/db/fetch_table.rs` + `src/cloud/fetch.rs`): no new comparison engine - `fetch_table` turns a connection plus `SCHEMA.TABLE` into a `DataTable`, a cloud object is downloaded and read through the registry, and both sides go to `compare::compare_join`. `split_qualified` handles the 1/2/3-part name; an empty schema means the connection's own database. Surfaces: `dialogs/db_compare.rs` (a `CompareSource {Database,Cloud}` radio picks the B side, `SideB` is resolved on the UI thread so a missing target reports without spawning; worker thread + polled slot, modelled on `db_copy.rs`; result into a detached tab, banner when either side hit the row cap; the dialog opens when EITHER connection list is non-empty, defaulting to Cloud for a cloud-only user), CLI `--diff-db`, MCP `diff_tables { b_db }`. Live test `file_vs_postgres_table_diff_live`.
- **Declared foreign keys as a third relationship source** (`src/db/relationships.rs`): the other two sources guess from values; a server already knows, so this reads its catalog instead. Pure SQL builders per engine (`foreign_key_sql`/`schema_columns_sql`, `''`-doubled literals) + `scan(c, catalog, schemas) -> (Vec<ColumnRow>, Vec<ForeignKey>)` + the pure assembler `build_db_map(columns, fks, wanted, max_tables) -> DbMap{map, skipped_edges, truncated}`. **Two catalog queries and no table data**, so the cost does not grow with the tables. Edges come back `scored: false` with `constraint: Some(name)` and all-zero numbers; `rel_map::score_edges(tables, &mut map, sample)` is the separate, never-automatic pass that fills them in **child-to-parent direction** (`left_orphans` means the opposite thing the other way round). That pass exists because `DbEngine::enforces_foreign_keys()` is true only for PG/MySQL/MSSQL/Exasol - Redshift/Snowflake/Databricks/BigQuery accept a declaration and enforce nothing - and `has_foreign_keys()` is false for ClickHouse alone. The shared scorer is `join_keys::score_pair`, extracted so the ranking, the map and this verification cannot report different numbers for one edge. Surfaces: the **Database** radio in `dialogs/rel_map.rs` (connection + catalog combos reusing `dbcmp.connection`/`catalog`, schema tick-list, and a **Tables** tick-list that redraws client-side from the already-read `db_columns`/`db_fks` - no second round trip; unscored edges draw an `FK` chip, not a fake `0.00`) and MCP `db_relationships` (read-only, `measure: true` opts into the row-reading pass). No CLI flag: `--relationships` stays a folder scan.
- **Export tables to files** (`src/db/export.rs`, 2026-10-07): `export_tables(conn, &ExportRequest, progress, cancel) -> Vec<TableOutcome>` streams each table through `fetch_batches` (50k pages) into a `Sink` (CSV/TSV via the shared delimited writer + Settings CSV options, Parquet via `ParquetStreamWriter`, JSONL) inside `write_atomically`, so a failure or a cancel leaves nothing under the real name; existing file -> `Skipped` unless overwrite; safe, collision-free file names (`Users` vs `users` -> `Users_2`). **Empty tables**: real drivers return NO columns for a row-less result, so the header comes from `relationships::scan_columns(.., Some(table))` + `table_columns` (catalog query, exact name first, then the one case-insensitive match), typed text; found by the live tests, the fake connector had hidden it. Surfaces: sidebar schema context menu **Export tables...** / table menu **Export to file...** (`DbTreeAction.export`) -> `dialogs/db_export.rs` (tables from the sidebar's own `ensure_db_listing` cache, own `db::connect` on the worker so a long run does not hold the shared connection; progress + `AtomicBool` cancel, closing cancels), `ShortcutAction::OpenDbExport` (unbound; works on an open db tab), CLI `--db NAME --db-export SCHEMA --out-dir DIR [--to EXT] [--db-export-tables a,b] [--overwrite]` (exit 1 if any failed), MCP `export_db_tables` (write tool: it writes files; `resolve_write_path` sandbox). Read-only on the server, so no `allow_writes` gate. Live tests `{postgres,mysql}_export_tables_live` (120,003 rows = 3 pages, every id once, Parquet + CSV, empty table header).
