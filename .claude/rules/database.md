# Live database connections

**Nine engines** (`DbEngine`, `ALL` in picker order): Postgres, MySql, Mssql, Redshift (Postgres wire protocol, `PgDialect` flag), ClickHouse (HTTP), Exasol (sqlx-exasol), Snowflake (SQL API v2), Databricks (Statement Execution API), BigQuery (REST `jobs.query`). Redshift/ClickHouse/Exasol are wire connectors; the three warehouses talk REST/HTTP via `src/db/rest.rs` (`RestClient`). `DbEngine::duckdb_attachable()` = Postgres/MySql/Redshift only (native DuckDB ATTACH); the rest import table-by-table (row-capped). `DbEngine::supported_auth() -> &[DbAuthKind]` gates the Settings auth picker per engine; `DbAuth` grew Token (Databricks PAT)/KeyPairJwt{private_key_path}(Snowflake)/OAuthClientCredentials{client_id,token_url}(Snowflake+Databricks M2M)/OAuthBrowser(Snowflake SSO + Databricks U2M browser)/GcpAdc+GcpServiceAccount{key_path}(BigQuery); `AwsIam` also carries optional IAM Identity Center fields (`sso_start_url,sso_region,sso_account_id,sso_role`) for the in-app browser device flow; `DbAuthKind` is the fieldless mirror (`i18n_key()`). `DbConnector::fetch_batches` = default paged read (`paged_sql` LIMIT/OFFSET) every connector inherits; `copy.rs` `choose_lane(src,tgt)` picks **Fast** (both attachable -> DuckDB server-to-server, binary COPY) or **Universal** (`fetch_batches` -> `write_table`, any pair). ClickHouse/BigQuery tabs open read-only (no discoverable PK). Warehouse conn-field reuse: Databricks Database=warehouse_id, BigQuery Database=project, Snowflake account=Host label. **Catalog browsing**: `DbEngine::has_catalogs()` (Snowflake/Databricks/BigQuery only) drives a third sidebar level catalog>schema>table; `DbConnector::list_catalogs()` (default empty) + `list_schemas(catalog: Option<&str>)`/`list_tables(catalog, schema)` carry it (Snowflake `SHOW DATABASES`, Databricks `SHOW CATALOGS`, BigQuery Cloud Resource Manager `v1/projects` via a throwaway RestClient + cloud-platform token scope). `select_sample_sql`/`primary_key_sql`/`table_metadata_sql` take `catalog: Option<&str>` (3-part name; PK skipped for catalog engines). `table_metadata_sql` backs the db-tree "Show metadata..." context action (per-engine dispatch: Databricks `DESCRIBE TABLE EXTENDED`, Snowflake/ClickHouse/Exasol `DESCRIBE`, BigQuery/rest `information_schema.columns`) -> `open_db_metadata` worker -> `DbOpenResult::MetadataReady` -> read-only detached tab. Sidebar node key (`db_browser::ConnSchema`) second element is a `\x1f`-joined path (`split_path`/`join_path`); `db_tree::draw_level` recurses one extra level; `DbOrigin.catalog`/`DbCopyEnd.catalog` qualify the open/copy/server-SQL-hint. BigQuery `quote_ident` = backticks (was wrongly double-quotes). CLI/MCP/attach keep two-level (pass None).

**tiberius is patched to a fork** (`[patch.crates-io]` at the bottom of `Cargo.toml`, pinned by commit to `thorstenfoltz/tiberius`). Upstream's last release is 0.12.3 (July 2024) and its `main` still pins tokio-rustls 0.24 -> rustls 0.21 -> rustls-webpki 0.101, an EOL line unpatched against GHSA-82j2-j2ch-gfr8 / -xgp8-3hg3-c2mh / -965h-392x-2mh5. tiberius was the **only** crate left on that stack, so the binary carried two complete rustls stacks; the patch removed 8 packages from the lock. The fork is one commit migrating the TLS stream to tokio-rustls 0.26 / rustls 0.23 / rustls-webpki 0.103, with two deliberate choices: the crypto provider is named **`ring`** (rustls 0.23 refuses to pick one when several are compiled in, and `object_store` pulls aws-lc-rs alongside our ring) to match `rustls_client_config`; and TLS is **pinned to 1.2**, because TDS tunnels the handshake inside TDS packets and the driver never processes post-handshake TLS 1.3 records, so a KeyUpdate surfaces as `UnexpectedEof` mid-session (not a downgrade: upstream advertises 1.3 then breaks on it, and SQL Server only offers 1.3 over TDS 8.0 strict encryption, which tiberius does not implement). Drop the patch once tiberius releases on tokio-rustls 0.26+. `deny.toml` needs the matching `[sources] allow-git` entry. `mssql_session_encryption_live` asserts `sys.dm_exec_connections.encrypt_option = TRUE` - a silently-degraded TLS stack would still connect and pass every other MSSQL test.

**Editable db tabs + confirmed write-back.** `src/db/write_back.rs` (pure library): `build_write_back_plan(table /*edits applied*/, &RowIdentity) -> DbWriteBackPlan{deletes,updates,inserts,added_columns}` - sqlite_reader diff shape addressed by the identity's values from `original[tag]`; errors on missing db_meta ("row identity lost") or a removed/renamed baseline column; added columns force full-row updates. **`RowIdentity` is how a row is addressed**: `Key(cols)` = a primary key OR a NOT NULL unique constraint (`db::row_key_sql` asks information_schema for both plus nullability, `db::choose_row_key` prefers the PK then the narrowest all-NOT-NULL unique, deterministically - the baseline is snapshotted at load and addressed by this key at save); `FullRow(cols)` = every baseline column, used when there is no key at all and `DbEngine::supports_row_update()` (PG/MySQL/MSSQL/Redshift/Exasol; ClickHouse + the catalog warehouses stay read-only, their DML is not a single-row UPDATE). **`FullRow` is safe only because `verify_one` rolls the transaction back unless each statement touched exactly 1 row** (2 = duplicate rows the values cannot tell apart, 0 = changed on the server since load); the check is deliberately NOT applied to `Key`, since MySQL reports *changed* not *matched* rows. `pk_where_sql` emits `IS NULL` for a NULL baseline value (`= NULL` is never true). `apply_write_back`: ONE transaction (ALTER ADD via `schema_export::sql::column_type_sql`, DELETE/full-row UPDATE, INSERT; rollback on error; MSSQL spells ADD without COLUMN). ## Database write semantics (SQLite / DuckDB)

DB writes are **diff-based, never overwrite**. The reader snapshots row identity (`rowid` / `__octa_row_id`) + original cells into `db_meta`. On save, in one transaction: DELETE missing tags, INSERT `None`-tag rows, UPDATE rows whose cells differ. Schema changes rejected before touching the file.

## Module layout

- `src/formats/sqlite_reader.rs`: `rusqlite` (bundled); `rowid` in `db_meta.row_tags`; diff writes; schema changes rejected.
- `src/formats/duckdb_reader.rs`: `duckdb` (bundled); synthetic `__octa_row_id BIGINT` (stripped from user schema) materialised **on save only** - reading NEVER mutates the file (tags come from DuckDB's implicit `rowid`; the save-time backfill sets `__octa_row_id = rowid` so read-tags still address the same rows). Users export results to .duckdb and open them elsewhere; a counter column sprouting on open was a reported bug. Diff-on-save.

## Related design patterns

- **Save an open table to a database**: **File -> Save to database...** (`ToolbarAction.open_table_to_db` -> `open_table_to_db_dialog`, `ShortcutAction::SaveTableToDb` UNBOUND) reuses the SQL panel's write-back dialog rather than adding a second one: `SqlWriteBackState.source: WriteBackSource::{SqlResult,ActiveTable}` is the only difference, so targets (saved live connection OR DuckDB/SQLite file) and modes are shared. The live-DB branch hands `tab.table` (edits applied) to `DbConnector::write_table`; the file branch builds a throwaway `SqlWorkspace` with the table as `data` and writes `SELECT * FROM data` through `write_result_to_db` (a long-lived workspace could hold a stale snapshot). Refuses an empty tab and a **large-file tab** (that holds one page, so it would write a slice and report success). **The live CREATE and its INSERT must quote identifiers identically**: `create_table_qualified` used `quote_ident` (bare when safe) while `write_table_generic`'s column list always quotes, so Postgres created `id` and the INSERT asked for `"ID"` - every table with a capital letter in a header failed with only "inserting rows". Fixed by `Dialect::quote_always`, pinned by `live_ddl_quotes_identifiers_so_the_insert_can_find_them`.
- **File vs database or cloud compare** (`src/db/fetch_table.rs` + `src/cloud/fetch.rs`): no new comparison engine - `fetch_table` turns a connection plus `SCHEMA.TABLE` into a `DataTable`, a cloud object is downloaded and read through the registry, and both sides go to `compare::compare_join`. `split_qualified` handles the 1/2/3-part name; an empty schema means the connection's own database. Surfaces: `dialogs/db_compare.rs` (a `CompareSource {Database,Cloud}` radio picks the B side, `SideB` is resolved on the UI thread so a missing target reports without spawning; worker thread + polled slot, modelled on `db_copy.rs`; result into a detached tab, banner when either side hit the row cap; the dialog opens when EITHER connection list is non-empty, defaulting to Cloud for a cloud-only user), CLI `--diff-db`, MCP `diff_tables { b_db }`. Live test `file_vs_postgres_table_diff_live`.
- **Declared foreign keys as a third relationship source** (`src/db/relationships.rs`): the other two sources guess from values; a server already knows, so this reads its catalog instead. Pure SQL builders per engine (`foreign_key_sql`/`schema_columns_sql`, `''`-doubled literals) + `scan(c, catalog, schemas) -> (Vec<ColumnRow>, Vec<ForeignKey>)` + the pure assembler `build_db_map(columns, fks, wanted, max_tables) -> DbMap{map, skipped_edges, truncated}`. **Two catalog queries and no table data**, so the cost does not grow with the tables. Edges come back `scored: false` with `constraint: Some(name)` and all-zero numbers; `rel_map::score_edges(tables, &mut map, sample)` is the separate, never-automatic pass that fills them in **child-to-parent direction** (`left_orphans` means the opposite thing the other way round). That pass exists because `DbEngine::enforces_foreign_keys()` is true only for PG/MySQL/MSSQL/Exasol - Redshift/Snowflake/Databricks/BigQuery accept a declaration and enforce nothing - and `has_foreign_keys()` is false for ClickHouse alone. The shared scorer is `join_keys::score_pair`, extracted so the ranking, the map and this verification cannot report different numbers for one edge. Surfaces: the **Database** radio in `dialogs/rel_map.rs` (connection + catalog combos reusing `dbcmp.connection`/`catalog`, schema tick-list, and a **Tables** tick-list that redraws client-side from the already-read `db_columns`/`db_fks` - no second round trip; unscored edges draw an `FK` chip, not a fake `0.00`) and MCP `db_relationships` (read-only, `measure: true` opts into the row-reading pass). No CLI flag: `--relationships` stays a folder scan.
