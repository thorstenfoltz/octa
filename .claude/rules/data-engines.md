# Data engines and analysis features

Every entry below is a pure engine in `src/data/` plus its GUI dialog, CLI flag
and MCP tool. Adding one means touching all of those surfaces.

## Module layout

- `src/data/mod.rs`: `DataTable`, `ColumnInfo`, `DbRowMeta` + the core row/column mutation methods. Cell edits live in a `HashMap<(row,col), CellValue>` overlay; `rows` only mutate on `apply_edits()`. `structural_changes` flags non-cell edits. `db_meta: Option<DbRowMeta>` carries DB row identity (`table_name`, `row_tags: Vec<Option<i64>>`, `original`, `original_columns`); new rows have `None` tags. Sibling files (all re-exported from `mod.rs`, so `octa::data::<Name>` paths are unchanged): `cell_value.rs` (`CellValue` + `BinaryDisplayMode` + `is_numeric_data_type`/`wildcard_to_regex`/`can_convert_value`/`convert_value`/`cmp_cell_values`), `view_enums.rs` (`ViewMode`/`MapMode`/`CompareMode`/`MarkdownLayout`/`SearchMode`/`SearchResultMode`), `marks.rs` (`MarkColor`/`MarkKey` + the mark methods), `undo.rs` (`UndoAction` + `undo`/`redo`/`coalesce_undo_since`). `src/app/state/` is likewise a dir-module: `mod.rs` holds the two core structs (`OctaApp`, `TabState`) + origin markers; `dialogs.rs` holds the ~30 small per-dialog/pipeline state structs (re-exported, so `crate::app::state::<Name>` is unchanged).
- `src/data/search.rs`: `RowMatcher` (Plain/Wildcard/Regex search-filter-replace). `RowMatcher::with_options(query, mode, case_sensitive, whole_word)` adds the search-bar `Aa`/whole-word toggles (routes through a `RegexBuilder` when either is on; `\b...\b` for whole-word). Per-tab `TabState.search_case_sensitive`/`search_whole_word`/`search_scope_col` (session) feed `tab.search_matcher()`; the search-bar scope dropdown (`Some(col)`=one column / `None`=all) gates the column range in `recompute_filter` + `search_highlight::cell_matches(.., scope_col)`. i18n `search.{case_sensitive,whole_word,scope_all,scope_hint}`. **Persistent search history**: `OctaApp.search_history: Vec<String>` (most-recent first) persisted to `<config_dir>/search_history.json` via `src/app/search_history.rs` (`load`/`record(history, query, limit)`); `ToolbarAction.commit_search_history` fires on search-box `lost_focus`, the toolbar **Recent** dropdown recalls entries. Capped by `AppSettings.search_history_limit` (default 5, 0=off). i18n `search.{history,history_btn,history_hint}`, `settings.search_history_limit`.

## Design patterns

- **Value Frequency**: `Ctrl+Shift+I` / header right-click / **Analyse -> Value frequency...**; no-context raises `value_frequency_picker.rs`. Compute `octa::data::value_frequency::compute_value_frequency`; UI `src/app/dialogs/value_frequency.rs`. Binning `Sturges` (`[5,30]`) or `Custom(n)` (`[1,1000]`); **binned results keep every bucket, ascending, not Top-N-truncated**; raw mode sorts by count desc with Top-N. "Filter table to this value" writes `column_filters`.
- **Numeric display formatting**: `src/data/num_format.rs` — `format_cell_number(value, Option<NumberFormat>, thousands, SeparatorStyle)` + `round_value`. `NumberFormat { decimals: Option<i32>, rounding }`; decimals signed (positive=after point, negative=round before, None=Auto). Per-column on `TabState.column_number_formats` (session-only). Configured via `src/app/dialogs/column_format.rs` (window id `octa_column_format_dialog_v2`; multi-column picker `column_format_cols`). Rounding is display-only: on Save if any column `rounds_values()`, `do_save_tab` defers to `pending_round_save` + `round_save_prompt.rs`.
- **Pivot / Unpivot**: long<->wide reshape via DuckDB `PIVOT`/`UNPIVOT`. App-level `OctaApp.pivot_dialog: Option<PivotState>` (`PivotKind` in `state.rs`, `PivotAgg` in `data::pivot`); **Analyse -> Pivot / Unpivot...** (`ToolbarAction.open_pivot`). Dialog `src/app/dialogs/pivot.rs` builds the SQL (quoted idents) + `octa::sql::run_query` -> detached tab (`custom_tab_label`, same pattern as `open_describe_tab`). The dialog shows a plain-language sentence (`octa::data::pivot::explain_pivot`/`explain_unpivot`, testable) + a **bounded live preview**: `PivotState.preview`/`preview_key` cache the result of running the op on a capped source sample (`PIVOT_PREVIEW_SOURCE_ROWS`=1000, `PIVOT_PREVIEW_RESULT_ROWS`=10), recomputed only when a hash of the inputs changes (never per frame, never the full table). i18n `analyse_menu.pivot` + `dialog.pv_*` (incl. `pv_explain_*`/`pv_preview*`).
- **Conditional column (CASE / if-elseif-else)**: derive a new column from ordered rules (first match wins, else fallback). Pure `octa::data::transform::conditional_value` — `CaseRule { cond_col: Option<usize>, op: CondOp, value, case_sensitive, output }`, `CaseSpec { rules, else_output }`, `build_case_column(table, spec) -> Vec<CellValue>` **reuses** `conditional_format::{CondOp, rule_matches}` (one comparison source of truth); `infer_case_column_type` types the result (numeric outputs become Int/Float). App-level `OctaApp.conditional_column_dialog: Option<ConditionalColumnState>` (`state.rs`); **Edit -> Conditional column...** (`ToolbarAction.open_conditional_column`, gated `!is_readonly()`), dialog `src/app/dialogs/conditional_column.rs` materialises via `insert_column` + `set` (undoable). Shortcut `OpenConditionalColumn`. i18n `[ccol]`.
- **Conditional formatting**: rule-based automatic cell colouring. Pure `octa::data::conditional_format` - `CondRule { column: Option<usize>, op: CondOp, value, color: MarkColor, case_sensitive }`, `CondOp` (Eq/Ne/Contains/NotContains/Gt/Lt/Ge/Le/Empty/NotEmpty; numeric compare when both parse as f64), `match_color(rules, col, cell)` returns the first matching rule's colour. Session-only `TabState.conditional_format_rules`; threaded through `draw_table` -> `draw_data_row_direct` (`rows.rs`), folded into `mark_color` via `.or_else` (explicit marks win). Dialog `src/app/dialogs/conditional_format.rs` (**Edit -> Conditional formatting...**); no Apply step, edits apply live. Rules are first-match-wins (an if/else-if/else chain); per-row `^`/`v` buttons reorder them + a `cnf_order_hint` makes that explicit. **Its rule rows and Data validation's are `egui::Grid`s, not one `horizontal` per rule**: `ComboBox::width` is a desired width, not a cap, so a long column name widens its button and shifts every later widget right on that row alone. i18n `[cond_op]` + `dialog.cnf_*` (the `cf_*` prefix is the Column Filter dialog's).
- **Find duplicates**: **Search -> Find duplicates...** / **Ctrl+Shift+D**. `octa::data::duplicates::find_duplicate_rows` (text key via `CellValue::to_string()` joined `\x1F`). UI `src/app/dialogs/find_duplicates.rs`. `Highlight` marks `MarkColor::Orange`; `NewTab` clones. `int(1)` vs `float(1.0)` don't dedupe.
- **Multi-search**: **Search -> Multi-search** / **F6**. `octa::data::multi_search::search_table(...)` (reuses `RowMatcher`). `src/app/multi_search.rs` owns `MultiSearchState` (worker + cancel in `Arc`), bottom `egui::Panel`. Scopes `AllOpenTabs` (sync) / `Directory` (worker on `read_sorted_dir`, single level, per-file cap `grep_max_file_size_mb` default 50 MB). Skips push `SkippedFile {Oversized|ParseError}` -> "N skipped" chip. Caps 10k total / 1k per file.
- **Schema Export**: **File -> Export schema...** / **F7** (not Ctrl+Shift+X — collides with `Event::Cut`). Library `src/data/schema_export/{mod,sql,pydantic,typescript,json_schema,rust}.rs` — pure `(&[ColumnInfo], &str) -> String`. Nine targets: five SQL dialects (Postgres/MySQL/SQLite/Databricks/Snowflake) behind one `Dialect` enum; Pydantic/TypeScript/JSON Schema/Rust one file each. Surfaces: GUI `src/app/dialogs/schema_export.rs`, CLI `src/cli/export_schema.rs`, MCP `export_schema`. Idents via `sanitize_ident`+`is_safe_ident`; unknown Arrow types -> TEXT + comment. Adding a target: `pub fn export(...)` + a `SchemaTarget` variant + four match arms + `SchemaTargetArg`/`Target` mirrors.
- **Chart tab** (`ViewMode::Chart` + `TabState.is_chart_tab`): pure `build_chart(...) -> Result<ChartPrep, ChartError>` in `src/data/chart.rs`. Kinds Histogram (Sturges), Bar (`ChartLimits.max_categories` default 200), Line (X-sorted), Scatter, Box (Tukey, whiskers 1.5*IQR). Axis bounds on `ChartConfig` -> `Plot::default_*_bounds`. `sample_indices` honours `ChartLimits.max_points` (Bar/Box fold full input). `cell_to_f64` coerces Date->days, DateTime->epoch secs. A *tab not a view mode*: `open_chart_tab` clones into a fresh `TabState`; `available_view_modes` returns `[Chart]`. Trigger Analyse -> Chart / `OpenChart` (F5). UI `src/view_modes/chart.rs`; export `src/data/chart_export.rs` (SVG -> `resvg` PNG / `svg2pdf` PDF). Deps: egui_plot 0.35, svg2pdf 0.13.
- **Formula diagnostics**: `evaluate_formula_with_diagnostics` returns `FormulaOutcome { value, bad_cell }`; non-numeric/Date/DateTime/Binary/Bool/Nested -> `Err(FormulaBadCell)` (first bad cell short-circuits). `add_column.rs` shows a `Formula skipped N of M...` banner.
- **Date/Time calculation**: pure `octa::data::time_calc` — `evaluate_cell(op, &CellValue[, &CellValue])` for `TimeCalcOp::{Difference, AddSubtract, ConvertDuration, Extract}` (parse via `date_infer`, chrono arithmetic; month/year add clamps the day). **Edit -> Date/Time calculation...** -> `src/app/dialogs/time_calc.rs`, materialising a new column.
- **Summary tab**: **Analyse -> Summary...** -> `OctaApp::open_describe_tab` (`src/app/tabs.rs`): snapshots the active table (`apply_edits`), then `octa::data::summary::build_summary_table(&snap, &settings.summary_stats)`. Pure module `src/data/summary.rs`: `SummaryStat` (strum `EnumIter`, `column_id`/`i18n_key`/`hint_key`/`is_mandatory`; ColumnName+Type always shown). **Output headers are `column_id()` snake_case identifiers** (machine-friendly, never localized - `i18n_key`/`hint_key` are the localized label/tooltip, shown via `TableViewState.header_tooltips` + Settings labels). One `SUMMARIZE data` pass; NotNull/Null derived from `count`+`null_percentage` (DuckDB `count` is *total* rows, not non-null), Unique/DistinctRatio from an exact `COUNT(DISTINCT)` pass (`exact_distinct_counts`; SUMMARIZE's `approx_unique` is HyperLogLog and can exceed row count), TotalRows=`row_count`. Range=max-min, Iqr=q75-q25 derived; Sum/TextLenMin/TextLenMax from one extra aggregate (`extra_aggregates`), Mode/ModeCount from a per-column GROUP BY (`mode_values`) - both gated on the stat being enabled so a minimal Summary stays one query. Settings `summary_stats: Vec<SummaryStat>` (default full set). Detached tab labelled `summary.tab_label` via `custom_tab_label`. **Cells are typed, not stringified**: `num_cell`/`typed_cell` store each statistic as the tightest `CellValue` (whole -> `Int`, decimal -> `Float` rounded to 6dp to kill float noise, text -> `String`), then a post-build `infer_column_type` pass sets each column's `data_type` from its cells. So numeric columns render through the table view's normal numeric path (grouped, right-aligned) and Save/export keep clean numbers. MCP `profile` stays raw-SUMMARIZE JSON (decoupled). Column Inspector is gone (superseded by Summary).
- **Data validation**: pure `octa::data::validation` — `ValidationRule { column: Option<usize>, kind: ValidationKind }`, `ValidationKind` (NotNull/Range{min,max}/Regex/Unique/MaxLength; one-variant-per-rule), `violations(table, rules) -> HashSet<(row,col)>`. Session-only `TabState.validation_rules`; the violation set is cached in `TabState.validation_violations`, recomputed in `recompute_filter` (like `search_cell_matches`) and threaded through `draw_table` -> `rows.rs`, painting failing cells `MarkColor::Red` via the same `.or_else` chain conditional formatting uses (manual marks + conditional colours win). Dialog `src/app/dialogs/validation.rs` (**Data -> Data validation...**, `ToolbarAction.open_validation` -> `show_validation`); live (any change sets `filter_dirty`); Range/MaxLength text fields buffer in egui temp memory. i18n `dialog.val_*` + `[validation_kind]` (reuses `dialog.cnf_*` for add/clear/remove/any-column).
- **Clean-up suggestions** (`src/data/cleanup.rs` pure engine + `src/app/cleanup_panel.rs` bottom panel, GUI-only): scans the active table and returns a ranked `Vec<Suggestion{kind,column,affected,severity,detail,examples}>`. **Adds no detection of its own** - every kind translates an existing engine (`scan_pii`, `detect_outliers`, `find_duplicate_rows`, the `trim` check, `can_convert_column`); a second detector would drift from the one Apply runs. `CleanupLimits` (100k rows, 0.90 type ratio, 0.05 null ratio, 0.5 PII confidence). `examples` carries up to 3 real offending values, **deterministic** - outlier coords are sorted before bucketing because `detect_outliers` returns a `HashSet`. One outlier pass over all columns, not one per column. **No setting and no Scan button**: opening the panel starts the scan, nothing runs while it is closed. Worker thread + polled `Arc<Mutex<..>>` slots, modelled on `multi_search.rs`. `apply_cleanup -> bool`: direct fixes (trim / cast / drop empty column / clean headers / dedupe) go through the same undoable paths the menu entries use and return `true` -> **automatic rescan** (a dropped column renumbers later suggestions); impute / outliers / anonymise open their dialog pre-filled and return `false`. Trim and clean-headers use `table.set` / `rename_column` + `coalesce_undo_since` so one Ctrl+Z reverts them - the load-time passes write directly and are NOT undoable, hence `trim::planned_header_names`. i18n `[cleanup]` + `analyse_menu.cleanup`; shortcut `OpenCleanupPanel` UNBOUND.
- **European number parsing** (`src/data/num_parse.rs`, pure): `1.234,56` and `3,14` are text to every reader because Rust's `parse::<f64>()` only accepts the bare English form. `classify_value` decides per **value** (Certain(European|English) / Ambiguous / NotNumeric), `infer_column` per **column** - never per cell, because a lone `1,234` is genuinely undecidable. Two guards: grouping must be groups of exactly three digits (which is what keeps `31.12.2024` out), and the GUI pass runs **after** date inference. Wired in twice on purpose, because the GUI and the headless surfaces have different read entry points: `formats::read_table_auto` calls `promote_certain_columns` (CLI/MCP/batch-convert; ambiguous columns stay text, nobody to ask), and `file_io/passes.rs::run_number_inference_pass` calls `promote_columns_with_snapshot` (GUI; banner with Okay/Dismiss mirroring the date banner's `original_values` revert, plus `pending_number_pickers` -> `dialogs/number_ambiguity.rs`). `can_convert_value`/`convert_value` route their Int64/Float64 arms through `parse_number_relaxed` (plain English first, so no existing behaviour changed). i18n `[dialog] num_*` + `[banner] numbers_*`.
- **File internals** (`src/data/file_internals.rs`, pure): the *physical* shape of a file as opposed to its data - `FileInternals { facts, chunks, hints }`. Parquet reports row groups, codec, encodings, per-column statistics, writer/created-by and bloom filters; other formats report size only (an answer, not an error). Up to three derived hints (tiny row groups, no statistics, no compression). Surfaces: **Analyse -> File internals...** (detached tab, facts + hints in the tab banner), `--describe FILE --deep` (facts as `key\tvalue`, hints on **stderr** so a pipe stays parseable), MCP `describe_file(deep: true)` -> `internals` object. Gotchas found the hard way: `ColumnChunkMetaData::encodings()` returns an **iterator**, not a slice, and `set_max_row_group_size` is deprecated for `set_max_row_group_row_count(Some(n))`.
- **Problem navigation** (`src/data/problem_nav.rs`, pure): F10 / Shift+F10 step through the cells other engines already flagged (`validation_violations` + `outlier_cells`, both cached on the tab), in display order, wrapping, skipping rows the filter hides. Computes nothing, only orders. Status bar shows `Problem 3 of 27`. Sibling of `record::next_record_index` by design.
- **Fuzzy join** (`src/data/fuzzy_join.rs`): joins on "similar to" rather than "equals", for tables naming the same thing differently (`Mueller GmbH` vs `Mueller Gmbh.`); `join.rs` only knows `=`/`<`/`<=`/`>`/`>=`. **Writes no new similarity maths**: `fuzzy_duplicates::similarity` is now `pub` and this engine calls it, with the same `NormalizeOpts` and the same blocking idea. `fuzzy_join(tables, steps, cancel)` folds left to right, `steps.len() == tables.len()-1`; each left row keeps ONE partner (highest score, ties to first occurrence) and the output gains `match_score_N` + `ambiguous_N` **per step** (a bad match early propagates, so one collapsed number would hide it). `AMBIGUITY_MARGIN` 0.05 is fixed, not a knob; a runner-up below the step threshold does NOT flag (the threshold is the user's own statement of what counts). Right/Full append unmatched right rows AFTER the left-driven ones. Surfaces: GUI `dialogs/fuzzy_join.rs` (**Data -> Fuzzy join...**, beside Join tables, N steps, worker + polled slot, `ShortcutAction::OpenFuzzyJoin` UNBOUND), CLI `--fuzzy-join` (+`--fuzzy-join-file/-on/-method/-threshold/-block/-join-type/-max-rows`; flags bundled in `cli::fuzzy_join::Args`, `Action::FuzzyJoin` boxed and in `main.rs`'s positional allowlist), MCP `fuzzy_join` (read-only; response carries `steps`). i18n `[fuzzy_join]` + `fuzzy_join.menu`. Ceilings: text comparison only, one partner per left row, `max_rows` per side without blocking, no accept/reject review.
- **HTML profiling report** (`src/data/report.rs`): one self-contained document (inline CSS, inline SVG, no JavaScript, nothing fetched) with four sections - `ReportSection::{Stats,Distributions,TopValues,Correlation}`. **Invents no analysis**: statistics from `summary::build_summary_table`, top values from `value_frequency`, the matrix from `correlation`, the pictures from `chart` + `chart_export::to_svg`, so a report cannot drift from what the tab shows. `build_report(table, filtered_rows, opts, cancel)` follows the caller's filter, and **sampling draws from that view, not the whole table** (a filtered report must not examine rows the filter hides). Everything user-supplied goes through `esc()`; a cancelled build errors rather than returning half a document. Distributions caps at `max_charted_columns` (50) and states the omission; a categorical column charts as `Aggregation::Count`; correlation is skipped below **two** numeric columns. Surfaces: GUI `dialogs/report.rs` (**File -> Report...**, beside Export schema, worker + polled slot, done-state offers **Open in browser**, `ShortcutAction::OpenReport` UNBOUND), CLI `--report OUT.html FILE` (+`--report-sections`, `--report-sample`; input is positional so `Action::Report` is in `main.rs`'s allowlist; an unknown section name is an error), MCP `create_report` (**write** tool: in `WRITE_TOOL_NAMES`, `remove_route`d under `--mcp-read-only`, `out_path` via `resolve_write_path`). i18n `[report]` + `file_menu.report`.
- **Schema drift** (`src/data/schema_drift.rs`): which files in a folder disagree about their columns. `analyse`/`report_table` are pure (they take already-read schemas); `collect_schemas(dir, recursive, registry)` is the shared walk, in the library because all three surfaces need it. Files are grouped by an exact schema **fingerprint**, not compared pairwise: the useful answer for 500 parts is "497 look like this, 3 look like that", so variants come back largest first. Backed by a new defaulted `FormatReader::read_schema` (default body = `read_file()?.columns`; Parquet reads its footer, Arrow IPC its header, pinned to agree with a full read by `tests/read_schema_tests.rs`). `DriftReport.ignore_case` carries the scan's folding so `report_table` groups names the same way, else a folded scan with 2+ variants splits one column across two rows. Surfaces: GUI `dialogs/schema_drift.rs` (**File -> Schema drift...**, beside Batch convert, or a folder's sidebar **Scan schemas...**; worker thread + polled slot, `ShortcutAction::OpenSchemaDrift` UNBOUND), CLI `--schema-drift DIR` (+ the shared `--recursive`, `--ignore-case`; **exits 1 on drift** like `--validate-schema`, report on stdout and file lists/skips on stderr), MCP `schema_drift` (read-only, kept under `--mcp-read-only`). i18n `[drift]` + `file_menu.schema_drift`. Ceilings: local paths, first table of a multi-table source, depth 8.
- **Timezone conversion** (`TimeCalcOp::ConvertTimezone { from: Tz, to: Tz }` in `src/data/time_calc.rs`): the sixth Date/Time calculation op. **`chrono-tz` is a direct dependency pinned at `0.10`** and was already in the tree via orc-rust, so it adds no crates; `Tz` is `Copy` with manual `Debug`/`Display`/`FromStr`, which is why the variant can hold it without breaking `TimeCalcOp`'s derives. Octa datetimes are `Timestamp(Microsecond, None)`, always naive, so the source zone is stated not detected - note `parquet_reader.rs:495` destructures `Timestamp(unit, _tz)` and **discards** any zone the file carried, which is a pre-existing fidelity gap deliberately left alone. `convert_timezone_column(values, from, to) -> (Vec<CellValue>, usize)` exists separately from `evaluate_cell` because the latter's `Option` cannot distinguish DST-ambiguous from not-a-datetime, and **both DST edges (autumn overlap, spring gap) yield null and are counted** rather than guessed. The dialog's apply path routes this op through the column helper and reads the source column *before* `insert_column`. GUI only, matching the feature (no CLI flag, no MCP tool). i18n `dialog.tc_tz_*`.
- **Mojibake repair** (`src/data/mojibake.rs`, pure): text decoded with the wrong character set then stored as valid UTF-8 (`MÃ¼ller` for `Müller`), invisible to `data::encoding` which only chooses an encoding at *read* time. `repair` is a **verified round-trip, never a guess**: encode back through `encoding_rs::WINDOWS_1252` (NOT a `ch as u8` Latin-1 cast - cp1252's 0x80..=0x9F maps above U+00FF, and a Latin-1 cast rejects exactly the common cases), refuse on `had_errors`, decode as UTF-8, and accept only if it decodes cleanly and no signature survives. Two surfaces: `CleanupKind::Mojibake` in the Clean-up panel (applied directly, `coalesce_undo_since`) and `TransformOp::RepairEncoding`. **No CLI or MCP surface** - the Clean-up panel is GUI-only and `transform_columns` does rename/cast/drop. i18n `cleanup.kind_mojibake`/`action_mojibake` + `transform_op.repair_encoding`.
- **Join diagnostics** (`src/data/join_diag.rs`, pure): why a join returns too few rows. Counts distinct keys per side, samples unmatched values, and names the one normalisation that would help (`FixKind` Trim/IgnoreCase/CollapseWhitespace/StripPunctuation/StripLeadingZeros), each computed by recomputing the same containment count through `fuzzy_duplicates::normalize` - **no new string maths**. A fix is reported only when it **strictly** beats the current count, so an empty list is a real answer. `values()` deliberately does NOT trim: the baseline must reflect what a real join does, or `TrimWhitespace` could never fire. Surfaces mirror its sibling `join_keys` exactly: `dialogs/join_diag.rs` (**Analyse -> Join diagnostics...**, synchronous like join_keys, "Use in Join" prefills the Join dialog) + MCP `diagnose_join` (read-only), **no CLI flag and no shortcut**, because join_keys has neither. i18n `[joindiag]`.
- **Schema harmonisation** (`src/data/harmonise.rs`): the write half of `schema_drift`, shaped like `batch_convert` (`plan_harmonise` decides everything before `run_harmonise` does anything). **Output goes to a new folder; originals are never touched**, and `--out-dir` is required. **A file whose values will not survive a cast is refused, never written with nulls in place of them** (`DataTable::can_convert_column`), because a harmonised folder of silently emptied cells looks clean and is not. Extra columns are dropped and named per file in the report + shown in the dialog's plan phase before the user commits. Two inputs colliding on an output name refuse **both** - deliberately NOT `batch_convert`'s `_2` suffix, which would paper over exactly the ambiguity that matters here. `HarmoniseOptions.root` exists because `collect_schemas` labels files by *name* for a flat scan and by *path* for a recursive one. Surfaces: `dialogs/harmonise.rs` (**File -> Harmonise schemas...** + a **Harmonise...** button in the drift dialog carrying folder/options across; two-phase Plan then Run, both on workers), CLI `--harmonise-schema DIR --out-dir DIR` (**exits 1 on any refusal**), MCP `harmonise_schemas` (**write** tool, refuses `out_dir == dir`). i18n `[harmonise]`. Ceilings: local paths, first table of a multi-table source, sequential, schema-level only.
- **Data drift** (`src/data/drift.rs`, pure): has this dataset changed shape since last time? `compare_profiles(a, b, opts) -> DriftReport` matches columns **by name** (one-sided columns go to `added_columns`/`removed_columns` and get no metric rows, because a zero baseline would breach every threshold) and reports `rows`, `null_rate`, `distinct_count`, numeric `min`/`max`/`mean`, and `new_values`/`vanished_values` for columns under `category_cap` (50). **Computes no statistic of its own**: every number is read out of one `summary::build_summary_table` call per side, so the report and the Summary tab cannot disagree (that also means `null_percent` is 0-100 and is divided by 100 here). `parse_thresholds("null_rate:0.05,rows:0.1")` builds the gates; a **zero baseline that moved at all counts as an unbounded change**, which is the only reading that makes 0.0 -> 0.5 fail. Surfaces: `dialogs/drift.rs` (**Analyse -> Data drift...**, two sides each an open tab or a file, worker + polled slot, result into a detached tab), CLI `--drift-report A B [--fail-on SPEC]` (**exits 1 only on a breached gate**, joining the early-return block), MCP `data_drift` (read-only). The result tab sets `table_state.header_tooltips` (the Summary mechanism) since its headers are machine ids; `change` is **relative** ((after-before)/before) and a zero baseline that moved at all is unbounded. i18n `[datadrift]` (NOT `[drift]`, which schema-drift already owns); `ShortcutAction::OpenDataDrift` UNBOUND.
- **Validation rules as a file** (`src/data/validation/rules_file.rs`): `validation.rs` became a dir-module so the rule set can be saved beside the data and re-run in CI. Rules are stored **by column name**, never index, because a rules file outlives the table it was written from; `resolve(file, columns)` returns the resolved rules **plus what it could not find**, and every surface treats a non-empty problem list as a failure. Surfaces: Save rules.../Load rules... in `dialogs/validation.rs` (the message rides in egui temp memory, the dialog has no state struct of its own), CLI `--check FILE --rules FILE` (**exits 1 on a violation AND on an unrunnable rule**), MCP `check_rules` (read-only; `passed` is false whenever `unknown` is non-empty). `violations()` answers for a whole rule set at once, so attributing a failing cell to its rule means calling it once per rule: N scans, fine for a gate, engine untouched. i18n `[rules]`.
- **Relationship map** (`src/data/rel_map.rs`): the picture over `join_keys::suggest_keys`. `build_map(tables, opts) -> RelMap{nodes, edges}` keeps candidates above `min_score` and adds the orphan counts, **copied off the `KeyCandidate` rather than recomputed** (the ranking already measured the pair from the same sample with the same scorer; a second read could only produce a number to disagree with). The orphan count is the tie-break value overlap cannot do: when both tables number rows from 1, `customers.id -> orders.id` and `customers.id -> orders.customer_id` both score 1.00 and only the orphans separate them. **Counted BOTH ways round** (`left_orphans`/`left_distinct_values` and `right_orphans`/`right_distinct_values`, all four born in `join_keys::PairScore`) because only the direction read from the *child* side settles such a tie and nothing in the scorer knows which side that is: with 4 customers and 1000 orders the customers side reads 0 for both candidates and the orders side reads 996 and 0. Reporting one direction made the tie-break work or not depending on tab/filename order, which was a real bug found while documenting it (2026-08-23); the fix is one extra subtraction in `score_pair` plus carrying it to the finder list, the map tooltip (`relmap.edge_direction`, rendered once per direction), the CLI columns and both MCP responses. `a_tie_is_broken_from_the_child_side_whichever_way_round_it_is_read` pins it. **score = overlap x distinctness of the more distinct side** (which is what stops a `status` column that overlaps perfectly from outranking a real key), and `min_score` (0.50) is a **slider in the dialog** (unstepped `Slider` with `show_value(false)` + an editable field parsed by `parse_score`, which takes either decimal mark and clamps: the built-in value box is a `DragValue`, whose horizontal-resize cursor reads as a window edge - same reason `find_fuzzy_duplicates` does it), applied on the next Scan since it gates the comparison itself. `collect_tables(dir, ..)` is the IO half, capped at `DEFAULT_MAX_FILES` 30. Surfaces: `dialogs/rel_map.rs` (**Analyse -> Relationship map...**; boxes AND the per-edge score chips are hand-drawn into ONE allocated painter and interacted with via `ui.interact` - never `egui::Area`, see the custom title bar note. Chips are `click_and_drag`: click prefills the Join dialog, drag **bends the whole edge**. The chip is the curve's handle - `RelMapState.chip_offsets` holds its offset from the straight midpoint (index-parallel to `map.edges`, `ZERO` = straight) and the edge draws as a `QuadraticBezierShape` whose control point is `2*chip - straight_mid`, since a quadratic's t=0.5 point is `(a + 2c + b)/4`, so the curve passes through the chip. Two earlier shapes were wrong: a free offset with a leader line back (the leader reads as a second connection) and sliding along the line (the line itself never moved)), CLI `--relationships DIR` (always exits 0, a report not a gate), and `suggest_join_keys`, which gained the two orphan fields instead of a tool of its own. i18n `[relmap]`; `ShortcutAction::OpenRelMap` UNBOUND. **Boxes fold at `MAX_LISTED_COLS` (12) and the `+N`/`-N` row is a click target** (`RelMapState.expanded`, cleared by `apply_map` since node indices belong to one map): registered AFTER the box's drag `ui.interact` so it wins the click, and click-only vs drag-only means dragging the box by that row still works. `listed_cols` threads through `node_height`/`anchor`, so expanding MOVES a line from the clamped last row to the column it actually names.
- **Relationship map export** (`src/data/rel_map_export.rs`, pure): PDF (default) / PNG / SVG / interactive HTML, **all four through one hand-emitted SVG** exactly like `chart_export`, whose `to_png`/`to_pdf` this reuses (and whose `escape_xml` is now `pub(crate)`) - never a screenshot, so no window-size or DPI variance. **This module computes NO geometry**: `dialogs/rel_map.rs::build_layout` hands it a finished `MapLayout` built from the same `edge_geometry`/`node_height`/`listed_cols` the painter uses (map space, i.e. screen minus the painter origin) plus `edge_tooltip`, so an exported line cannot land where the drawn one did not and the SVG `<title>` says what the hover said. `MapColors` is read off the live `Visuals`, so the export matches the running theme. The **HTML** export is one self-contained file (no fetch, no library): it re-runs `anchor` in JavaScript to re-route lines while boxes are dragged, which is why `EdgeLine` carries table/column indices, and `geometry_json` emits the chip's **offset from the straight midpoint, not its position** - the midpoint moves when a box moves, so an absolute point would straighten the curve on the first drag. Format persists in `AppSettings.rel_map_export_format` (the picker beside the button IS the settings UI; the footer row pins `spacing.interact_size.y` to the button height, since a ComboBox sizes off `interact_size` and a Button off its text, so the row steps otherwise - same fix as `chart::control_row`). **The HTML `<svg>` is `width/height="100%"` with NO `viewBox`, and pan/zoom moves an inner `<g id="octa-view">`, never the element**: an `<svg>` clips to its own viewport, so at intrinsic size a box dragged past the drawing's bounds vanished, stopped being hit-testable, and the next grab there panned the whole picture - one bug, both symptoms, found by driving the file in Chromium. No viewBox keeps 1 user unit = 1 CSS px so a dragged box tracks the pointer at any zoom; the background rect sits OUTSIDE the stage group or panning drags the backdrop away; the toolbar is `pointer-events:none` (button `auto`) so it cannot swallow a drag. `SvgMode::{Standalone,Embedded}` is the split - the standalone file MUST keep its intrinsic size and viewBox or the PDF comes out blank. Ceilings: HTML has no chip-bending, no Join click-through, no Measure.
- **Join key finder** (`src/data/join_keys.rs`, pure): ranks cross-table column pairs by containment weighted by distinctness, which is what stops a `status` column that happens to overlap from outranking `cust_id -> id`. Built for N tables (all pairings). Surfaces: `dialogs/join_keys.rs` (**Analyse -> Join key finder...**; "Use in Join" prefills the existing Join dialog rather than joining itself) and MCP `suggest_join_keys` (read-only). Ceilings: sampled (`DEFAULT_SAMPLE_ROWS` 10k), single columns only, values compared as trimmed text.
- **Batch convert** (`src/data/batch_convert.rs`: pure `plan_batch` + `run_batch` + `report_table`): N files -> one target format in one run. **`plan_batch` decides everything that can fail before any work starts** - output names, stem collisions between two inputs (`_2`, `_3` in input order, so a run cannot overwrite its own earlier output), existing outputs (skipped unless `overwrite`), and an unwritable target. The writability probe checks `all_extensions().contains(ext)` **and** `supports_write()`: `reader_for_path` falls back to the Text reader for anything unknown, which is right for opening and wrong for a write target. `run_batch` never aborts on one bad file; `progress(done, total)` per item, `cancel` checked before each. Reads via `read_table_auto` so `.gz`/`.zst` need no extra code. **Ceilings: local paths only, first table only for multi-table inputs, sequential.** Surfaces: GUI `src/app/dialogs/batch_convert.rs` (sidebar multi-select -> `TreeAction.convert_files`, or **File -> Batch convert...**; worker + `Arc` slots drained by `drain_batch_convert` -> report tab), CLI `--batch-convert --to EXT --out-dir DIR` (**returns `ExitCode`**, joining `--validate-schema` in dispatch's early-return block, because a partly failed run is a successful read with exit 1; headerless `input\toutput\tstatus` on stdout, errors + summary on stderr), MCP `batch_convert` (**write** tool). i18n `[batch]`; shortcut `OpenBatchConvert` UNBOUND.
- **Time bucketing + rolling windows** (`src/data/timeseries.rs` pure builders, in the shape of `pivot.rs`): `build_resample_sql` (`date_trunc` buckets by `Interval` minute..year, `TimeAgg` sum/mean/min/max/count/first/last, optional extra `group_by`) and `build_rolling_sql` (`agg(v) OVER (PARTITION BY .. ORDER BY t ROWS BETWEEN n-1 PRECEDING AND CURRENT ROW)`), plus `explain_*` sentences. Execute nothing - the GUI dialog, CLI and MCP tools all run the string through `octa::sql::run_query`, so the three surfaces cannot diverge. **`TRY_CAST` not `CAST`** on the time column (one unparseable row buckets as NULL instead of failing the query); `ORDER BY` on the window is mandatory; the bucket column dodges a collision (`bucket` -> `bucket_2`); `Interval::parse`/`TimeAgg::parse` back the CLI words. Surfaces: GUI `src/app/dialogs/timeseries.rs` (**Analyse -> Time series...**, bounded preview cached on a `preview_key` hash exactly like `pivot.rs`, date-typed columns first via `col_combo_ordered`, result into a detached tab), CLI `--resample`/`--rolling` (`--partition-by-cols` is spelled long because `--partition-by` is the split-into-files action; **both are in `main.rs`'s positional-FILE allowlist** or they warn about their own input), MCP `resample_timeseries`/`rolling_window`. Shared dialog widgets live in `src/app/dialogs/widgets.rs` (`col_combo`/`col_combo_ordered`/`multi_col_picker`/`render_preview_grid` + the `PREVIEW_*` caps) - `render_preview_grid` takes an id prefix because two of these dialogs can be open at once and hardcoded egui ids collide. i18n `[timeseries]`; shortcut `OpenTimeseries` UNBOUND.
- **Data-ops batch** (engines `src/data/{dedupe,impute,outliers,pii,union,join,partition}.rs`, each = pure engine + GUI dialog + CLI flag + MCP tool): **Drop duplicate rows** (`dedupe_rows`, Data menu, Ctrl+Shift+H, in-place + coalesced undo), **Fill missing values** (`impute_column`, Data menu, in-place + coalesced undo), **Union tables** (`plan_union`/`union_tables`, Data menu, reconciliation plan -> new tab; `plan_union(schemas, ignore_case)` folds column-name case and the flag rides on `UnionPlan` so `union_tables` matches names the same way it grouped them - GUI checkbox, CLI `--union-ignore-case`, MCP `ignore_case`, off by default), **Join tables** (Data menu, Ctrl+Shift+Q, new tab; **GUI uses `join_two`** - 2-table, left+right tab + N conditions `left_col <op> right_col` (`JoinOp` Eq/Lt/Le/Gt/Ge), columns/types need not match (TRY_CAST both sides to DOUBLE if both numeric else VARCHAR); CLI/MCP keep `join_tables` = N-way shared-name `USING` equi-join), **Partition by column** (`partition_table`, Data menu, Ctrl+Shift+Z, writes N files via `rfd::pick_folder`), **Detect outliers** (`detect_outliers` IQR/ZScore, Analyse; `OutlierOutput::Highlight` flags session-only `TabState.outlier_cells` painted `MarkColor::Orange` via the `rows.rs` `.or_else` chain (lowest precedence, **Clear highlight** button), or `NewColumn` materialises a boolean `is_outlier` column (undoable)), **Detect PII** (`scan_pii`/`suggested_anon_rules`, Analyse, read-only; `ColumnPii{kind,confidence,by_name,value_match}` scores header keywords + value patterns per kind (12 `PiiKind`s, `PiiKind::id()` for CLI/MCP), report >=0.5; `require_name` kinds (Name/Country/BirthDate/PostalCode/Address) need the header; **Send to Anonymise** seeds `AnonymizeState`). Union/Join opened from the menu show a `union.need_open` toast when <2 tabs (no silent no-op). **Shortcut note**: several ship `KeyCombo::UNBOUND` because every clipboard-safe Ctrl+Shift letter is taken and Ctrl+Shift+C/X/V fire egui-winit `Event::Copy/Cut/Paste` (matches `command && key`, ignoring Shift) on the table; Ctrl+Alt risks AltGr. i18n `[outliers]`/`[outlier_method]`/`[pii]`/`[pii_kind]` (32 locales).
- **Transform column**: OpenRefine-style column shaping. Pure ops in `src/data/transform/` (one file per op, `mod.rs` re-exports): `split_column`/`SplitSpec` (Delimiter/Regex/FixedWidth -> N new cols), `merge_columns`, `fill_down`/`fill_up`, `extract_pattern` (compiled `&Regex`, first capture or whole match), `replace_in_column` (reuses `search::RowMatcher` + a new `RowMatcher::replace_all`). - **Duplicate column names**: `rename_map::plan_dedupe(columns, ignore_case) -> Vec<(idx, old, new)>` numbers repeats (`id`, `id_2`, `id_3`), skipping any suffix another column already owns so `a`, `a`, `a_2` renames only the middle one. It lives beside `plan_renames` but returns **indices**, because that module's other half addresses a column by name and a name is the one thing that cannot pick out a duplicate - which is also why this could not be folded into the mapping text.
