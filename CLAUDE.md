## Commands

cargo run -- file.parquet

## Installation

`sudo ./install.sh` for system-wide on Linux, `./install.sh ~/.local` for user-local. On Windows: `install.bat` (system-wide, admin; bundled in the release zip) or `install.ps1` (per-user, no admin; run standalone from the repo root, NOT shipped in the zip since it downloads the zip itself) — the PowerShell script downloads the latest release, verifies the SHA256 against `SHA256SUMS`, installs into `%LOCALAPPDATA%\Programs\Octa`, and `Unblock-File`s the binary to dodge SmartScreen. Linux build needs `libgtk-3-dev libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev libxkbcommon-dev libssl-dev libfontconfig1-dev libfreetype6-dev`.

## CI Pipeline

PRs to `master` run four jobs: `test` (fmt + clippy + cargo test, one shared `Swatinem/rust-cache@v2` target dir), `licenses` (`cargo deny check licenses`), `megalinter` (shell/security/markdown via `ghcr.io/oxsecurity/megalinter-rust:v9`), and `db-live`. Clippy/rustfmt live in `test`, not megalinter (no Rust cache there, ~1000s/PR). **`megalinter` runs first and hard-gates `test`** (`test.needs: [changes, megalinter]`): a lint failure skips the Rust job instead of burning ~15 min of compute. `licenses` stays parallel (`needs: [changes]`).

**`db-live`** (`needs: [changes, test]`, `if: needs.changes.outputs.db == 'true'`) runs `tests/db_live_tests.rs` against **Postgres 17 + MySQL 8 service containers**. Gated on a `db` paths filter (`src/db/**`, `tests/db_live_tests.rs`) because standing up two servers is only worth it when the connectors change; gated on `test` so it never boots a database for code that does not compile, and so `Swatinem/rust-cache` (`shared-key: build` on both jobs, `save-if: false` here) restores `test`'s warm target dir instead of doing a cold build. No MSSQL: the image is ~1.5 GB and slow to go healthy, and the job already has to reclaim ~20 GB of preinstalled runner toolchains to fit the build. The step **greps the log for `skipped: OCTA_TEST_(POSTGRES|MYSQL)_URL` and fails the job on a hit** - the suite passes as green no-ops when an env var is missing, so without that guard a typo would produce a passing job that connected to nothing. The tests create and drop their own databases, hence the `postgres` / `root` superuser accounts.

`release.yml` (`workflow_dispatch`) intentionally does **not** re-run `cargo test` (PR CI already validated the merged commit). Jobs: `build-linux` (+ AppImage), `build-windows`, `build-macos` (aarch64 only — no Intel/x86_64 build; that job was dropped as too slow), `publish` (needs all builds), `aur-publish`, and `docker-publish` (runs **in parallel** with the builds, no `needs:` — the Dockerfile builds from source so it never depended on the release artifacts; `docker/*` actions pinned to their first Node.js 24 majors — login@v4, metadata@v6, build-push@v7 — so no `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24` opt-in is needed).

One boolean input gates the publishing half: **`build_only` (default false) skips `publish` and `docker-publish`**, and `aur-publish` inherits the skip through `needs: [publish]`; the three build jobs still run, so a `build_only` dispatch produces every artifact without cutting a public release. Before it, any dispatch shipped to GitHub Releases, AUR and ghcr at once, with no way to test a build. There is **no Store publishing in CI**: the `store-publish` job and its `publish_to_store` input were removed, since the Partner Center credentials they needed are unobtainable on this account (see `windows/STORE_SETUP.md`) and `windows/build-msix.sh` packs a Store MSIX locally instead.

## CLI

`octa` is **flag-driven**, not subcommand-driven: pick one of `--schema`, `--head`, `--tail`, `--sample`, `--convert`, `--sql`, `--export-schema` (`-e`), `--compare-schemas`, `--diff`, `--describe`, `--validate-schema`, `--unique-columns`, `--anonymize`, `--dedupe`, `--impute`, `--outliers`, `--detect-pii`, `--union`, `--join`, `--partition-by`, `--resample`, `--rolling`, `--batch-convert`, `--mcp` (mutually exclusive via clap `group = "action"`); with none, launches the GUI with the positional file list. Implemented in `src/cli/`, one file per action. Global `-f / --format {tsv|json|csv}` (default tsv) routes through `src/cli/output.rs`; `--convert`, `--export-schema` and `--partition-by` ignore it (the last prints a bare `path\trows` listing of the files it wrote, headerless, straight from `println!` - deliberately not a data table). `--export-schema` picks a target via `-t / --target` (`SchemaTargetArg` → `octa::data::schema_export::SchemaTarget`). `disable_help_flag = true` + a custom `--help` (`ArgAction::HelpLong`) makes `-h`/`--help` identical.

`--validate-schema` returns exit `1` on a successful read where schemas drift (CI gating); `cli::dispatch` pulls it out of the normal `Result → ExitCode` mapping so `validate_schema::run` returns `Result<ExitCode, _>`. `--mcp` does **not** route through `cli::dispatch`: `main.rs::run_mcp` peels it off first so GUI/CLI paths never build a tokio runtime.

`--diff` takes a `--diff-mode {set|ordered|join}` (default `set`) + `--diff-on COLS` (comma list, required for `join`). `set` is the original whole-row membership diff (`octa::data::diff::diff_rows`); `ordered`/`join` route through `octa::data::compare` (`compare_ordered` positional row-by-row cell diff; `compare_join` key-matched added/removed/changed). `compare::build_compare_table` renders the shared output table (leading `status` + `changed_columns`). `compare::subset` is reused by the MCP tool.

`--describe` grew `--deep` (physical layout, see File internals below); `--diff` grew `--diff-db CONN --diff-db-table SCHEMA.TABLE`, which replaces the second positional file with a live table (`--diff` is `num_args = 1..=2` for that reason, `detect_action` enforces which count each form needs); `--convert` and `--batch-convert` grew `--compression CODEC` (validated at parse time against `write_options::PARQUET_CODECS`) and `--row-group-size N`.

Man page source `docs/cli/octa.1.adoc`; the release renders/bundles `octa.1` (install.sh falls back to rendering); mkdocs mirrors it at `docs/cli/man-page.md`.

A positional FILE may be a cloud object URL (see Cloud URL as a path below); read-only from the CLI.

Global `--rows N|all` overrides the streaming initial-load cap for one run (`cli::parse_rows_flag`; `all` → `usize::MAX`); `cli::dispatch` installs an `octa::formats::InitialLoadRowsGuard`.

`--sql` workspace flags: `--sql-table NAME=PATH` (repeatable) adds workspace tables; `--sql-attach ALIAS=PATH` ATTACHes a DuckDB/SQLite file (`alias.schema.tbl`); `--sql-write-to PATH` + `--sql-write-table TABLE` (+ optional `--sql-write-schema`, `--sql-write-mode {create|append|replace}`) persists the SELECT instead of printing. `src/cli/sql.rs` builds + tears down a fresh `SqlWorkspace` per invocation.

Data-ops actions (engines in `src/data/<name>.rs`, all also GUI dialogs + MCP tools): `--dedupe` (+`--dedupe-on/-keep`), `--impute COL=STRATEGY` (mean/median/mode/ffill/bfill/`const:VALUE`), `--outliers` (+`--outlier-method/-cols/-k`, prints flagged cell coords), `--detect-pii` (+`--pii-sample`), `--union` (+`--union-file/-drop/-cast`), `--join` (+`--join-file/-on/-type`), `--partition-by COL` (+`--out-dir` required, `--partition-format`, writes N files). `tests/dedupe_cli_tests.rs` covers `--dedupe`.

Adding an action: append a flag to `cli::Cli`, add an `Action` variant, drop `src/cli/<verb>.rs`, extend `Cli::detect_action`, add a `cli::dispatch` arm.

## MCP server

`octa --mcp` runs a stdio JSON-RPC server (rmcp 1 + tokio current-thread). `src/mcp/`, one file per tool under `tools/`. `--mcp-read-only` (clap `requires = "mcp"`) threads a `read_only` bool through `run_mcp` -> `mcp::run` -> `OctaMcpServer::new(.., read_only)`, which `tool_router.remove_route`s `write_table`/`edit_table`/`convert`/`transform_columns`/`anonymize`/`partition_table`/`write_db_table`/`copy_db_table` (read-only surface for agent frameworks; `mcp::read_only_tests` covers it). Tools: `read_table`, `tail`, `sample`, `schema`, `list_tables`, `count_rows`, `run_sql`, `convert`, `export_schema`, `profile`, `find_duplicates`, `value_frequency`, `search`, `compare_schemas`, `diff_tables`, `describe_file`, `validate_against_schema`, `unique_columns`, `suggest_join_keys`, `pivot`, `correlation`, `grep_files`, `list_objects`, `write_table`, `edit_table`, `transform_columns`, `anonymize`, `detect_pii`, `detect_outliers`, `fill_missing`, `drop_duplicates`, `union_tables`, `join_tables`, `partition_table`, `resample_timeseries`, `rolling_window`, `batch_convert`, `list_db_connections`, `list_db_tables`, `query_db`, `write_db_table`, `copy_db_table`. The data-ops tools wrap `src/data/{dedupe,impute,outliers,pii,union,join,partition}.rs`; row-returning ones (`drop_duplicates`/`fill_missing`/`union_tables`/`join_tables`) reuse `table_to_json`, analytics ones (`detect_outliers`/`detect_pii`) emit custom `json!`, `partition_table` is the only data-ops *write* tool (one file per group; removed under `--mcp-read-only`). Most are thin wrappers over pure `src/data/` functions; `profile` wraps `run_query(table, "SUMMARIZE data")`; row-returning tools reuse `tools::table_to_json`. `pivot`/`correlation`/`grep_files` are read-only analytics (kept under `--mcp-read-only`); `pivot` builds DuckDB PIVOT/UNPIVOT via the shared `octa::data::pivot` (same builders as the GUI dialog), `correlation` wraps `octa::data::correlation` (Pearson/Spearman over numeric cols), `grep_files` mirrors the GUI Multi-search directory scope (`octa::data::multi_search` + `read_sorted_dir`). `transform_columns` is the write tool `edit_table` is not: rename/cast/drop columns then write back (order: drop, rename, cast). `validate_against_schema` wraps `compare_schemas` after `parse_json_schema` (Timestamp normalises to `Timestamp(Microsecond, None)` — JSON Schema can't carry the unit/tz tuple).

- Tool descriptions are string literals at the `#[tool(description = ...)]` site (rmcp's macro rejects a `const`).
- `schemars` pinned to `1` (matches rmcp's re-export; 0.8 breaks `Parameters<T>`).
- `get_info` uses `Implementation::new("octa", env!("CARGO_PKG_VERSION"))`, **not** `Implementation::from_build_env()` — the latter's `env!` macros expand inside the rmcp crate, so the server introduced itself to every client as `rmcp 2.2.0`. `tests/mcp_smoke_tests.rs` asserts `serverInfo.name == "octa"`.
- Caps: `mcp_default_row_limit: Option<usize>` (default `Some(1000)`, `None`=unlimited), `mcp_default_cell_bytes: usize` (default 65536, `0`=no cap). Per-call `limit` `Some(0)`=unlimited; `unlimited: bool` installs an `InitialLoadRowsGuard` in `spawn_blocking` to lift the file cap (`limit` only slices the response). Responses surface `truncated`/`total_rows_available`/`cell_truncated`; oversized cells get a `[truncated: N bytes; ...]` marker.
- Settings read **once at startup**; defaults duplicated literally in `src/ui/settings.rs::{default_mcp_row_limit, default_mcp_cell_bytes}` (settings are library, `src/mcp/` is binary).
- Blocking work on `spawn_blocking`; `run_mcp` installs `tracing_subscriber` to stderr (stdout is JSON-RPC) and prints a ready banner.

Adding a tool: drop `src/mcp/tools/foo.rs` with a `Params` struct + `pub async fn handle(...)`, register in `tools/mod.rs`, add a wrapper method on `OctaMcpServer` with `#[tool(description = "...")]`.

**Cloud URLs (Plan 5).** Read tools accept a cloud URL (`s3://`/`az://`/`gs://`) as `path`: `ToolContext::resolve` detects it via `octa::cloud::parse_cloud_url`, downloads to a temp file (`cloud_fetch_to_temp`, `tmp.keep()` leak), and reads it through the registry. `list_objects` (`src/mcp/tools/list_objects.rs`, read-only, kept under `--mcp-read-only`) lists one bucket level by URL. Creds: `ToolContext.cloud_settings: Option<AppSettings>` (None for MCP/CLI -> ephemeral connection + `resolve_ambient_creds`; Some for chat -> matches a saved `cloud_connections` by kind+bucket then `resolve_creds`, resolved lazily on the worker so the aws-CLI shell-out stays off the UI thread). `CloudConnection` carries `allow_writes: bool` (`serde(default)` = **false**, secure by default - existing saved connections need re-opting in after upgrade; checked IN ADDITION to the global `cloud_writes_enabled` - both must allow; GUI gate `OctaApp::cloud_tab_writable` covers save/save_tab/auto-save/upload, chat gate in `resolve_write_dest` after `resolve_cloud`; MCP ephemeral connections default writable, its gate stays `--mcp-read-only`), `prefix: Option<String>` (confine to a key prefix in a bucket) and `account_level: bool` (browse all buckets/containers; `bucket` empty); `CloudConnection::covers(&CloudLocation)` matches exact bucket / prefix-contained / any-bucket-same-kind. Account-level bucket enumeration is `cloud::list_account_buckets` (CLI shell-out: aws/az/gcloud). The sidebar browser roots a prefix-scoped connection at its prefix and lists buckets for an account-level one (per-bucket provider via `cloud_browser::bind_bucket`, keys re-qualified `<bucket>/<key>`). MCP/chat `resolve_cloud` matches via `covers` and binds an account-level connection to the URL's bucket. Settings cloud form has a scope checkbox + prefix field. Chat sandbox: an unsaved bucket is rejected when `restrict_filesystem` (assistant only reaches saved connections); MCP allows any bucket via ambient creds. Azure ephemeral needs `AZURE_STORAGE_ACCOUNT` (an `az://` URL can't carry the account). Cloud tools flow into the Assistant automatically via `define_chat_tools!`. **Cloud WRITES**: write tools (`write_table`/`convert`/`transform_columns`/`anonymize`/`run_sql write_to`/`create_chart`/`write_text`) accept a cloud-URL target via `ToolContext::resolve_write_dest` (returns a `WriteDest` = local path OR temp file + provider; `WriteDest::finish()` uploads the temp on success, `is_cloud()` skips local-only steps like backups). Gating mirrors reads: chat needs `cloud_writes_enabled` (the manual-Save switch) + a saved connection; MCP (no settings) uses ambient creds for any bucket (gate is `--mcp-read-only`, which drops the write tools). `write_table` to cloud is overwrite-only (the temp has no existing-object semantics). `resolve_write_path` stays the local-path/sandbox helper (no longer rejects cloud URLs).

`run_sql` mirrors `--sql`: `extra_tables: Vec<{name, path, table?}>` (name sanitised via `sanitize_sql_name`), `attach: Vec<{alias, path}>`, `write_to: Option<{path, schema?, table, mode, create_schema_if_missing?}>` (response becomes `{kind:"write_back", rows_written, created_schema, target}`). Fresh `SqlWorkspace` per call.

`diff_tables` mirrors `--diff`: `mode: Option<String>` (`set` default / `ordered` / `join`) + `on: Option<Vec<String>>` (join keys). `set` keeps the original `only_in_a`/`only_in_b` + `shared_keys`; `ordered`/`join` add `changed_a`/`changed_b` (the differing rows, parallel order), a `changed` array (`{row_a, row_b, changed_columns}` per pair), and `changed_count`/`unchanged_count`. Dispatches to `octa::data::compare`.

`write_table` / `edit_table` are the data-write tools (distinct from `convert` and `run_sql write_to`). Both reuse the registry `write_file` + inverse-of-`table_to_json` helpers in `tools/mod.rs`: `cell_from_json(value, arrow_type)`, `build_data_table(columns, rows)`. `write_table` takes inline `columns` (name + optional Arrow `type`, default `Utf8`) + array-of-arrays `rows`, writes any *file* format by extension; `mode` is `create`/`overwrite`/`append` (append needs matching column names). DB files rejected (their `write_file` needs `db_meta`). `edit_table` edits an existing file in place: `set` (cells; `col` is index or name), `insert_rows` (`at` defaults to append), `delete_rows` (highest-index-first), then `apply_edits()` + `write_file()` (so SQLite/DuckDB keep diff-based saves). No column changes.

**tiberius is patched to a fork** (`[patch.crates-io]` at the bottom of `Cargo.toml`, pinned by commit to `thorstenfoltz/tiberius`). Upstream's last release is 0.12.3 (July 2024) and its `main` still pins tokio-rustls 0.24 -> rustls 0.21 -> rustls-webpki 0.101, an EOL line unpatched against GHSA-82j2-j2ch-gfr8 / -xgp8-3hg3-c2mh / -965h-392x-2mh5. tiberius was the **only** crate left on that stack, so the binary carried two complete rustls stacks; the patch removed 8 packages from the lock. The fork is one commit migrating the TLS stream to tokio-rustls 0.26 / rustls 0.23 / rustls-webpki 0.103. Two deliberate choices in it: the crypto provider is named **`ring`** (rustls 0.23 refuses to pick one when several are compiled in, and `object_store` pulls aws-lc-rs alongside our ring) to match `rustls_client_config`; and TLS is **pinned to 1.2**, because TDS tunnels the handshake inside TDS packets and the driver never processes post-handshake TLS 1.3 records, so a KeyUpdate surfaces as `UnexpectedEof` mid-session. That is not a downgrade: upstream advertises TLS 1.3 and then breaks if a server negotiates it, and SQL Server only offers 1.3 over TDS 8.0 strict encryption, which tiberius does not implement. Drop the patch once tiberius releases on tokio-rustls 0.26+. `deny.toml` needs the matching `[sources] allow-git` entry. `mssql_session_encryption_live` asserts `sys.dm_exec_connections.encrypt_option = TRUE` — a silently-degraded TLS stack would still connect and still pass every other MSSQL test, so that is the one that catches it (the whole session is encrypted, not just the login: tiberius' `Config::default()` is `EncryptionLevel::Required` whenever a TLS feature is on, and `trust_cert()` disables certificate *validation*, not encryption).

**Connection cache** `src/app/db_conn_cache.rs` (`DbConnCache`, `OctaApp.db_conn_cache`, cleared on Settings apply): `Arc<Mutex<HashMap<conn_id, Arc<Mutex<Box<dyn DbConnector>>>>>>` + injectable `connect_fn` test seam. `with_conn(conn, secret, f)` = get-or-connect; a CACHED connector whose `f` fails is dropped, reconnected once, retried once (heals dead TCP; fresh-connect failures surface as-is). Wired into sidebar listing/table-open workers, the SQL server-mode worker (via `get_or_connect` + `lock_connector` — NO auto-retry there: a user cancel must not silently re-run the statement; failure just `invalidate`s), the SQL write-back dialog, and the db write-back worker. One connector per id serialises same-connection ops (ponytail ceiling: small pool if it matters).

## Chatbot (in-GUI assistant)

A docked chat panel (`src/app/chat_panel/`, a dir-module: `mod.rs` = panel shell + body/header/messages/input; `controls.rs` = profile/Ollama/context-chip row; `windows.rs` = prompts + history windows; `session.rs` = session lifecycle + `send_chat_message`; `context.rs` = `build_tool_context` + edit drain; `helpers.rs` = render/format free fns. App-level like SQL) where an LLM drives Octa's tools in an agentic loop over the open tabs/files. Toggle via toolbar **Analyse -> Assistant**, **View** menu, or `ShortcutAction::ToggleChatPanel` (default `Ctrl+Shift+A`); header has a close [x]. GUI-only. The input row's `@`-mention autocomplete consumes Up/Down/Enter/Tab keys **before** the multiline `TextEdit` renders (mirrors the SQL editor; the editor would otherwise eat them) — Enter accepts a suggestion while the popup is open, sends otherwise. **Saved prompts**: `src/app/chat_prompts.rs` (`ChatPrompt`, `<config_dir>/chat_prompts.json`), `OctaApp.chat_prompts` + `chat_prompt_save: Option<ChatPromptDraft>`, naming dialog `src/app/dialogs/chat_prompt.rs`. **Prompts** button opens a manager **window** (`render_prompts_window`, standard `DialogSize` chrome via `ChatPanelState.prompts_window_open`/`prompts_window_size`): save-current / Insert / delete. The chat **History** window also uses the standard chrome now (`session_list_size`). i18n `chat.prompt_*`/`chat.prompts_hint` + `dialog.prompt_*`.

Core reuse lever: each MCP tool's work lives in `pub fn run(ctx: &ToolContext, p: &Params) -> anyhow::Result<Value>` (`src/mcp/tools/<name>.rs`); the MCP `handle` is a thin `server.tool_context()` -> `spawn_blocking(run)` wrapper, and the chat layer calls the **same** `run`. `ToolContext`/`Source`/`TableSnapshot`/`source_from` live in `src/mcp/tools/mod.rs`; `resolve(&Source)` reads via `read_with_registry` or clones an open-tab snapshot. Single-source tools' `Params` carry `open_tab: Option<String>` (`"@active"`, a tab name, or absent->`path`); compare/diff carry `open_tab_a`/`open_tab_b`; `write_table`/`edit_table` reject an `open_tab` target. `path` fields are `#[serde(default)]`.

**Filesystem sandbox (chat only).** `ToolContext` carries `restrict_filesystem` + `allowed_read_paths` (canonical open-tab paths) + `export_dir`; `for_mcp` leaves them off. `build_tool_context` (`chat_panel/context.rs`) sets them for chat: reads confined to open tabs (`ensure_readable`); a multi-table file is fully reachable once any sheet is open. Writes go through `resolve_write_path` (bare name -> `export_dir`; absolute path honoured). `TableSnapshot.handle` (`#1`...) addresses same-named tabs; `snapshot_for_pathish(s)` matches handle/name/filename (gated on `table.is_none()` so sibling-sheet reads still hit disk). `run_sql.extra_tables` resolve open tabs (`add_table` + `TableOrigin::TabClone`); `run_sql.write_to` also writes plain file formats. Chat-only tool `create_chart` (`src/mcp/tools/create_chart.rs`, in `define_chat_tools!`, no MCP `handle`) reuses `octa::data::chart::build_chart` + `chart_export`.

**Non-tabular files.** Text/code/Markdown files load as a single `Line` column. Chat-only tools `read_text` (joins the `Line` column into the file's text — captures in-memory edits) and `write_text` (writes content to a new file in `export_dir`, an absolute path, or back to an open tab's file on disk via `open_tab`; the live editor does **not** refresh — the user reloads). Both live in `src/mcp/tools/{read_text,write_text}.rs` (no MCP `handle`). The system prompt (`src/app/chat/mod.rs::build_system_prompt`) tells the model to use these for prose/code.

Module layout under `src/app/chat/`:
- `types.rs` - `Role` / `ContentBlock {Text|ToolUse|ToolResult}` / `Message` / `ChatEvent` / `StopReason` / `ToolDef`.
- `tools.rs` - `define_chat_tools!` builds **both** `tool_defs()` (schemas from `schemars::schema_for!(Params)`, `$schema`/`title` stripped) and `dispatch(ctx, name, args)` from one list. Descriptions come from a `pub const DESCRIPTION` per tool module.
- `providers/` - one file per backend (`anthropic`, `openai`, `openai_compat`/`ollama`, `gemini`) behind `trait ChatProvider`. **OpenAI proper streams via the Responses API** (`openai_responses.rs`, `/v1/responses`): gpt-5.x 400s on `reasoning_effort` + function tools at chat/completions. `build_responses_body` sends `store:false` + (with reasoning) `include:["reasoning.encrypted_content"]`, FLAT tools `{type:"function",name,...,strict:false}` (strict must be explicit false — Responses defaults strict on and schemars schemas don't satisfy it), `instructions` = system, `max_output_tokens`; reasoning = effort **word** (numeric -> local error), and temperature is OMITTED while reasoning is set. Reasoning items stream back as `ChatEvent::ProviderData` -> `ContentBlock::ProviderData{provider,data}` (serde-additive) and are replayed verbatim before their turn's `function_call` items (gpt-5.x rejects a replayed function_call without its paired reasoning item); other providers' wire mappers filter the variant out. `handle_event` is a pure per-SSE-event fn (no `[DONE]` sentinel; `response.output_item.done` carries complete function_call arguments so the argument deltas are ignored). `agent.rs` accumulates an ordered `raw_blocks: Vec<ContentBlock>` (ToolUse + ProviderData in event order); dispatch iterates ToolUse only. `openai.rs` keeps the chat/completions helpers (`run_openai`/`build_body`/`messages_to_wire`) for `openai_compat`/`ollama`, which stay on that endpoint. `ProviderConfig.max_tokens: Option<usize>` (None=omit field; Anthropic substitutes a high value); compat/ollama emit `max_tokens` via `build_body`'s `token_field`. `gemini.rs::to_gemini_schema` sanitises schemars JSON Schema to Gemini's OpenAPI subset (resolve `$ref`, `Option`/`anyOf`->`nullable`, drop `additionalProperties`/`$schema`/`$defs`/`default`/`title`) else Gemini 400s. `stream_sse` extracts `error.message` from non-2xx bodies. Ollama is first-class: keyless `ChatProviderKind::Ollama`, `chat_ollama_url`, `src/app/chat/ollama.rs` (`is_running`/`list_models` via `/api/tags`; `start_server` spawns `ollama serve` in its own process group via `pre_exec(setsid)` so `stop_child_group` kills server + `llama-server` child; `stop_local_server` pkills for the unowned case; needs the `libc` unix dep). Panel worker threads do the model dropdown + Refresh/Start/Stop + ~5s status poll; Octa-started server killed on `OctaApp::on_exit`. SSE over blocking `ureq` (`json`) on a `std::thread`; `stream_sse` configures an `Agent` and uses `into_reader()` (not `read_to_string`, which defeats streaming). Providers assemble tool calls fully before emitting `ChatEvent::ToolCall`.
- `session.rs` - `ChatSessionState` (messages, `streaming`, `running`/`cancel` `Arc<AtomicBool>`, error) behind `Arc<Mutex<..>>`.
- `agent.rs` - `spawn_turn` runs on a `std::thread` holding only a cloned `egui::Context` + `Arc<Mutex<state>>` + a moved `ToolContext` (never borrows `TabState`). Loops up to `chat_max_tool_iterations`: stream -> commit -> dispatch tool calls (capped by `truncate_for_model`, 100 KB) -> append -> repeat. Per-turn `cancel`/`running` are fresh `Arc`s installed by `send_chat_message`; `cancel_chat` flips cancel and clears state; the worker's finally only clears shared state when `Arc::ptr_eq` confirms it's still the active turn.
- `persist.rs` - one pretty JSON per session under `<config_dir>/chat_sessions/`; autosaved per turn (debounced) and on new/load.
- `audit.rs` - opt-in tool-call audit log (`chat_audit_log_enabled`, off by default): each tool call appends one JSON line (`AuditEntry`: tool, args/result bytes, duration, is_error, ts) to `<config_dir>/chat_audit/<session_id>.jsonl`. `TurnRequest.audit_session: Option<String>` (set in `send_chat_message` from the session id when enabled) gates recording in `agent.rs`'s dispatch loop. Startup size warning: `OctaApp::new` sums `audit::total_size_bytes()`, sets `status_message` when `> chat_audit_log_warn_bytes` (default 10 MB) and `chat_audit_log_warn_enabled`. i18n `chat.audit_*`, `settings_hint.chat_audit_*`.
- `secrets` - in the library at `src/ui/settings/secrets.rs` (re-exported `crate::app::chat::secrets`). Per-provider keys, precedence **env -> keyring -> plaintext settings.toml**; `set_api_key` reports keyring-vs-fallback, `storage_location` reports the source. **Linux keyring = freedesktop Secret Service**, pure-Rust zbus. `keyring = "4"` is a single plain dep (no per-OS `[target.'cfg(..)']` blocks): its default `v1` feature picks `zbus-secret-service-keyring-store` on Linux (declared upstream with `crypto-rust`, so no libdbus and no OpenSSL), `apple-native` on macOS and `windows-native` on Windows, and `v1::Entry::new` registers the store itself on first call.

**Model profiles** (`src/ui/settings/chat_profiles.rs`, library-side since `AppSettings` is): `ChatModelProfile { id, name, description, kind, model, temperature, reasoning, base_url, use_own_key, allow_writes }` — an arbitrary `Vec` of named provider+model+params setups, several per provider allowed. **`allow_writes` (default false) REPLACES the global `write_protection` for the chat surface** (that switch keeps governing GUI file saves + the MCP startup default): `send_chat_message` passes it into `build_tool_context` (`allow_existing_writes`/`allow_schema_changes`/`read_only: !allow`) and `tools::tool_defs_for(allow)` (filters `WRITE_TOOL_NAMES` out of the advertised list; `dispatch` also refuses them on a `read_only` ctx, and `run_sql write_to` gates itself — that also closed the `--mcp-read-only` hole). The legacy-migration seed inherits `!write_protection`; profiles created later default read-only. The edit drain gate is `is_readonly() || !active_profile(..).allow_writes`. `build_system_prompt(tab_summaries, allow_writes)` swaps the write-tool guidance for an explicit READ-ONLY paragraph when writes are off (else the model speculates about "missing tool bindings" instead of naming the profile switch). `AppSettings.chat_profiles: Vec<ChatModelProfile>` + `chat_active_profile: String` (the id). `ensure_profiles(&mut settings)` runs in `AppSettings::load` (wrapping `load_raw`, so *every* path incl. parse-failure gets one) and on Settings-apply: seeds one profile from the legacy `chat_provider`/`chat_models`/`chat_temperature`/`chat_base_url`/`chat_ollama_url` fields (which stay as migration source + fallback) and re-points a dangling active id. `active_profile(&settings)` is the accessor the panel/`send_chat_message` use. `id` is minted once via `fresh_id` and frozen (it names the keyring entry). Panel header = one profile dropdown (+ **Profiles...** -> Settings); Ollama keeps its server controls + discovered-model list in the panel, writing the pick back into the active profile (`set_active_profile_model`). The **Ollama server URL stays global** (the probe/start/stop target); a profile's `base_url` overrides it per request.

**Thinking/reasoning**: `ProviderConfig.reasoning: Option<String>` (free text, empty = omit). OpenAI -> Responses `reasoning.effort` (word; numeric -> local error; temperature omitted while set); compat/Ollama -> `reasoning_effort` via the shared `build_body`; `anthropic.rs` -> `parse_thinking_budget` (numeric token budget; a word like `high` is a **local error** since Anthropic has no effort field) then `thinking.budget_tokens` + forces `temperature: 1` + lifts `max_tokens` above the budget (both API requirements) — `build_body` therefore returns `Result<Value, String>` and `stream_turn` `?`s it; `gemini.rs` -> numeric `thinkingConfig.thinkingBudget`.

**Keys** (`src/ui/settings/secrets.rs`) are now **id-based**: `get_key_for/set_key_for/delete_key_for/key_storage_for(key_id, env_var, ..)`. Two id spaces: provider (`kind.id()`, shared by every profile of that provider, env-var backed) and profile (`profile_key_id(id)` = **`profile.<id>`** — namespaced so a profile named "Anthropic" can't clobber the shared `anthropic` key; no env var). `get_api_key`/`set_api_key`/... and `get_profile_key`/`set_profile_key`/... are thin wrappers. A profile resolves its key via `chat_panel::profile_api_key` (own key iff `use_own_key`, else shared).

Settings live in the **main Settings dialog** (`src/ui/settings/dialog.rs`, "Chat / Assistant" `CollapsingHeader`); the panel's Settings button opens it via `settings_dialog.focus_chat_section` (+ one-shot `focus_chat_profiles`). The big sections use nested sub-`CollapsingHeader`s to separate per-instance from global config: Chat = "Model profiles" / "Global options" (`chat_global_options_grid`) / "API keys" (`chat_api_keys_body`), Databases + Cloud = connection list up front with the add/edit form behind a `settings.sub_conn_form` sub-header `.open(Some(true))`-forced while a row is being edited (cloud also via one-shot `focus_cloud_form` from the sidebar "+ Add"). The profile list + add/edit form is `src/ui/settings/dialog/chat_section.rs` (`chat_profiles_section`), backed by `chat_profile_form_*` buffers on `SettingsDialog`. `chat_*` fields in `src/ui/settings/mod.rs`: `chat_profiles`, `chat_active_profile`, legacy `chat_provider`, `chat_models: BTreeMap` per-provider, `chat_base_url`, `chat_ollama_url`, `chat_panel_position`, `chat_temperature` (default **0.0**), `chat_max_tool_iterations`, `chat_max_tokens` (default 16384) + `chat_max_tokens_unlimited`, `chat_export_dir` (default ~/Downloads), `chat_api_keys: BTreeMap`. Numeric settings use comma-tolerant text buffers. Chat tool context caps: `chat_result_row_limit` rows (default 200, user-configurable in Settings; `chat_result_row_limit_unlimited` checkbox -> `ToolContext.default_row_limit = None`, mirrors `chat_max_tokens`/`_unlimited`), 4 KiB/cell (`CHAT_CELL_CAP`). `table_to_json` adds a `note` to truncated results telling the model to write the full result to a file/tab and not to add a SQL `LIMIT`; the system prompt reinforces it. Chat UI strings under `[chat]` in every locale. The **Clear API key** button arms a confirmation (`chat_key_clear_confirm: Option<ChatProviderKind>`) — a second explicit click calls `secrets::delete_api_key`.

**Provider/model presets** are a hand-editable runtime `models.toml` beside `settings.toml` (`src/ui/settings/chat_models.rs`): `preset_models(kind)` / `default_model(kind)` read it, seeded from the `ChatProviderKind` consts and auto-written on first run; `reload()` re-reads (wired to a Settings "Reload models.toml" button). **Report AI content** (`src/app/dialogs/ai_report.rs`, `OctaApp.show_ai_report_dialog`): a Microsoft Store certification requirement, not a product idea — a product that *presents* generative-AI output must offer an in-product way to report it, and the Assistant panel renders model text even though Octa ships no model and runs no inference. Rationale + the resubmission checklist in `windows/STORE_SETUP.md`.

Adding a provider: drop `src/app/chat/providers/<name>.rs` impl `ChatProvider`, add a `ChatProviderKind` variant + `make_provider` arm + a `report_url` arm. Adding a tool: free once the MCP tool has `run` + `DESCRIPTION` and is in `define_chat_tools!`.

## Performance settings

- `initial_load_rows` (default **5M**) caps the first streaming batch. Process-wide `AtomicUsize` (`src/formats/mod.rs::INITIAL_LOAD_ROWS`); `set_initial_load_rows` runs from `OctaApp::new`, Settings apply, and `run_mcp`. `InitialLoadRowsGuard` is an RAII override for CLI `--rows` / MCP `unlimited` (safe: CLI single-threaded, MCP current-thread runtime). `initial_load_rows_unlimited` overrides to `usize::MAX`.
- Single-table reads of files >= `BACKGROUND_LOAD_MIN_BYTES` (8 MB, `src/app/file_io/`) run on a worker thread (`OctaApp.pending_load`, polled by `drive_pending_load` in the update loop, applied via `finish_single_load`); the status-bar spinner shows "Loading file..." and the open-queue waits for the in-flight load. Multi-table sources (Excel/DB) stay synchronous; files < 8 MB load inline.
- `syntax_highlight_max_bytes` (default 1024 KB) gates the raw editor's syntect pass; Settings exposes a Bytes/KB/MB unit picker.
- `text_mode_extensions: Vec<String>` forces unknown extensions through `TextReader` (checked in `load_file` before registry lookup; lowercased, dot-stripped; unioned into the picker's "All Supported").
- `thousands_separators_in_cells` (default **on**) + `number_separator_style: SeparatorStyle` (English/European) group numeric cells display-only via `src/ui/table_view/rows.rs` -> `octa::data::num_format::format_cell_number` (never touches saved/exported/CLI/MCP output).
- `excel_max_auto_sheets` (default **5**) caps auto-opened Excel sheets; above it `load_file` raises `pending_sheet_picker`.
- `trim_whitespace_on_load` (default **off**) + `warn_on_whitespace_trim` (default **on**) drive the load-time whitespace pass; `offer_repair_on_malformed` (default **off**) the repair prompt; `language` (default `"en"`) drives `octa::i18n`.

## Microsoft Store

Published as **Octa Data Viewer** (the name "Octa" was taken), Store ID `9PF9BVRT9PX4`, listing https://apps.microsoft.com/detail/9PF9BVRT9PX4. Submitted manually (`windows/build-msix.sh` -> Partner Center); the docs point Windows users there first since the Store-signed build skips SmartScreen. Full runbook `windows/STORE_SETUP.md`. Two local scripts do the work that CI otherwise would:

- **`windows/build-msix.sh`** packs a Store MSIX from a *published GitHub release*, on Linux. Downloads the release zip, verifies it against `SHA256SUMS`, stages the payload (six `magick`-resized logos + version-substituted manifest; `release.yml` used to do this and no longer does), packs, then unpacks again to re-verify every block-map hash and `cmp`s the exe against the release binary. `makeappx.exe` is Windows-only, so it builds Microsoft's `msix-packaging` `makemsix` into `windows/.msix-tools/` on first run (~50 s; ~10 s thereafter) — that build needs **`MSIX_PACK=on`** (off by default, else the binary can only unpack) and a **C++14 -> C++17 bump in two `CMakeLists.txt`** (the bundled pin fails against modern system ICU headers). Output `windows/octa-<ver>.0.msix`, unsigned (correct: the Store signs, after certification passes). Both output and tool cache are gitignored. `OCTA_MSIX_TEST=1` builds `-test-unsigned.msix` instead: same payload plus `OID.2.25.311729368913984317654407730594956997722=1` in `Identity/Publisher`, which is what Windows 11 demands before `Add-AppxPackage -AllowUnsigned` will take an unsigned package. Sideload-test only - the OID is part of the package identity, so that build must never reach Partner Center.
- **`scripts/build-store-listing.py`** fills the Partner Center listing CSV. Partner Center exports one CSV with a `default` column plus one column per language **detected in the uploaded package** (hence the 32 `<Resource Language>` entries in `AppxManifest.xml`); blank language cells inherit `default`, so one English screenshot set and one English fallback text cover all 32 - which is also why the script **blanks** a language cell for any field `_default.toml` owns (an export comes back with `OverrideLogosForWin10 = False` filled into all 32 columns, and a filled cell beats `default`). Content lives in `docs/assets/store/listings/<code>.toml` (31 files, each written natively rather than translated and addressing the reader informally; `en-us` inherits `_default.toml`; a bare export column falls back to the single script variant, `sr` -> `sr-cyrl.toml`). Images: six screenshots reused from `docs/assets/screenshots/` plus three Store logos (`store-tile-300x300.png` rose, `-150x150` emerald, `-71x71` blue, the last two gated on `OverrideLogosForWin10`). It drops the Xbox/Holographic/SurfaceHub/mobile rows (453 -> 225) but **never trailer rows** (deleting one deletes the asset in Partner Center), leaves `Field`/`ID`/`Type` untouched as required, resolves each referenced image from `<outdir>/shots/` -> `docs/assets/store/` -> `docs/assets/screenshots/`, and names any that are missing.

`docs/assets/store/INDEX.md` documents the assets. Store *listings* are not in the package; only the supported-language list is.

## Architecture

Native desktop GUI for tabular data, `eframe`/`egui` (immediate-mode), Rust edition 2024. Needs a C compiler (duckdb, rusqlite). The crate is both a library (`src/lib.rs` re-exports `data`, `formats`, `ui`) and a binary (`src/main.rs`); tests `use octa::data::*`.

**Renderer: `glow` (OpenGL), deliberately not eframe's default.** eframe's `default` feature selects **wgpu**, which links naga (a shader compiler), wgpu-core/-hal/-types, ash (Vulkan bindings), spirv and gpu-allocator: 23 crates and ~3.5 MB for a program that draws 2D tables and writes no shaders. `eframe` is therefore declared `default-features = false` with an explicit `["accesskit", "default_fonts", "glow", "wayland", "x11"]`. Do NOT "fix" it back to `default`. glutin covers every target: GLX+EGL on X11, EGL on Wayland, WGL on Windows, CGL on macOS (Apple's deprecated-but-present OpenGL; the fallback if that ever breaks is a per-target `[target.'cfg(target_os = "macos")']` block selecting wgpu there only).

**`winit` is a direct dependency on purpose.** eframe pins winit with `default-features = false`, and the only thing that re-enables `winit/default` is eframe's own `default` feature, which we turn off. Dropping it would silently lose `wayland-dlopen` (the binary would hard-link `libwayland-client.so` and refuse to start on X11-only machines) and `wayland-csd-adwaita` (Wayland window decorations, needed whenever `use_custom_title_bar` is off). winit is already in the tree, so the direct dep adds no crates.

Canonical format registration order: `FormatRegistry::new()` (`src/formats/mod.rs`); user-facing list `docs/getting-started/supported-formats.md` — both update together. Read-only formats (SAS, R, HDF5, NetCDF, EPUB, GeoJSON, Fixed-Width) inherit `supports_write=false`.

`TextReader` claims every highlightable source/config extension (`.py`/`.rs`/`.go`/web markup/...) so they're advertised as supported; `highlight_whitelist_is_supported` pins `HIGHLIGHT_WHITELIST` to the registry's set. `formats::filename_reader_name(file_name)` matches extension-less filename conventions (`Dockerfile`, `Dockerfile.*`, `Containerfile`, `Containerfile.*`) to the Text reader, checked in `reader_for_path` between the extension and sniff steps; a bundled `assets/Dockerfile.sublime-syntax` (loaded best-effort like Terraform/TOML) + `syntax::syntax_for_filename` highlight them; `directory_tree::file_is_listed` keeps known filenames visible in the sidebar filter. `src/formats/sniff.rs::sniff_format` does content-based detection (magic bytes + JSON/CSV probes) for missing/wrong extensions: `reader_for_path` consults it before the Text fallback, `load_file` retries via `try_content_sniff_reload`; `reader_by_name` maps a sniff result to a reader.

### Module Layout

- `src/main.rs`: app entry + root state (`OctaApp`); top-level UI orchestration.
- `src/data/mod.rs`: `DataTable`, `ColumnInfo`, `DbRowMeta` + the core row/column mutation methods. Cell edits live in a `HashMap<(row,col), CellValue>` overlay; `rows` only mutate on `apply_edits()`. `structural_changes` flags non-cell edits. `db_meta: Option<DbRowMeta>` carries DB row identity (`table_name`, `row_tags: Vec<Option<i64>>`, `original`, `original_columns`); new rows have `None` tags. Sibling files (all re-exported from `mod.rs`, so `octa::data::<Name>` paths are unchanged): `cell_value.rs` (`CellValue` + `BinaryDisplayMode` + `is_numeric_data_type`/`wildcard_to_regex`/`can_convert_value`/`convert_value`/`cmp_cell_values`), `view_enums.rs` (`ViewMode`/`MapMode`/`CompareMode`/`MarkdownLayout`/`SearchMode`/`SearchResultMode`), `marks.rs` (`MarkColor`/`MarkKey` + the mark methods), `undo.rs` (`UndoAction` + `undo`/`redo`/`coalesce_undo_since`). `src/app/state/` is likewise a dir-module: `mod.rs` holds the two core structs (`OctaApp`, `TabState`) + origin markers; `dialogs.rs` holds the ~30 small per-dialog/pipeline state structs (re-exported, so `crate::app::state::<Name>` is unchanged).
- `src/data/search.rs`: `RowMatcher` (Plain/Wildcard/Regex search-filter-replace). `RowMatcher::with_options(query, mode, case_sensitive, whole_word)` adds the search-bar `Aa`/whole-word toggles (routes through a `RegexBuilder` when either is on; `\b...\b` for whole-word). Per-tab `TabState.search_case_sensitive`/`search_whole_word`/`search_scope_col` (session) feed `tab.search_matcher()`; the search-bar scope dropdown (`Some(col)`=one column / `None`=all) gates the column range in `recompute_filter` + `search_highlight::cell_matches(.., scope_col)`. i18n `search.{case_sensitive,whole_word,scope_all,scope_hint}`. **Persistent search history**: `OctaApp.search_history: Vec<String>` (most-recent first) persisted to `<config_dir>/search_history.json` via `src/app/search_history.rs` (`load`/`record(history, query, limit)`); `ToolbarAction.commit_search_history` fires on search-box `lost_focus`, the toolbar **Recent** dropdown recalls entries. Capped by `AppSettings.search_history_limit` (default 5, 0=off). i18n `search.{history,history_btn,history_hint}`, `settings.search_history_limit`.
- `src/data/encoding.rs`: `decode_bytes(&[u8]) -> (String, &'static str)` and `read_to_string_detected(path)` — BOM sniff, then UTF-8 fast path, then `chardetng` + `encoding_rs`. Used by `TextReader`/`MarkdownReader` so non-UTF-8 (Windows-1252/Latin-1/UTF-16) text opens. CSV keeps its own streaming path (`csv_reader` `lossy_utf8`).
- `src/formats/mod.rs`: `FormatReader` trait + `FormatRegistry`. Multi-table sources implement `list_tables`/`read_table(name)`; single-table formats fall through to `read_file`.
- `src/formats/parquet_reader.rs`: `build_arrow_array` + `data_type_from_string` map our type-name strings <-> Arrow `DataType` (update together). Native reader (parquet-58) rejects >32,767 row groups; `read_file` retries via a DuckDB path (`read_parquet` + `query_arrow`). Both honour `initial_load_rows` and strip pandas index columns via `pandas_index_columns`. **arrow/parquet are held at 58 by `duckdb` and `orc-rust`**, both of which require arrow `^58` on their latest releases *and* their main branches. That is what keeps the open `thrift 0.17` advisory (GHSA-2f9f-gq7v-9h6m, OOM on a malicious Parquet footer) unfixable: arrow-rs 59 dropped the `thrift` crate outright, so bumping to 59 would close it. Aliasing parquet 59 beside arrow 58 was considered and rejected - a third arrow copy in the binary, plus `arrow_ipc_reader.rs` and `file_io/mod.rs` both call `parquet_reader::{arrow_value_to_cell, data_type_from_string, build_arrow_array}`, and `parquet_reader.rs` would have to juggle arrow 59 from the native reader against arrow 58 from its DuckDB fallback. Recheck when duckdb-rs or orc-rust ship arrow 59.
- `src/formats/sqlite_reader.rs`: `rusqlite` (bundled); `rowid` in `db_meta.row_tags`; diff writes; schema changes rejected.
- `src/formats/duckdb_reader.rs`: `duckdb` (bundled); synthetic `__octa_row_id BIGINT` (stripped from user schema) materialised **on save only** - reading NEVER mutates the file (tags come from DuckDB's implicit `rowid`; the save-time backfill sets `__octa_row_id = rowid` so read-tags still address the same rows). Users export results to .duckdb and open them elsewhere; a counter column sprouting on open was a reported bug. Diff-on-save.
- `src/formats/spss_reader.rs`: SPSS read-only via `ambers` (needs arrow ^57; pinned `arrow57 = { package = "arrow", version = "57" }` alongside arrow 58).
- `src/formats/{sas,stata,rds,dbf,hdf5,netcdf,geojson,epub}_reader.rs`: pure-Rust, mostly read-only. RDS = tabular subset. `geojson_reader` claims only `.geojson`. `epub_reader` uses `rbook` + `htmd` (Apache-2.0; `epub`/`html2md` crates are GPL-3.0, blocked).
- `src/formats/fwf_reader.rs`: fixed-width (`.fwf`/`.prn`), read-only. `infer_field_ranges` finds boundaries from always-blank char positions; first line is header. All Utf8. Pure `read_fwf(&str, &Path)`.
- `src/formats/numpy_reader.rs`: NumPy `.npy` (single array) + `.npz` (zip of named arrays -> multi-table via `list_tables`/`read_table`), read-only. `.npy` parsed by `npyz` (dtype dispatched on `TypeChar`+byte width -> `CellValue`); 1-D -> one `value` col, 2-D+ -> `col_N` per trailing-axis index (row-major). `.npz` unzipped with the existing `zip` crate (no `npyz` `npz` feature, avoids a second zip). Structured/record arrays rejected.
- `src/formats/{msgpack,bson}_reader.rs`: MessagePack (`rmp-serde`) + BSON (`bson`, features `serde`+`serde_json-1`), both read-only. Each decodes to `serde_json::Value` then reuses `json_reader::json_to_table` (same flattening as JSON). BSON reads concatenated documents (mongodump shape) via `Document::from_reader` over a cursor, each -> `Bson::into_relaxed_extjson`.
- `src/formats/shapefile_reader.rs`: ESRI Shapefile (`.shp` + sibling `.dbf`/`.shx`), read-only, via `shapefile` crate (feature `geo-types`). `read_with_features` mirrors geojson: leading `__geometry` WKT col + `.dbf` attribute cols (field order read from the sibling `.dbf` via `dbase::Reader` since `dbase::Record` iterates unordered; reuses dbf_reader's `field_value_to_cell`/`dbf_type_string`), plus `Vec<MapFeature>` (`geo_types::Geometry::try_from(shape)`). Wired exactly like GeoJSON: `file_io.rs` populates `tab.geojson_features` on load -> `ViewMode::Map`; `available_view_modes` + `map.rs` treat `Some("GeoJSON")|Some("Shapefile")` as geometry-from-file (no lat/lon coord picker).
- `src/formats/lakehouse_reader.rs`: Delta Lake / Apache Iceberg, read-only. **NOT in the registry** (the unit of opening is a *directory*, not an extension). `detect(dir)` -> `LakehouseKind` by marker subdir (`_delta_log/` Delta, `metadata/` Iceberg); `read_dir` runs `INSTALL/LOAD {delta|iceberg}` + `delta_scan`/`iceberg_scan` on an in-memory DuckDB conn (DESCRIBE for typed cols, reuses duckdb_reader's `duckdb_type_to_arrow`/`duckdb_value_to_cell`; honours `initial_load_rows`). Directory-open plumbing: `file_io.rs::load_file` short-circuits `path.is_dir()` -> `load_lakehouse_dir`; GUI **File -> Open table folder...** (`ToolbarAction.open_table_folder` -> `pick_folder` -> `load_file_in_new_tab`). **Extensions install over the network on first use** (then cached). i18n `file_menu.open_table_folder`(+`_hint`). **Dataset mode**: `LakehouseKind::Parts(PartsFamily{Parquet,Delimited,JsonLines})` — non-lakehouse directories are scanned recursively (depth 8) for data parts, the majority family wins (`read_dir_report` lists skipped files -> `dataset.skipped_files` banner), and DuckDB scans the **explicit file list** (never globs — DuckDB errors on no-match globs). Directory-tree context menu "Open as dataset..." (`TreeAction.open_dataset`). i18n `[dataset]`.
- `src/sql/mod.rs`: re-exports `SqlWorkspace`, `AttachKind`, `WriteTarget`, `WriteMode`, `WriteReport`, `QueryKind`, `QueryOutcome`, `sanitize_sql_name`. `run_query(table, query)` is a one-shot wrapper (fresh workspace, registers `data`, tears down).
- `src/sql/workspace.rs`: `SqlWorkspace` owns one persistent DuckDB conn + `tables` + `attachments`. API: `new`, `set_active_table` (the `data` TEMP TABLE), `add_table_from_{file,datatable}`, `attach`, `detach`, `remove_table`, `list_attached_tables`, `execute`, `write_result_to_db`. DuckDB ATTACH native for `.duckdb`/`.ddb`; SQLite tries `INSTALL/LOAD sqlite` then falls back to per-table `SqliteReader` (`alias__table`); SQLite writes always via `rusqlite`. `execute` columns all `Utf8`. Sync; MCP wraps with `spawn_blocking`.
- `src/ui/table_view.rs`: virtual renderer (scroll, resize min 60px, drag-reorder, multi-cell/row/column selection, inline edit, context menu, line breaks, binary display). Returns an `Interaction` struct; caller mutates.
- `src/ui/toolbar/` (dir module): toolbar (logo, File/Edit/View/Search/Help menus, zoom, view-mode radio, custom title-bar buttons). `mod.rs` holds `draw_toolbar` (the menu bodies are inline closures sharing its locals); `types.rs` holds the returned `ToolbarAction` struct + `ParseScope` (re-exported); `menu_button.rs` holds `top_menu_button`, which sets `ui.style_mut().wrap_mode = Extend` inside every menu so long localized item labels (de/ru/...) don't wrap onto two lines, the popup grows instead.
- `src/ui/directory_tree.rs`: sidebar browser, left/right per setting; each row a full-width `Sense::click()` rect; `read_sorted_dir` is the sole disk walker. `render_directory_tree`/`draw_dir` take `allowed_exts: Option<&HashSet<String>>` (lowercased registry extensions + `text_mode_extensions`, built in `sidebar.rs` when `directory_tree_filter_enabled`, default on): files whose extension isn't in the set (and extensionless files) are hidden; directories always shown.
- `src/ui/table_picker.rs`: modal for multi-table sources (single-table DBs auto-load). Window id `octa_table_picker_dialog_v2`; height fit-to-content up to `table_picker_visible_rows` (default 10); body/footer via `Panel::bottom` + `CentralPanel`.

### Key Design Patterns

- **Interaction structs**: UI components return plain structs; `main.rs` reads them and mutates state. No callbacks.
- **Edit overlay**: cell edits in `DataTable.edits` until `apply_edits()`; structural mutations shift edit indices atomically.
- **Lazy filter**: `filter_dirty` triggers `recompute_filter()`; `filtered_rows: Vec<usize>` maps display->data index.
- **Search: filter vs highlight**: `data::SearchResultMode {Filter, Highlight}` (default Filter; persisted `AppSettings.search_result_mode`, session override `OctaApp.search_result_mode`, search-bar toggle). `state::effective_highlight(view_mode, mode)` = `Highlight || view_is_text_or_tree` (Notebook/Raw/Markdown/Json|YamlTree always highlight). Reusable engine `src/ui/search_highlight.rs`: `apply_highlight(job, ranges, current, normal, active)` splits `LayoutJob` sections to background-paint matches (composes with any layouter), `highlight_colors(&ThemeColors)`, `cell_matches(...)`; `RowMatcher::find_ranges(text)` yields byte ranges. Per-tab `TabState.search_nav: SearchNavState {match_count, current, pending_jump: Option<NavDir>}` + `search_cell_matches`; Enter/Shift+Enter (or the `<`/`>` toolbar buttons) set `pending_jump`, the active view advances `current` and scrolls (table: `selected_cell`+scroll; text editors: `set_char_range`+`scroll_to_rect`; tree/notebook: `scroll_to_me`/offset). Highlight mode keeps all rows in `recompute_filter` (column filters still hide). `render_pulldown(ui, src, Option<&(RowMatcher, Color32)>)` carries the docs-dialog + markdown-preview highlight (None elsewhere keeps EPUB/preview unchanged).
- **Selection model**: cell click selects one; **Ctrl+click** toggles into a disjoint `selected_cells` set (first toggle promotes the prior single cell). Row-number click selects a row (Ctrl/Shift extends); header click selects a column. Copy honours the selection.
- **Tab multi-selection for Compare**: Ctrl-click a non-active tab toggles `OctaApp.tab_multi_selection`; `CompareSelectedTabs` (F9) runs with exactly one selected; `begin_compare_with_tab` clones the right side from memory (in-memory edits carry through).
- **Right-click copy**: TextEdit views (raw, SQL) show **Copy** (by selection id) + **Copy All**; non-TextEdit views keep one whole-content entry (`Label::selectable(true)` handles partial Ctrl+C).
- **Arrow navigation**: extend-selection (Ctrl+Arrow) resolved before plain arrows in `draw_table`. Jump-first/last are Ctrl+Shift+Arrow. `ScrollPageUp`/`ScrollPageDown` (Ctrl+PageUp/Down) step by `floor(area_height/row_height)` and let `scroll_row_into_view` follow. All remappable via `ShortcutAction`.
- **Zoom**: Ctrl+Plus/Minus/0, 5% steps, 25-500%; `OctaApp.zoom_percent` is transient.
- **Clipboard**: dual-path `arboard` + `TableViewState.clipboard` fallback; TSV cells, newline rows. `copy_selection_as_markdown` (`src/app/clipboard.rs`) renders the same selection as a GitHub Markdown table (header row + `md_escape` for pipes/newlines); `do_copy_markdown` -> **Edit -> Copy as Markdown table** (`ToolbarAction.copy_as_markdown`) + cell/row context menu (`TableInteraction.ctx_copy_markdown`). i18n `edit_menu.copy_markdown`(+`_hint`), `context_menu.copy_markdown`.
- **Lazy row loading**: Parquet loads `initial_load_rows` sync, then `bg_row_buffer`/`bg_loading_done`/`bg_can_load_more` background-stream (UI drains per frame).
- **Column types as strings**: `ColumnInfo.data_type` holds Arrow type names; all readers must round-trip through `data_type_from_string()`.
- **Unsaved-changes guards**: window close and file open check `is_modified() || raw_content_modified` -> Save/Don't Save/Cancel.
- **Read-only mode**: `OctaApp.readonly_mode` is a transient session flag (not persisted), F8 / **View -> Read-only mode**; every edit path funnels through `is_readonly()`. First toggle queues `ReadOnlyNotice` unless opted out. Status bar shows a plain `[Read-only]` pill.
- **JSON/YAML tree key editing**: `render_value_tree` overrides `selection.bg_fill` to a neutral; object keys renamable inline (Enter -> `json_util::rename_object_key_at_path`, rebuilds map to preserve order); array indices not. Edits flow to `tab.raw_content` via the kind's serializer.
- **Parse-error fallback**: `load_file` calls `fallback_to_raw_text` when a text-format reader errs — reloads via `TextReader`, switches to `ViewMode::Raw`, shows a dismissible `tab.parse_error_banner`. Files >500 MB skip it; binary formats never fall back.
- **Default view per file type**: `apply_loaded_table` (`file_io.rs`) overrides the Table default after parsing: `format_name == "JSON"` && `json_value.is_some()` -> `ViewMode::JsonTree`; `"YAML"` -> `ViewMode::Raw` (both close the SQL panel). JSONL/others stay Table. Hardcoded, not a setting; `available_view_modes` already offers these.
- **Open as / Reopen as (parse through a chosen reader)**: one format list (`toolbar::OPEN_AS_FORMATS` = {JSON, JSON Lines, CSV, TSV, YAML, TOML, XML, Markdown, Text}) behind two menus, for files whose extension lies (a `.log` that is really JSON). **File -> Open as ->** `<fmt>` (`ToolbarAction.open_as_files`) -> `OctaApp::open_files_as`: pick-the-format-then-the-files, `rfd` picker **unfiltered** (`All Files`) on purpose, N files -> a tab each. **View -> Reopen as ->** `<fmt>` (`ToolbarAction.open_as`, gated on `has_source_path`) -> `OctaApp::reopen_active_as`: re-reads the file already in the tab. Both funnel into `read_into_active_tab_as(path, reader_name)`, which reads via `registry.reader_by_name` **before** touching the tab (a failed parse leaves it intact), then blanks the tab's table (`DataTable::empty()` + `raw_content_modified = false`) so `apply_loaded_table` **reuses the active tab** rather than spilling into a new one, re-running the whole post-load pass (view-mode pick, JSON/YAML seeding, date inference). `tests/open_as_tests.rs::every_open_as_reader_name_resolves` pins the menu's reader names to the registry.
- **`load_file_in_new_tab` reuses a blank tab**: it pushes a placeholder tab *only* when the active tab is not blank (`col_count()==0 && raw_content.is_none() && !is_modified()`). Octa starts with one empty tab and the tab bar is hidden until a second tab exists, so unconditionally pushing left that empty tab stranded as a visible "Untitled" beside the file the user opened (cloud opens, archive-entry opens). Plain `load_file` never had the bug: `apply_loaded_table` does the same blank-tab check.
- **Text-editor drag-select autoscroll**: `view_modes::text_ops::autoscroll_while_selecting(ui, &response)` — call it **inside** the `ScrollArea` closure (it reads `ui.clip_rect()` as the viewport). egui's `TextEdit` extends its selection to the pointer but never scrolls its `ScrollArea`, so a selection could not be dragged past the visible lines. Wired into the Raw, Markdown-edit and SQL editors. `ui.scroll_with_delta` is **inverted** (negative y scrolls down).
- **Column-wide date promotion**: `run_date_inference_pass` promotes string columns all matching one date/datetime layout to `Date`/`DateTime`. Ambiguous columns queue `pending_date_pickers` (European/US/leave-as-text). Binary readers excluded.

### Write Support

Most formats write. CSV preserves its `csv_delimiter`. Excel writes via `rust_xlsxwriter` (calamine read-only); only `.xlsx` round-trips. ODS has a hand-rolled OpenDocument 1.2 writer. TOML/YAML serialize through a JSON intermediary.

**`.xlsx` formatting export** (`src/formats/xlsx_style.rs`, pure + unit-tested; the writer in `excel_reader.rs` consumes its decisions and decides nothing itself): marks, conditional colours, frozen columns and per-column number formats cross into a saved workbook. `map_rule(&CondRule) -> XlsxRule` decides per rule whether it becomes a **live** Excel rule (`Cell`/`Text`/`Blank`) or must be **`Bake`**d, i.e. painted onto the cells matching it today. Two Excel semantics force baking and are the whole reason the module exists: ordering operators over **text** (Excel collates by locale, `rule_matches` by Rust string ordering) and **case-sensitive** `Eq`/`Ne`/`Contains`/`NotContains` (Excel's `cellIs`/`containsText` are unconditionally case-insensitive, so a native rule would colour *more* cells than Octa). A live Excel rule also always overrides a cell's direct fill with no notion of list order, so the export **partitions at the first baked rule**: everything before it stays live, everything from it on is painted. Gate `WriteOptions.xlsx.include_formatting` (**default off**). Saving a tab that carries any of the four asks once anyway via `save_would_ask_about_style` -> `pending_xlsx_style_save` -> `src/app/dialogs/xlsx_style_save.rs` (forced choice, optional remember -> writes the setting); the same predicate gates `auto_save::tab_is_auto_saveable`, since auto-save must never raise a modal. **One-way**: Octa reads a styled `.xlsx` back as plain data.

### Database write semantics (SQLite / DuckDB)

DB writes are **diff-based, never overwrite**. The reader snapshots row identity (`rowid` / `__octa_row_id`) + original cells into `db_meta`. On save, in one transaction: DELETE missing tags, INSERT `None`-tag rows, UPDATE rows whose cells differ. Schema changes rejected before touching the file.

Results render a row-counter label directly above the grid (display-only, never in the data/export). Result collection (local `sql/engine.rs::execute_query` AND server connectors) stops at `initial_load_rows()`; `result_rows_label` (view_modes/sql.rs) switches the counter to `sql.result_rows_capped` when row_count sits on the cap (translated x32; hermetic test `tests/sql_result_cap_tests.rs`, own binary since the guard is process-wide). `render_sql_view` zeroes `widgets.{hovered,active}.expansion` for the whole panel - themes paint hovered widgets up to 3px larger, which reads as twitching in the dense grid. **Attached-table listings are cached** (`SqlWorkspace.attached_tables_cache`, RefCell): the panel rebuilds its workspace snapshot per frame via `workspace_snapshot`, and for Postgres/MySQL attachments an uncached `list_attached_tables` is a remote information_schema query - two attached servers made the editor unusable. Cache dropped on `detach` + `invalidate_attached_cache()` (the panel's [refresh]); remote attachments also skip the per-table `COUNT(*)` entirely (`row_count: None` - on InnoDB COUNT(*) is a table scan). **History** dropdown: per-tab session `TabState.sql_history` (recorded by `record_sql_history` in `run_workspace_query`, cap 30); `SqlAction.recall_query` loads one back. **Snippets** button (`SqlAction.open_snippets_window`) opens a manager **window** `src/app/dialogs/sql_snippets_window.rs` (standard DialogSize chrome, app-level `OctaApp.sql_snippets_window_open`/`_size`) with save-current/Insert/delete; persistent `OctaApp.sql_snippets: Vec<SqlSnippet>` (`src/app/sql_snippets.rs`, `<config_dir>/sql_snippets.json`, name+description+query); naming dialog `src/app/dialogs/sql_snippet.rs`; `SqlAction.{insert_snippet,save_snippet,delete_snippet}` still exist (History recall reuses none). Save flow: `save_snippet` -> `OctaApp.sql_snippet_save: Option<SqlSnippetDraft>` -> `src/app/dialogs/sql_snippet.rs` (name+desc form). i18n `sql.{history,snippets,snippet_*}`, `dialog.snip_*`. **Row-diff highlight after mutation** (`sql_row_diff_highlight_enabled` default on + `sql_row_diff_highlight_secs` default 4): `apply_sql_diff_highlight` diffs pre/post via `compare::compare_ordered`, marks changed cells (Cell) + new rows (Row) green on the mutated table, stores keys in `TabState.sql_diff_marks` + expiry `sql_diff_highlight_until`; `OctaApp::expire_sql_diff_highlights` (per frame in `update_loop`) clears them when the timer elapses. i18n `settings.sql_diff_{highlight,secs}`.

### Keyboard shortcuts

`src/ui/shortcuts.rs`: `ShortcutAction` (strum `EnumIter`) + `default_combo`/`label`/`group` (all exhaustive matches), `Shortcuts { bindings: HashMap }` persisted in `AppSettings`. ### Auto-Update

Toolbar checker. `ureq` HTTP, `flate2`/`tar`/`zip` extraction. Logic in `src/app/update_check/` (+ `src/ui/toolbar.rs` for the Help entry). `check_for_updates` GETs `releases/latest` on a thread; pure `parse_release(body) -> (version, notes)` (unit-tested) pulls the `v`-stripped `tag_name` plus the release body, which GitHub omits for a release published without a description.

**Startup check + release notes.** Two settings, both default **on**: `check_updates_on_start` (one request per launch) and `show_release_notes` (the window). `update_loop::ui` fires the check on the first frame it sees (needs an `egui::Context` to repaint, so not `OctaApp::new`) guarded by `startup_update_started`, and `drain_startup_update_check` acts on the result once (`startup_update_seen`). `UpdateState::Available` carries `{version, notes}`. Available + notes on + `last_release_notes_version != version` -> `pending_release_notes` -> `src/app/dialogs/release_notes.rs` (notes rendered by the shared `view_modes::markdown::render_pulldown`; **Update now** hands off to `perform_update` + the existing update dialog; closing records `last_release_notes_version` so it is once per **release**, not per launch). Notes off -> a `status_message` toast instead, so the check is never a silent no-op. **`UpToDate` carries `{notes}` too** (same body, same request) and raises the SAME window for the version the user is *running* when `last_release_notes_version != CARGO_PKG_VERSION` - otherwise the feature could never fire for the release that introduced it, only for the one after it. That form drops the "Update now" button and the store note (`current` flag in `release_notes.rs`) and titles itself `release.whats_new`; with notes off it stays silent, since nothing about it is actionable. `Error` stays silent: a flaky network must not nag at every launch. The in-window "Do not show this again" checkbox writes `show_release_notes = false` - the same switch Settings shows.

**Store handling changed shape.** Previously `octa::platform::is_store_packaged()` gated two places: `check_for_updates` returned before setting any state, and `toolbar/mod.rs` hid the Help entry (which is what kept the dialog from being reached in that state). Knowing a release exists is useful on Store even though the *install* is impossible there, so the gate moved to where the install actually is: the check runs everywhere, the Help entry is always shown, and **both dialogs drop the Update button and show `release.store`** when packaged. Keeping the entry hidden while the startup check announced releases anyway would have left Store users told about a version with no way to re-check it. Status bar splits `Checking` from `Updating` (the startup check runs every launch; a spinner labelled "Updating..." for a read-only version query reads as a silent install).

i18n: appendable `[release]` section x32, which also holds the Settings section labels (same pattern as `[diagnostics]`, whose `section` key titles the Diagnostics settings block).

### Testing

Integration tests in `tests/`. Binary fixtures (parquet, avro, arrow, xlsx) auto-generated by `tests/common/mod.rs::ensure_fixtures()`; text fixtures checked in. DB tests seed a `tempfile::NamedTempFile` via `rusqlite`/`duckdb`. SQL tests build `DataTable` literals and call `octa::sql::run_query`. `tests/sql_workspace_tests.rs` exercises multi-table JOINs, ATTACH (DuckDB + SQLite, with/without the bundled extension), name collisions, and write-back round-trips in every mode.

Almost every test calls the library directly; the **binary** surfaces get their own process-spawning suites (`CARGO_BIN_EXE_octa`, `OCTA_CONFIG_DIR` pointed at a tempdir so no run touches the developer's real `settings.toml`). `tests/cli_smoke_tests.rs` walks every file-based action through the real binary asserting exit code + first stdout line, plus the `--validate-schema` exit-1-on-drift contract, `-f tsv|json|csv`, `--rows`, and `detect_action`'s missing-companion errors. `tests/mcp_smoke_tests.rs` speaks newline-delimited JSON-RPC to `octa --mcp` over stdio (initialize -> `tools/list` -> `tools/call`), pins that every advertised tool has a description + object `inputSchema` (a `schemars` regression would otherwise only show up at an agent's first call), and re-checks the `--mcp-read-only` tool removal on the wire. Adding a CLI action or MCP tool means adding a case to the matching smoke test. `tests/{dedupe,anonymize}_cli_tests.rs` cover those two actions in depth. `tests/db_live_tests.rs` is env-gated (`OCTA_TEST_{POSTGRES,MYSQL,MSSQL,REDSHIFT,CLICKHOUSE,EXASOL,SNOWFLAKE,DATABRICKS,BIGQUERY}_URL`) and **passes as a no-op** when a var is unset, so a green local run says nothing on its own. The `db-live` CI job supplies Postgres + MySQL and fails if either skipped (see CI Pipeline); the other seven engines still only run against a server you point them at by hand.

### i18n

Hand-rolled `src/i18n.rs` (spans the lib/bin split): `t(key)` + `set_language(code)`, TOML catalogs embedded from `locales/*.toml` (**32 files total**: English master + 31 langs: de/es/fr/it/nl/pt/pl/sv/da/no/fi/tr/id/vi/ro/hu/cs + el/ru/ja/ko/zh + uk/bg/sr/hr/sl/sk + lt/lv/et). Roboto-Medium/Bold cover Latin+Greek+Cyrillic; the bundled NotoSansCJK-subset covers CJK/kana/hangul (so el/ru/ja/ko/zh all render). `apply_fonts` also appends Roboto to the Monospace fallback so Greek/Cyrillic render in the SQL editor. `set_language` runs at `OctaApp::new` and on Settings apply (live). `every_language_covers_every_english_key` enforces key parity; `t()` falls back to English for any missing key. String migration is **incremental** — add a key to *every* locale then call `t()`. Arabic/Hebrew deferred (need RTL layout work).

Two traps that test does **not** catch, both hit in practice: it checks a key *exists*, not that its value differs from English, so a whole section can ship untranslated and CI stays green (the entire `[union_tree]` block did, in all 31 locales). And nothing enforces a locale's script: `sr.toml` is **Cyrillic**, but 168 strings were in Latin, many also ASCII-stripped (`Sacuvaj` for `Sačuvaj`) so they could not be transliterated mechanically — a bare `c` is ц, ч or ћ depending on the word. 33 values in `sr.toml` are legitimately Latin (format/product names, `SQL`, `MCP`, `SHA-256`, `Aa`, `X:`/`Y:`); everything else must be Cyrillic. To audit either problem, diff each locale's values against `en.toml` and eyeball the ones that match, ignoring product names like `JSON Lines` and `Azure AD` which are identical everywhere by design.
